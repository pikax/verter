## Selector and existing-check integration

[ci-impact.mjs](https://github.com/pikax/verter/blob/main/scripts/ci-impact.mjs) owns path filters, crate-root closures, escape hatches and gate composition. The [`detect-changes` job](https://github.com/pikax/verter/blob/main/.github/workflows/ci.yml#L99) takes only the changed-file list from `dorny/paths-filter@v4`; the lane decision stays in that script. Rust metadata supplies the dependency graph; non-crate filters own scripts, fixtures and generated inputs. Unowned paths fail audit and otherwise select all gates. Workspace manifests/lock, toolchain, cargo config, nextest config, proc macros and foundational identity changes select impact-bearing lanes; workflow/action/classifier changes select everything. The explicit inert lists own prose; an inert entry never overrides a consuming filter.

Subsystem outputs describe changed consumers. Artifact outputs describe required producers: `native_artifact = native OR playground OR transport`; `wasm_artifact = wasm OR playground OR transport`. Debug LSP is selected by VS Code OR editor-neutral OR DX; extension output by VS Code OR editor-neutral. Release LSP is selected by editors. `impact_full` is diagnostic, not a separate correctness suite; `release` distinguishes project/IDE rehearsal or landed-proof reuse. The workflow appendix maps each output consumer to its `if` and `needs`; outputs are not counted as extra tests.

[compile-contracts.mjs](https://github.com/pikax/verter/blob/main/scripts/compile-contracts.mjs) resolves each normal owner through `cargo run --locked -p verter_compile_contracts --no-default-features --features <owner>`; special bench/variant/soak packages and excluded session-observe use separate invocations. Nightly repeats the four group partition. This preserves feature-off privacy tests rather than unifying them into the default workspace test graph.

CI's Rust target caches use job-specific keys, restore on all refs and normally save only from main. The archive sccache namespace is `verter-rust-test-v1`; compile contracts share compile-unit sccache namespace `verter-compiler-contracts-v2` but separate outer cache by group, toolchain/config, locks/manifests and runtime revision with fallback prefixes. Main revision suffixes allow refreshing immutable entries after source-only changes. VS Code host cache saves on any missing ref and sccache's GitHub backend writes per-compile entries from all refs: both are explicit CI exceptions. Gradle restores broadly and saves main-only. Other workflows have their own policies: nightly/tsserver caches often disable target caching; DX/probe/release caches do not inherit CI's main-only rule. Read each exact declaration in the storage appendix.

[Landed reuse](https://github.com/pikax/verter/blob/main/scripts/release-proof.mjs) records PR number and tested merge tree in `ci-tested` notices. A main squash only disables lanes when that PR's successful CI proves exactly the landed tree; a different base, direct push, force push or missing proof runs normal selection. Tag publication additionally requires the release rehearsal and retained artifact families, then downloads from its proven run. Main-only cache refresh can therefore be skipped on a proven landing; it must not be mistaken for a missing validation or guaranteed fresh cache save. This task does not change proof or refresh behavior.
