## Foundational definitions (Stage 1 deliverables)
- **Internal handle name = `HotTypeRef`** (NOT `TypeHandle` — `component_meta_payload::TypeHandle` already exists as a public content-hash BFS DTO and stays output-only). `HotTypeRef` wraps a `SemanticNodeId` in the session arena; it is NEVER a cache KEY (R6: keys stay content-free slot/fact identity).
- **`CarrierResolverContext`** (RUNTIME / VALUE-SIDE — NEVER a query key): the demand-time context a `BareRef`/`ImportType` carrier needs to resolve, recovering what the current `lower.rs:642-769` `Ref` path uses — `name_resolution`, `DeclarationScopePayload`, `ScopeShadowing` (builtin shadowing), substitutions, augmentation scope, type-param/binder env, reduction-demand axes (mode). It is PASSED at resolution time as runtime state (or split into a small content-free slot key + value-side rehydration of the heavy fields). DO NOT hash `name_resolution`/`DeclarationScopePayload`/`ScopeShadowing`/substitutions/active-stacks/content-versions into `SemanticQueryKey` — the query key stays content-free (R6); version rides the cached VALUE's `NodeScopeId`/read-set.
- **New graph carriers** (in `SemanticNodeData`, scoped by `NodeScopeId`): the three arg-carrying carriers are OPAQUE tuple payloads with PRIVATE fields (`crates/verter_session/src/semantic_query/carrier.rs`) — `BareRef(carrier::BareRefCarrier)` (unresolved name; private `name`/`scope`/`type_args`, where `type_args` holds an applied `Foo<Arg>`'s structurally-lowered arguments and is empty for a bare `Foo`, so the query-free lowerer can carry `Foo<Arg>` without resolving it to an `InstantiationRef`), `ImportType(carrier::ImportTypeCarrier)` carrier (unresolved; private `specifier`/`qualifier`/`type_args`/`typeof_query`), a raw-fallback carrier preserving `Unknown{raw}` text, and a content-free **`SyntheticBindingId`** replacing `SyntheticCarrierKey.value_node: u64` as the synthetic-binding identity. The pre-existing `TypeOf(carrier::TypeOfCarrier)` carrier carries the same `type_args` slice (private `value_root`/`path`/`type_args`) for `typeof v.make<Arg>`; `BareRef`'s and `TypeOf`'s `type_args` raise back to `TypeExpr::Ref.type_arguments` / `TypeExpr::ValueRef.type_args` at the `materialize_type_expr` reverse boundary. Args descend ONLY via `SemanticNodeData::carrier_type_args`, rebuild ONLY via `map_carrier_type_args`, head fields read via `typeof_head`/`bare_ref_head`/`import_type_head`, and construction goes through `new_typeof`/`new_bare_ref`/`new_import_type` (these sanctioned accessors live in an `impl SemanticNodeData` block INSIDE the `semantic_query::carrier` module; the carriers' own `arg_nodes`/`with_type_args`/head getters and their fields are PRIVATE to that module — the raw-args surface is compiler-confined to `carrier.rs`, NOT `pub(super)`-to-the-parent) — making the anti-tail `node.type_args` direct bind unrepresentable by construction FOR THESE THREE current sealed carriers (their payload fields are private); the by-construction guarantee is per-carrier (a future carrier is FORCED to be CLASSIFIED at the wildcard-free fences but classification ≠ ENCAPSULATION, so a future named-struct carrier with a public `type_args` field could re-open the bind), and that enum-wide gap is CLOSED by the PRE-EXISTING (pre-Stage-6) enum-wide guard `no_named_type_args_field_outside_opaque_carrier` (introduced before the Stage-6 work; present, correct, and discriminating, and ORTHOGONAL to Stage-6 Option B — see the Stage-3 debt note below). `RecursiveRef` is DEMAND-TIME-minted (solver-produced, Stage 3), not Stage-2-emitted. Preserve `ConstructorType` fidelity (first-class carrier). Preserve tuple-element rest fidelity via `TupleElement.rest`; standalone `TypeExpr::Rest` remains non-publishable/scratch-only (no `SemanticNodeData::Rest`).
- **The reverse boundary (`SemanticNodeId -> TypeExpr`) is the SEALED `OutputProjector` capability + sealed carriers**, output/compat only (block 8-A3). The `OutputProjector::materialize_output_type_expr` (plain SHELL raise) / `materialize_reduced_output_type_expr` (REDUCE-then-raise) methods hand back the sealed `OutputTypeExpr` / `MaterializedOutputTypeExpr` carriers (private inner `TypeExpr`, capability-gated unwrap); the capability is constructible ONLY inside the true output subtrees, so a hot mint/unwrap is a COMPILE error. The Kind-B raise-then-decide interim is the named `legacy_semantic_type_expr_bridge` (retained until 8-A4). The test-only `materialize_type_expr(handle)` harness is `#[cfg(test)]`-gated.
- **Typed replacements for the ~99 SEMANTIC `Unknown{raw}` control-flow uses**: extend `QueryError` / a typed carrier; the `BUDGET_EXCEEDED_SENTINEL` fuse is named must-not-regress. Display-only `rawType` passthrough is SEPARATE (round-trips raw text through materialize). The Stage-1 "no Unknown-as-control-flow" guard applies ONLY to NEW carrier constructors; the GLOBAL fence is Stage 8/9 (raise.rs:263/739 legitimately use Unknown as control output today).
