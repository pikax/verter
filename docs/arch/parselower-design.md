# PARSELOWER — Staged Migration Design v3 (synthesized from the 3/3 design-review consensus)

GOAL: delete `TypeExpr` from the HOT parse/shallow/macro/lazy-body/prepared caches; lower demanded OXC bodies + macro type-args to interned handles in the `SemanticNodeData` arena; keep OXC AST worker-local (`!Send`); materialize `TypeExpr` ONLY at compat/JSON/test/diagnostic/output boundaries. PERFPARSE non-SFC fast-path is separate.

This v3 keeps the endorsed staged skeleton and bakes in the 7 review refinements (the v1→v2→v3 review chain endorsed the direction; v3 finalizes the stage-1/2/3 foundation). The breaking phase was re-sequenced per the architecture ruling at `/tmp/mom/STAGE5/fork/decider-OUT.txt` (the former monolithic "Stage 3C / Stage 5 atomic macro-producer" framing split into Stage 5A + Stage 6-prep + a reordered Stage 6). Stages 1-4 are NON-BREAKING (additive / dormant dual-read; LANDED); the remaining stages are each-gate-green: Stage 5A (macro hot-mirror structural producer), Stage 6 and Stages 7-9 are BREAKING, with the inserted Stage 6-prep (graph-native `whole_env()` consumer readiness) NON-BREAKING.

## Foundational definitions (Stage 1 deliverables)
- **Internal handle name = `HotTypeRef`** (NOT `TypeHandle` — `component_meta_payload::TypeHandle` already exists as a public content-hash BFS DTO and stays output-only). `HotTypeRef` wraps a `SemanticNodeId` in the session arena; it is NEVER a cache KEY (R6: keys stay content-free slot/fact identity).
- **`CarrierResolverContext`** (RUNTIME / VALUE-SIDE — NEVER a query key): the demand-time context a `BareRef`/`ImportType` carrier needs to resolve, recovering what the current `lower.rs:642-769` `Ref` path uses — `name_resolution`, `DeclarationScopePayload`, `ScopeShadowing` (builtin shadowing), substitutions, augmentation scope, type-param/binder env, reduction-demand axes (mode). It is PASSED at resolution time as runtime state (or split into a small content-free slot key + value-side rehydration of the heavy fields). DO NOT hash `name_resolution`/`DeclarationScopePayload`/`ScopeShadowing`/substitutions/active-stacks/content-versions into `SemanticQueryKey` — the query key stays content-free (R6); version rides the cached VALUE's `NodeScopeId`/read-set.
- **New graph carriers** (in `SemanticNodeData`, scoped by `NodeScopeId`): the three arg-carrying carriers are OPAQUE tuple payloads with PRIVATE fields (`crates/verter_session/src/semantic_query/carrier.rs`) — `BareRef(carrier::BareRefCarrier)` (unresolved name; private `name`/`scope`/`type_args`, where `type_args` holds an applied `Foo<Arg>`'s structurally-lowered arguments and is empty for a bare `Foo`, so the query-free lowerer can carry `Foo<Arg>` without resolving it to an `InstantiationRef`), `ImportType(carrier::ImportTypeCarrier)` carrier (unresolved; private `specifier`/`qualifier`/`type_args`/`typeof_query`), a raw-fallback carrier preserving `Unknown{raw}` text, and a content-free **`SyntheticBindingId`** replacing `SyntheticCarrierKey.value_node: u64` as the synthetic-binding identity. The pre-existing `TypeOf(carrier::TypeOfCarrier)` carrier carries the same `type_args` slice (private `value_root`/`path`/`type_args`) for `typeof v.make<Arg>`; `BareRef`'s and `TypeOf`'s `type_args` raise back to `TypeExpr::Ref.type_arguments` / `TypeExpr::ValueRef.type_args` at the `materialize_type_expr` reverse boundary. Args descend ONLY via `SemanticNodeData::carrier_type_args`, rebuild ONLY via `map_carrier_type_args`, head fields read via `typeof_head`/`bare_ref_head`/`import_type_head`, and construction goes through `new_typeof`/`new_bare_ref`/`new_import_type` (these sanctioned accessors live in an `impl SemanticNodeData` block INSIDE the `semantic_query::carrier` module; the carriers' own `arg_nodes`/`with_type_args`/head getters and their fields are PRIVATE to that module — the raw-args surface is compiler-confined to `carrier.rs`, NOT `pub(super)`-to-the-parent) — making the anti-tail `node.type_args` direct bind unrepresentable by construction FOR THESE THREE current sealed carriers (their payload fields are private); it is NOT yet closed enum-wide — a future carrier is FORCED to be CLASSIFIED at the wildcard-free fences but not ENCAPSULATED, so a future named-struct carrier with a public `type_args` field could re-open the bind (recorded as the enum-wide-guard debt in the Stage-3 debt note below). `RecursiveRef` is DEMAND-TIME-minted (solver-produced, Stage 3), not Stage-2-emitted. Preserve `ConstructorType` fidelity (first-class carrier). Preserve tuple-element rest fidelity via `TupleElement.rest`; standalone `TypeExpr::Rest` remains non-publishable/scratch-only (no `SemanticNodeData::Rest`).
- **`materialize_type_expr(handle) -> TypeExpr`** = the SINGLE reverse boundary, output/compat only.
- **Typed replacements for the ~99 SEMANTIC `Unknown{raw}` control-flow uses**: extend `QueryError` / a typed carrier; the `BUDGET_EXCEEDED_SENTINEL` fuse is named must-not-regress. Display-only `rawType` passthrough is SEPARATE (round-trips raw text through materialize). The Stage-1 "no Unknown-as-control-flow" guard applies ONLY to NEW carrier constructors; the GLOBAL fence is Stage 8/9 (raise.rs:263/739 legitimately use Unknown as control output today).
