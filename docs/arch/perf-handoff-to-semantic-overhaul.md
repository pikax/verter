## 4. Lessons from the wave-1 reviews (apply to the reworks)

The wave-1 C items were each 3/3-reviewed; two concurrency classes cost multiple rounds and must be carried into the re-expression:

- **item 12 ABA:** the compare-and-swap must prepare its transition from the **same single snapshot** it later compares against (no re-read between check and commit).
- **item 23 / keystone:** an off-mutex / detached provider task guarded by a single non-atomic version check is a **TOCTOU** — a stale push can still land after a newer one (clobber), and a "missing freshness ⇒ current" policy makes close an **ABA hole** (resurrects state into a closed doc). This is exactly why keystone item 2 is split (§3b): part (a) (ungated, off-mutex + freshness fields) does NOT close the ABA hole; the robust fix needs **per-path push serialization with a monotonic accepted-version** — keystone item 2 **part (b)**, which is GATED item 19's per-canonical-lock + host-concurrency-contract territory when applied to `did_change_mutex`. The armed-restart monitor (item 23's `restart_generation` rail) must **own its own cancellation** (forward spawn-failure into the monitor; never abort it from a generation read). The closed test matrices for these must include the **wake-before-poll** scheduler ordering, not just the already-committed case.
