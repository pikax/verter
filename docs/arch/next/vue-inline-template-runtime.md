# Vue inline-template runtime emission (production parity + perf)

**Status:** LANDED for client VDOM (2026-07-19, V1b). Vapor inline and inline
SSR remain deferred. Recorded alongside the Vue conformance-goldens program
(`crates/verter_vue_conformance`).

## What shipped

Verter's SFC→JS runtime pipeline now emits BOTH official topologies, driven by
`CodegenOptions.inline` (`resolve_inline()` = `inline.unwrap_or(is_production)`
— the official default: inline in production builds):

- **Non-inline (default in dev):** `_sfc_main` + separate `function render` +
  `_sfc_main.render = render` (assembled by
  `verter_session::compile::assemble_vue_main_module`).
- **Inline (default in production, or `inline: Some(true)`):** the official
  `compileScript({ inlineTemplate: true })` shape — the render is emitted
  INSIDE `setup()` as a returned `(_ctx,_cache) => { … }` closure that
  references setup bindings directly (no `$setup.` prefix, `.value` unwrap for
  refs), hoisted statics at module scope, no `__returned__` object.

The two shapes are **behaviorally equivalent** (same component semantics);
inline is official's production shape (fewer closures, no intermediate
bindings object, better minification).

Implementation notes:

- **Gate:** `inline_active` in `crates/verter_compiler/src/compile/mod.rs`
  requires client VDOM + `<script setup>` + template (Vapor inline and inline
  SSR fall back to non-inline; template-only / script-only SFCs are unaffected
  by the flag, matching official).
- **Merge:** the template render codegen runs on the SAME `CodeTransform` as
  the script in inline mode, and the emitted `return (_ctx,_cache) => { … }`
  chunk is `move_slice()`d into `setup()` at `inline_inject_pos`. The
  single-CT merge keeps full source-map fidelity (targeted test:
  `sourcemap_e2e_tests::inline_template_expression_maps_to_template_source`).
  Script + template helper imports merge into one deduplicated line.
- **Hoists:** inline hoisted statics emit as a module-scope prepend (official
  module-preamble placement), not inside the render chunk.
- **Assembly:** `VerterCompileResult.inline` / `RuntimeCompileOutput.inline`
  carry the RESOLVED topology (never sniffed from source text);
  `assemble_vue_main_module` skips `filter_setup_return` and the render attach
  on the inline branch. `CompileProfile.inline` rides the session cache
  identity.
- **Wrapper gate:** the V1a `isTS → _defineComponent` / JS → plain-object gate
  applies identically to inline output.

## Conformance context

The conformance corpus is dual-topology: the default non-inline cells
(`goldens/<ver>/vdom|vapor/…`) plus inline cells for VDOM script-setup cases
(`goldens/<ver>/vdom-inline/…`, generated by
`packages/vue-conformance-oracle/gen-vue-goldens.mjs` via a single
`compileScript({ inlineTemplate: true })` call per cell; each `.meta.json`
records `topology` + `inlineTemplate`). Cells key by case × backend ×
topology; the inline backlog is tracked in
`corpus/known-divergences.json` alongside the non-inline entries.

## Remaining deferred work

- **Vapor inline:** Vapor's always-`_ctx.` binding model conflicts with the
  inline closure-over-bindings shape; a separate follow-on.
- **Inline SSR:** official has `hasInlinedSsrRenderFn`; Verter's SSR is
  non-inline (see `docs/arch/ssr-noninline-shape-divergence.md`).
- **HMR:** Verter's HMR suffixes are topology-agnostic; official prod HMR
  wrapper nuances are out of scope.
