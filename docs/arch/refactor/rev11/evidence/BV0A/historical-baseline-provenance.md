# 36-cell code-byte baseline — historical provenance

**Baseline file (retired):** `crates/verter_session/src/compile/map_equality_tests/bf2_seed_matrix_code_baseline.json`
**Formerly consumed by:** `assembled_code_bytes_match_the_pinned_baseline`
(`crates/verter_session/src/compile/map_equality_tests/bf2_seed_matrix.rs`)

**Disposition:** the baseline file and its consuming test are deleted. The
zero-byte-drift claim this record proves is a completed migration proof, not
a standing correctness contract — every legitimate compiler correction after
the migration moves these bytes on purpose, so re-anchoring the pin to a new
baseline on every such change would convert a one-time migration check into a
permanent, self-derived byte-level ABI. This record is retained as the
durable proof the migration itself was byte-neutral; standing protection
against unintended drift is now `enabling_source_maps_perturbs_no_assembled_code_byte`
(map-on/map-off parity within the current tree) and
`every_seed_matrix_cell_composes_identically_to_the_independent_reference`
(agreement with the independently derived write grammar), both in the same
module.

## The finding this repairs

Final conformance review of the assembled BV0A package found the previously-committed baseline
circular: it was generated by hashing whatever the CURRENT candidate's own `assemble_vue_main_module`
emitted, regenerable in place via `VERTER_BF2_MATRIX_UPDATE_BASELINE=1` from "whichever tree is
currently running." Its own doc comment admitted it was "NOT by itself evidence about what the
assembler emitted before source-map composition existed." Neither the map-on/map-off self-comparison
nor cross-implementation agreement with the JS reference substitutes for this — neither establishes
historical byte equality against the pre-BV0A assembler, which is what AMD-008's "previously
successful results ... remain byte-identical" requirement actually asks for.

## The fix

The baseline is now produced by running the GENUINE pre-BV0A assembler — the actual bare-`String`
`assemble_vue_main_module(canonical_id, compiled, meta, profile) -> String`, before source-map
composition existed — against this matrix's exact current inputs, in a tree with no other BV0A
change applied.

### Historical anchor

`program/architecture-lock @ 6ecfcb7b59c371292f554c06be1d880861e435bc` — predates all BV0A
implementation work. Not itself the branch's fork point: `work/bv0a-integration`'s true merge-base
with this commit is the earlier `a30c1a2b0` (`git merge-base HEAD 6ecfcb7b59c371292f554c06be1d880861e435bc`
confirms this; `git merge-base --is-ancestor 6ecfcb7b59c371292f554c06be1d880861e435bc HEAD` is false —
the two commits are siblings off `a30c1a2b0`, not one an ancestor of the other). This does not weaken
the anchor: the four blob-identity checks below (manifest, fixture tree, `Cargo.lock`,
`rust-toolchain.toml`) are what actually establish that the anchor's fixture/build inputs match the
candidate's, independent of exact git ancestry, and those were confirmed by direct blob-hash
comparison, not inferred from ancestry.

### The old-driver trap, avoided

The stock BF2 driver at the historical anchor compiled every cell with a NARROWER fixed profile
(`is_production: true, ssr: false` only). Reusing its old dump files unchanged would have compared the
current 36-axis matrix against the wrong inputs. Instead, the current tree's exact `compile_fixture` /
`compile_cell` logic — fixture bytes, all 36 manifest axes (fixture × backend × sourceMap × isProd),
canonical IDs, the compiled `RuntimeCompileOutput`/`FileMeta`, and the full production/SSR/HMR/
source-map `CompileProfile` — was ported verbatim into the historical worktree. Only the final
assembler call was swapped for the old signature; every input the two runs feed the assembler is
identical.

### Runner

A throwaway `git worktree add --detach` at the anchor commit, patched with one ephemeral,
never-committed test module (`crates/verter_session/src/compile/historical_dump.rs`) that: reads the
same locked golden manifest, builds the same 36 `RealCompile` triples via the ported
`compile_fixture`/`compile_cell`, and calls the anchor's own `assemble_vue_main_module` directly — no
other production code at the anchor was touched. Run via
`cargo test -p verter_session --lib compile::historical_dump::dump_historical_baseline`, dumped to a
JSON file, and discarded (`git worktree remove`) after the digests were copied into the committed
baseline.

## Result

All 36 cells: the genuinely historical digest equals the candidate's current digest, cell for cell,
byte for byte. Zero divergence. `enabling_source_maps_perturbs_no_assembled_code_byte` and
`every_seed_matrix_cell_composes_identically_to_the_independent_reference` remain separate, independent
evidence; this record closes the third, previously-missing leg (historical byte-neutrality against the
actual pre-BV0A code, not a self-referential pin).

## No escape hatch

The baseline consumer test no longer has any regenerate-in-place code path. A future change to the
36-cell matrix's inputs (a new fixture, a new axis) requires re-deriving the pin from a newly named
historical anchor by the same procedure recorded here — not a environment-variable rewrite from
whichever tree happens to be running the test.
