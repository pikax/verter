# L1 — Long-churn bounded-memory soak

**Status:** LOCKED — contains binding acceptance criteria from the ratified timing directive; this charter is not separately authorized or dispatched. See the [landed timing ruling](../rulings/ARCHITECT-RULING-2026-08-23-TIMING-ARCHITECTURE.md).  
**Class:** Foundational.  
**Predecessors:** `E4`, `G4`, `H3`, `J4`, `K3`.

## Objective

Prove the final managed architecture remains causally correct, bounded, and reclaimable under long edit/lifecycle churn.

## Acceptance criteria

- No stale publication occurs after a newer revision.
- Work during rapid edits is bounded by active keys/documents, not edit count.
- Foreground demand bypasses background quiet windows.
- Cancelling one waiter does not cancel useful production for independent waiters.
- Cross-file edits converge exactly through dependency read sets/stamps.
- Correctness has no dependency on host scheduling, global idleness, yield count, polling luck, or elapsed thresholds.
- Existing memory criteria remain: clean equivalence, attributable pins, owner plateaus, no monotonic count growth, and no process restart is required for cleanup.

## Proof

Campaigns cover rapid repeated edits, unrelated parallel edits, create/delete/rename/move/open/close, project/config/provider restart, query storms, pressure, cancellation, and quiescence. Exact receipts, stamped publications, work counts, and structural bounds are correctness oracles; one generous real outer watchdog only detects a hang.
