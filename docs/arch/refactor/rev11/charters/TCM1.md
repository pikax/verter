Digest-bound authorization record still required before dispatch (see
`docs/arch/architecture-lock/ledger/authority-registry.toml`); ledger status stays LOCKED until TCM0 is

**Class:** foundational. **Predecessor:** TCM0 (its ratified mapping contract — `ADR-021`,
`evidence/TCM0/*`, this charter's own citations).
**Downstream:** TCM2, TCM3, TCM4 all build on TCM1's typed `SourceProjectionMap`.
**Authority:** `rulings/MAINTAINER-STEERING-TCM-CONTENT-MAPPERS.md` §8 (compact typed
`SourceProjectionMap`), §12 (offset/encoding safety); `evidence/TCM0/mapping-products-string-surface.md`;

This is the block the rest of the program is currently building on top of — no correct TypeScript
span-map adapter (TCM2) or oracle client (TCM3) can exist while semantic projection is string-encoded.

## 1. Intent contract

**Actor / problem.** Every IDE-facing consumer of Verter's semantic projection (the LSP's own position
mapper, the FFI/NAPI/WASM boundary, and — once TCM2/TCM3 land — the TypeScript content-mapper terminal
adapter) currently reads `source_projection_map()` as a JSON **string**, parsed back via
`PositionMapper::from_json`. This is not one boundary: `mapping-products-string-surface.md` records AT
LEAST 36 `Option<String>`/`String`/`Option<Arc<str>>`/`&str` fields carrying the same string-encoded
convention (32+ in `verter_compiler`, 4 in `verter_protocol`'s FFI wire types) — of which AT LEAST 35 are
in TCM1's migration scope; the 36th (`FfiBlockOverrideEntry.source_map`) is caller-supplied inbound data
with no `CodeTransform` producer relationship and is explicitly out of scope (exit criterion 1's
correction below) — corrected three times,
2026-08-23, and explicitly NOT claimed closed; see that file's own hedge. A typed compact
`SourceProjectionMap`, recorded
directly inside `CodeTransform` at the point bytes are produced, is the prerequisite every downstream TCM
block depends on.

**Required observable outcomes.**
- Every in-process consumer of semantic projection reads a typed `SourceProjectionMap` value, never a
  JSON string it must re-parse.
- The ordinary no-projection compiler route performs zero projection-product allocation, zero
  side-table construction, and zero UTF-16 conversion — provably, not merely "not obviously slower."
- `PlacementMap`, `SourceProjectionMap`, `RuntimeSourceMapData`, `EncodedSourceMap` remain four distinct
  types with four distinct owners; none is collapsed into a shared "universal map" type.
- `CodeTransform` remains the sole authority for generated bytes and mapping geometry; projection facts
  are recorded in the same write/edit/chunk operations that produce those bytes, never reconstructed
  afterward.

**Forbidden observable outcomes.**
- A string round-trip surviving anywhere behind the typed boundary (in-process OR at the FFI/NAPI/WASM
  wire — the FFI wire types are IN SCOPE, per the correction below, not a second string-encoded path left
  alive at the process boundary).
- A second writer or a second geometry authority that can disagree with `CodeTransform`.
- Any projection-product work (allocation, side table, UTF-16 conversion, feature-policy computation, V3
  serialization) occurring when no projection was requested.

**Authority / fallback order.** `CodeTransform` is the sole byte-and-geometry authority; there is no
fallback writer. TypeScript terminal projection policy and position encoding are terminal-state concerns
that never enter the compiler-artifact cache key (steering §10, §12) — TCM1 does not implement the
terminal adapter itself (that is TCM2), but must not preclude it by baking a terminal-specific concept
into the compiler-core type.

## 2. Owned scope

1. **Replace the string-encoded projection boundary with a typed `SourceProjectionMap`.** Single point of
   origin: `CodeTransform`'s own `generate_map`/`generate_map_json*`
   (`crates/verter_compiler/src/code_transform/source_map.rs`) — the typed intermediate
   (`oxc_sourcemap::SourceMap<'static>`) already exists transiently at exactly that point today and is
   discarded by every current caller. TCM1 replaces the discard, not each downstream consumer site
   individually (`tcm1-tcm4-charter-refinements.md`'s TCM1 note).
2. **Migrate the full string-encoded surface, not just the two originally-cited lines.** The amendment's
   original citation (`checker.rs:411` calling `PositionMapper::from_json`) is corrected:
   `checker.rs:411` base64-encodes the string into a `sourceMappingURL` comment; the actual
   `PositionMapper::from_json` call is test-only
   (`crates/verter_lsp/tests/cases/kebab_tag_mapping_full_columns.rs:65`). TCM1's real acceptance
   surface is the best-effort inventory in `mapping-products-string-surface.md`: AT LEAST 35 fields IN
   SCOPE for migration (32+ in `verter_compiler`, 3 in `verter_protocol`'s FFI wire types — a 36th
   `verter_protocol` field, `FfiBlockOverrideEntry.source_map`, is caller-supplied inbound data with no
   `CodeTransform` producer relationship and is out of scope), corrected THREE TIMES 2026-08-23 (the
   original "at least nine... plus four"/"thirteen" count was wrong; a first re-derivation attempt at 28
   was ALSO found wrong by a
   follow-up review — one struct misattributed, 8 fields missed by naming/visibility patterns a literal
   grep cannot reach). That file explicitly does NOT claim this count is exhaustive — closing it exactly
   needs a type-aware structural tool, not another manual pass; TCM1's own migration work is the actual
   completeness authority (exit criterion 1 below), not a pre-computed number.
   **Before migrating any field, classify it by which of the four distinct products it actually is**
   (`PlacementMap` / `SourceProjectionMap` / `RuntimeSourceMapData` / `EncodedSourceMap`) —
   `mapping-products-string-surface.md` inventories the (not-claimed-exhaustive) fields but does not perform this
   classification; TCM1 does it as a named, reviewable step (not an implicit judgment call folded into
   the migration), because "migrate to the typed shape" is ambiguous about WHICH of the four typed shapes
   a given field becomes, and collapsing that ambiguity silently is exactly the "UniversalProjectionMap"
   failure mode §5 forbids. Every field TCM1 finds — starting from, but not limited to, this file's
   inventory — migrates to its classified typed shape; the FFI/NAPI/WASM wire
   boundary is IN SCOPE, not deferred to a later block — leaving it string-encoded is a second production
   route in tension with the "one clean
   cutover" rule.
3. **Implement the final generic relation and projection-class model.** Relations: `ExactCopy`, `Atom`,
   `IdentityAlias` (TypeScript-terminal `Verbatim`/`Atom`/`Alias`) — no fourth `Anchor` relation.
   Projection classes: the five ratified in `projection-class-contract.md` (`AuthoredVerbatim`,
   `AuthoredTransformed`, `SynthesizedHelper`, `ExternalUnit`, `DefinitionAnchor`) — TCM1 lowers producer
   output into this class set; it does not invent a sixth.
4. **Zero-length `Atom` definition anchors.** `relation = Atom`, `original_len = 0`,
   `projection_class = DefinitionAnchor` is a first-class, testable shape, not an edge case handled by
   convention.
5. **Compact packed segment representation.** Packed contiguous records with sparse side tables. No
   `String`, `Arc`, `Vec`, `Box`, `HashMap`, repeated feature bitset, repeated provenance struct, or
   allocated semantic object on any per-segment record. Local ownership (`String`/`Box<str>`) during
   one-shot compilation; `Arc` only at a proven shared publication/cache boundary. Final segment shape,
   tag layout, size budget, and indexing strategy are selected BY TCM1's OWN measurement, recorded before
   the acceptance bar is checked — not chosen to fit a result observed afterward.
6. **Invariants**, enforced not merely documented: generated spans ordered and non-overlapping; original
   overlap permitted; one original range may project to many generated ranges; exact-copy ranges
   textually and length identical; edit-producing operations require length-preserving `ExactCopy`;
   zero-length original ranges require a named semantic class (item 4); all range additions checked
   before narrowing; **generated scaffolding with no source segment is an unmapped generated gap and is
   never assigned fake authored ownership** (steering §8) — a gap is a first-class absence of a segment,
   not a synthesized zero-width segment pointing at an arbitrary authored position.
7. **Offset and encoding safety.** Canonical UTF-8 internally unless TCM1's own evidence shows a better
   common coordinate system. Validate `usize`→`u32`, `u32` limits, UTF-8 boundaries, ordering,
   additions-before-narrowing, non-overlap, UTF-16 conversion, and TypeScript's signed `int32` wire range
   `0..=i32::MAX`. Overflow is a typed error returned before serialization — never wrapped, saturated,
   truncated, or reinterpreted.
8. **Lazy terminal views.** Provide lazy Verter/internal and TypeScript-terminal projection views over the
   same typed data — the terminal view is a read-time transform, not a second stored representation.
9. **Prepared-artifact cache-key composition**, per `cache-lifecycle-contracts.md` (corrected 2026-08-23):
   MAY include source/content identity, framework/language mode, codegen options, source-unit revisions,
   product profile, projection schema identity, compiler ABI. MUST NOT include feature-mask policy,
   `projection_policy_id`, UTF-8-vs-UTF-16, wire representation, or V3 encoding options — and MUST NOT be
   keyed by the `SourceProjectionMap` value itself (that is the computation's output, not its key).
10. **Test coverage**: property, differential, mutation, composition, and concurrency tests over the typed
    product; a test that FAILS if projection recording is invoked under a statically-dispatched
    no-projection mode.

## 3. Owned-scope boundary (what TCM1 does NOT own)

- No content-mapper process, no TypeScript JSON-RPC types in compiler core, no TypeScript semantic-API
  client — those are TCM2/TCM3.
- No TypeScript feature-mask constants in framework codegen — the terminal policy
  (`projection-class-contract.md`'s class × relation × region × owner × capability → mask derivation) is
  TCM2's terminal-adapter concern; TCM1 emits the class/relation, not a computed TypeScript mask.
- No activation, no routing change, no production dispatch change (TCM1's typed product is not wired to
  any consumer's active code path beyond the mechanical string→typed migration of item 2).
- No topology work, no distributed-lifecycle-owner implementation (`distributed-lifecycle-contract.md` —
  TCM1 has no lifecycle-owner code at all).
- No queue, flight, coalescer, or protocol-admission surface. The four-part timing taxonomy in
  `architecture.md` §1.6 adds no TCM1 concurrency criteria. The 300 ms background-diagnostics quiet
  window remains H3's `SyncCoordinator` policy; TCM1 must not widen it (already a material bound).

## 4. Numbered exit criteria

1. **No production caller reads `source_projection_map()` (or any other string-encoded field carrying
   the same convention) as a string it must parse — scoped to the DIRECT `CodeTransform` producer chain;
   the wire boundary and externally-supplied fields are separately owned (below).** This is proven by
   COMPILER-ENFORCED DELETION for the surface it actually covers, not by a name/text scanner (a landed
   name-keyed scanner over field names or doc comments is itself forbidden by this program's own
   structural-enforcement rule — see `CLAUDE.md`'s Stub Prevention / "Landed guards are structural"
   discipline; two prior drafts of this criterion each overclaimed — first proposing exactly such a
   scanner, then claiming the deletion argument alone proves the FULL transitive surface including the
   wire boundary and externally-supplied fields, which round-6 review disproved with concrete
   counter-examples below).

   **What compiler-enforced deletion actually proves.** `generate_map` (`code_transform/source_map.rs:103`)
   is ALREADY typed (`SourceMap<'static>`), not a string — only the convenience `generate_map_json*`
   variants return `String`. TCM1 DELETES those `generate_map_json*` variants (not adds a typed variant
   alongside them). Every DIRECT caller that previously received a `String` from one of them — one that
   assigns the return value straight into a field, with no intervening explicit serialization call — now
   fails to COMPILE, because there is no other way for such an assignment to type-check once the producer
   stops emitting strings. This is a genuine completeness proof for that direct chain, including a caller
   a name/grep search would miss (an oddly-named field, a downstream cache copy in a different crate) —
   the Rust type checker finds it, not a text search.

   **What it does NOT prove, named explicitly rather than silently assumed (round-6 finding):**
   - **Read-time JSON projections are a distinct, RETAINED capability (owned-scope item 8, criterion 2
     below)** — a caller that explicitly serializes the typed value back to a string (e.g. the existing
     `style_planner.rs:308` pattern) compiles cleanly and could keep filling an unmigrated `String` field
     forever. This is not closed by deletion; it is closed by SEALING the projection surface: TCM1's
     criterion 2 evidence must enumerate every such terminal projection method as a small, reviewed,
     closed set (not an open convention any call site may invoke ad hoc), so a NEW unreviewed projection
     call site is itself a reviewable diff, not an invisible escape hatch.
   - **The FFI/NAPI/WASM wire boundary is a SEPARATE proof, owned by exit criterion 3 below, not claimed
     to follow from this criterion's compiler-deletion argument.** `verter_protocol`'s own
     `CodeTransform`-produced DTO fields (`FfiVirtualFileResponse`/`FfiIdeResponse`/`FfiTscResponse` — NOT
     `FfiBlockOverrideEntry.source_map`, which is a distinct out-of-scope caller-supplied field named
     below) DO become typed — criterion 3 requires that, same as every in-process field. What stays
     string-shaped, by design and
     ONLY at the true terminal step, is the actual cross-language byte serialization the NAPI/WASM binding
     functions perform to hand the value to JS (the steering's own `EncodedSourceMap` "terminal external
     serialization" concept — a narrow, sealed, single conversion function per binding, not a raw string
     carried through the Rust-side DTO itself). Criterion 3 proves the DTO-typing half; that same criterion
     — not this one — also proves the binding-layer serialization is the sealed terminal step, not an
     early opt-out.
   - **Externally-supplied (inbound) map fields with NO `CodeTransform` producer relationship are OUT OF
     TCM1's SCOPE entirely**, named here so they are not silently assumed migrated: preprocessor-supplied
     override data (`verter_protocol::FfiBlockOverrideEntry`'s map field, fed from caller input at
     `verter_ffi/src/convert/input.rs`, not from `CodeTransform`'s output) and any comparable
     caller-supplied map fields TCM1's implementer discovers. These carry a different kind of data
     (caller override, not TCM-produced projection) and are a distinct, separately-owned concern — TCM1
     does not migrate them, and this charter does not claim compiler-deletion proves anything about them.

   Evidence: the deletion is real (old string-returning methods verifiably absent, `grep` confirms), the
   crate/workspace builds green with the typed product as `generate_map`'s sole return type for the direct
   chain, criterion 2's sealed-projection-set evidence, criterion 3's independent wire-boundary proof, an
   explicit named list of out-of-scope externally-supplied fields, `grep` for `PositionMapper::from_json`
   returning zero production (non-test) hits, and a named regression test asserting the typed accessor is
   the only production path for the in-scope surface. `mapping-products-string-surface.md`'s inventory
   (and any one-time `syn`-based or manual sweep TCM1's own implementer runs to plan the migration) is a
   legitimate MIGRATION AID for sequencing the work, but is explicitly NOT the landed completeness proof
   and is deleted or left unlanded once migration completes, per this program's rule that a migration-only
   scanner never lands.
2. **`generate_map` in `code_transform/source_map.rs` produces the typed `SourceProjectionMap` at the
   single point of origin, and it is the SOLE producer** — this criterion does not retain
   `generate_map_json*` alongside it (criterion 1's compiler-enforced deletion covers exactly those
   variants; a criterion that kept them producing `String` from `CodeTransform` would defeat that proof).
   String/JSON forms are obtained only as read-time projections of the typed value itself (owned-scope
   item 8's lazy terminal views — e.g. a `to_json()`/`EncodedSourceMap` conversion method on
   `SourceProjectionMap`, not a second `CodeTransform` producer method), never a separately-maintained
   parallel representation. Evidence: source read of `code_transform/source_map.rs` confirming
   `generate_map_json*` is absent and `generate_map` is the only producer, plus a test asserting the JSON
   projection and the typed value agree byte-for-byte for a fixed fixture set (a differential test per
   item 10 above).
3. **The `verter_protocol` DTO fields carry the typed shape**, not a raw `String`; the actual
   cross-language bytes reaching JS through NAPI/WASM bindings serialize that typed value through exactly
   ONE sealed terminal conversion function per binding — never an early opt-out where a binding function
   accepts or forwards a raw string instead of the typed value. Evidence: `verter_protocol`'s three
   in-scope `CodeTransform`-produced wire fields (`mapping-products-string-surface.md` —
   `FfiVirtualFileResponse`/`FfiIdeResponse`/`FfiTscResponse`; `FfiBlockOverrideEntry.source_map` is the
   distinct out-of-scope caller-supplied field named in criterion 1's correction, not migrated here)
   migrated to the typed shape at the DTO level; a
   named, reviewed list of every NAPI/WASM binding function that performs the terminal serialization
   (`verter_napi`/`verter_wasm` conversion sites); a wire-compat test proving the new DTO shape round-trips
   through NAPI and WASM bindings; a test proving no OTHER binding-layer call site independently
   stringifies the typed value (only the named sealed conversion functions do).
3a. **Each field found is classified by product before migration** (owned-scope item 2).
   Evidence: a table (in the implementation's own PR/commit description or a companion doc) naming, per
   field, which of `PlacementMap`/`SourceProjectionMap`/`RuntimeSourceMapData`/`EncodedSourceMap` it
   became — reviewed against `mapping-products-string-surface.md`'s inventory for completeness (all
   every field this pass and TCM1's own migration work found accounted for) and against §5 below for no
   field silently becoming a shared/universal type.
4. **Zero-allocation proof for the no-projection route.** Evidence: an allocation-counter test (consistent
   with the existing `allocator_canaries` pattern already used by `verter_session`/`verter_compiler`)
   asserting zero projection-product allocations, zero side-table construction, and zero UTF-16
   conversion when compiling under the no-projection static mode; a companion test that FAILS if
   projection recording is invoked under that mode at all (owned-scope item 10).
5. **Compactness proof.** Evidence: a `size_of`/structure-size test locking the per-segment record's byte
   size against the budget TCM1's own measurement selects (owned-scope item 5), plus a negative test
   confirming no `String`/`Arc`/`Vec`/`Box`/`HashMap`/bitset/provenance-struct field exists on the
   per-segment type (a `syn`/type-level check is acceptable per this program's structural-guard
   preference; a doc-comment claim alone is not sufficient evidence).
6. **Invariant tests** (owned-scope item 6) exist and are named: ordered/non-overlapping generated spans,
   permitted original overlap, one-to-many original→generated, exact-copy length identity, zero-length
   `Atom`/`DefinitionAnchor` pairing (owned-scope item 4), additions-checked-before-narrowing.
7. **Offset-safety tests** (owned-scope item 7): `usize`→`u32` overflow returns a typed error (not a
   panic, not silent truncation); a fixture exercising a value at `i32::MAX` and one one past it, proving
   the boundary is exact.
8. **No second geometry authority.** Evidence: an architecture-guard-style test or `syn`-based structural
   check (this program's stated preference over a name-keyed scanner) proving no code path outside
   `CodeTransform`'s own recording operations constructs a `SourceProjectionMap` segment.
9. **Cache-key composition test** (owned-scope item 9): a test asserting that varying feature-mask policy,
   `projection_policy_id`, UTF-8-vs-UTF-16, or wire representation does NOT change the prepared-artifact
   cache key (a golden-key test), and that varying content/framework-mode/codegen-options/compiler-ABI
   DOES.
10. **Property/differential/mutation/composition/concurrency test suite lands** (owned-scope item 10),
    named in the crate's test manifest, covering the four mapping products' interaction surface without
    independently reimplementing the same expected geometry twice in a way that could agree with the same
    bug (steering's own warning under "Required conformance coverage").

11. **`oxc_sourcemap` re-export disposition** (relocated by AMD-023, derived part `A4`): the re-export is
    dispositioned explicitly — retained with its consumer named, or removed. Criteria 1 and 3 already
    cover the producer chain and the wire boundary and are not replaced.

12. **Introduced-or-orphaned type recording** (relocated by AMD-023, derived part `B1`): every DTO or
    API type this block introduces or orphans whose sole producer/consumer pair lies inside the deleted
    set is recorded in the deletion manifest's item-17 list. Recording is the obligation; TCM4 verifies.

## 5. Forbidden

- Rescanning generated output to reconstruct semantic mappings.
- Decoding V3 source-map data to recover semantic composition.
- Identifying aliases from generated identifier spelling.
- Inferring semantic classes from equal generated/original lengths after the fact.
- Mapper-specific duplicate code generation (a second emission path that exists only to satisfy TCM2's
  eventual consumer shape).
- A second writer capable of disagreeing with `CodeTransform`.
- A `UniversalProjectionMap`/`OneMapForAllConsumers`/`MapperOwnedSourceMap` type collapsing the four
  distinct products.
- A content-mapper process, a TypeScript JSON-RPC type, or a TypeScript semantic-API client anywhere in
  compiler-core scope (owned-scope boundary, §3).
- A `V1 | V2` runtime enum, a versioned-vs-versionless internal representation, or any compatibility shim
  preserving the old string form alongside the new typed form once migration completes (no dual-path
  transition survives past this block's own landing).
- Choosing the segment size budget, tag layout, or acceptance thresholds AFTER observing a specific
  implementation's numbers rather than from TCM1's own locked measurement methodology.

## 6. Material bounds

Per `performance-baselines.md` (locked before implementation, not adjusted after):

- **Zero additional projection-product allocation when unrequested is a HARD REQUIREMENT**, proven by
  allocation counters (exit criterion 4), not a target range.
- **No compiler invocation is caused solely by terminal feature policy or position encoding** — both stay
  out of the prepared-artifact cache key (owned-scope item 9); a cache-key test is the proof, not a
  benchmark.
- **The debounced background-diagnostics push (`sync_coordinator.rs`'s 300ms silence window) is an
  existing, unchanged threshold.** TCM1 must not need to widen it; if TCM1's design requires widening it,
  that is a rescope trigger for TCM0/the program orchestrator, not a quiet adjustment landed inside TCM1.
- Package certification is settled (`rulings/MAINTAINER-RULING-TCM-PACKAGE-CERTIFICATION-SETTLED.md`);
  TCM1 has no package-dependent bound of its own (it never touches the TypeScript wire), so this is cited
  only for completeness — TCM1's material bounds are entirely compiler-core, not package-dependent.

## Abort / rescope

Per the steering's global abort conditions, applied to TCM1's scope: generated output must be rescanned
to reconstruct semantic mappings; semantic mappings are reconstructed from V3 JSON; mapping products are
collapsed into a universal map; `CodeTransform` ceases to be the byte/geometry authority; a required
zero-allocation proof cannot be produced without weakening the no-projection route's actual behavior.
