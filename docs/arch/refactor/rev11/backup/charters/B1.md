### Dependency-direction test (the block's own exit criterion)

The strategy is **locked** by [`evidence/A5/dependency-direction.md`](../evidence/A5/dependency-direction.md).
B1 implements it; B1 does not redesign it. Binding points:

- **One `cargo metadata --format-version 1 --all-features` forbidden-edge test over the whole
  workspace graph**, modelled on `crates/verter_macro_dto/tests/cases/dependency_closure_guard.rs`.
  **No new source-text scanner** — `CLAUDE.md`'s forward-only rule forbids a name-keyed file scanner
  as landed enforcement, and three of the four current mechanisms are exactly that grandfathered form.
- Edges: normal + build, transitive; dev edges excluded and the exclusion stated.
- Assertion form: **closure-based, not direct-edge-based**. A direct-edge test passes while a two-hop
  violation walks straight through it, and §4 of the A5 artifact shows that is not hypothetical.
- Exceptions: **equality-pinned, never subset-checked**, each with a recorded rationale and a named
  removal gate.
- Discrimination: the test must FAIL when a forbidden edge is added. Prove it by adding one to a
  scratch manifest and observing the failure, and prove the mutation was actually applied
  (`CLAUDE.md` → *Verification Must Prove Execution*: a plant that fails to apply reports a pass).
- Layer assignment: A5 §3 proposes the 7-layer matrix; **B1 ratifies it**. The two placements a
  reviewer will challenge (`verter_protocol` at layer 5, `verter_audit` at layer 1) carry their
  justification there.
- Supersession, in the same accepted candidate: delete `verter_audit_no_upward_deps` and both tests
  in `crates/verter_scheduler/tests/cases/no_session_dep.rs` — strictly implied by the walk.
  `audit_substrate_isolation` is **not** fully implied; its dependency half is, its *naming* half is
  not (it rejects any `verter_*` token in `crates/verter_audit/src`, which is what caught A4's
  `_verter_attribution_scope` local binding). B1 decides that residue explicitly — keep it as a
  separate named grandfathered guard, or drop it as coverage the program does not need. Silently
  deleting it and calling the closure test a superset loses real coverage and is not an available
  option.

## Required performance evidence

Cell `A6_META_COMPILE_40_COLD_RUST` in `performance-gates.toml`, `required = true`. Its metrics are
conjunctive: an absolute pass does not offset a relative failure, and a timing pass does not offset a
work-counter, zero-work, or output-oracle failure.

The cell is the **in-situ** measurement of the canonicalization/hash/key-construction overhead this
charter's template asked for: `workspace.normalize_canonical_id` runs 11,313 times and the hash sites
run on every artifact in the measured workload, so a new identity or key type that adds a
normalisation, a copy, or a hash per construction moves a gated counter. `session.semantic_cold_build`
is the discriminating metric for this block specifically: a new key type that is not equal where the
old one was turns warm hits into cold builds and that counter moves first.

B1 may **add** a dedicated micro cell only through a new lock record digest and the same independent
review class (ADR-016). It may not replace, reweight, subset, or reinterpret the locked cell, and it
may not choose a pass criterion after measurement.
