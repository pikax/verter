# BF3 — Conformance exhaustion and correction dispatch audit

**Status:** PROPOSED amendment / **RATIFIED (AMD-009 §7)**. The §7 DIRECTION is ratified by a
direct maintainer act; these exact bytes are recorded and independently reviewed, not
maintainer-inspected — see
[`amd009-ratification-packet.md`](../evidence/BF3/amd009-ratification-packet.md). This audit
charter is not accepted.
**Class:** Foundational (audit). **Predecessor:** BF2.

## Objective

Before B2/B3, exhaust the retained Svelte and non-Vue-runtime conformance inventory,
distinguish genuine product defects from harness or route artifacts, and dispatch
every genuine failure to its immediate root-cause correction owner. BF3 adds no
production retraction or defect-recognition mechanism.

## Owned scope and required procedure

1. Build and run the Svelte counterpart of the genuine shipped-path authoritative
   gate.
2. Exercise the exact six `svelte@5.56.8` client cells individually across every
   applicable parse, real-package link, structural, diagnostics, mapping, and runtime
   axis. Record the existing Svelte `ServerGenerate` refusal as a genuine
   contract-defined pre-compilation capability boundary and add nothing to it.
3. Prove each claimed axis discriminates with an independently planted defect and a
   green unplanted control.
4. Exhaust every retained reachable-success product and public/default route,
   including PublicApi/TSC/declaration, diagnostics/maps/CSS, batch, NAPI, WASM,
   host, and bundler spellings. Route aliases receive route-identity and publication
   proof rather than being counted as new semantic cases.
5. Classify each observed mismatch as a compiler/product defect, route/transport
   defect, or harness/oracle/normalizer/source-content/assembly artifact before
   assigning ownership.
6. Add a precise independently discriminating regression for every genuine defect.
7. Record the named immediate correction block and its acceptance/test ID; never
   translate a defect into a production guard, refusal, withhold path, retraction, or
   removal ID.

Vue VDOM/Vapor/SSR runtime rows already owned and corrected by BV0 stay outside this
audit's runtime scope. BF3 does not implement any compiler, session, route,
transport, CSS, or conformance correction.

## Required exits

The full retained inventory has actual results. `UNPROVEN` records an open proof gap
and cannot count as exhaustion. Every genuine failure has exact
request/route/profile/products/domain evidence, an independently discriminating
regression, root-cause classification, a named correction owner, and a correction
acceptance/test ID; no guard or removal ID exists.

`FC-ATOMIC-001` remains non-vacuous for successes and genuine contract-defined
refusals: one successful request publishes all and only its requested products and a
refusal publishes none. Route-parity tests, harness mutation controls, and
correction-owner regressions replace cold-path and guard tests. If no genuine failure
exists, only the per-failure clauses are vacuous; inventory, oracle execution, route,
atomicity, and mutation-control exits remain mandatory.

BF3 may close as an audit only after AMD-009 is ratified and BA0, BS0, BCSS0, and
BRT0 exist as mandatory predecessors of B2 and B3. B2 and B3 stay locked until BV0,
BF3, BA0, BS0, BCSS0, and BRT0 are all accepted.

## Abort/rescope

If a genuine defect requires repair beyond an existing immediate owner's charter,
stop and rescope it into the appropriate correction block. If an observation is a
harness or oracle defect, correct that infrastructure before disposition. Never
fall back to retraction, fixture-identity logic, generated-output string scanning,
or a second semantic authority.
