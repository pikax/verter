## Binding ruling fences (not deletion rows)

These are not transitional mechanisms and are not residue K3 may delete:

- The shared-overlay 20-second fallback bound in the `verter_lsp` shared attach/overlay/close 15/20/2-second family is an unsettled serving-policy duration. It needs its own architecture ruling and exact timer tests because it changes serving behaviour. No block, including H2 or K3, may reclassify, retarget, shorten, or delete it without that ruling. `LazyTransport`/`LazyOverlayCore` establishment singleflight is a deletion row above; the durations that bound it are this fence.
- Timing policy stays with its semantic domain and is not flattened into one duration table: `verter_lsp` owns quiet windows and scanner fairness; `verter_type_runtime` owns provider lifecycle, recovery, silence health, and request-hop margins; `verter_tsgo_api` owns relay/attach/process lifecycle bounds; `verter_workspace` owns external-tool execution policy; TCM2 owns mapper-process JSON-RPC queue and stdio-protocol liveness; TCM3 owns oracle-client snapshot/query lifetime.

## Preserved causal authorities

`RegistrationSignal`, `ProviderReadyReceipt`, `CarrierCommitStamp`, semantic provider `applied_generation`, barrier-synced `CarrierSlot` content, and exact dependency read-set stamps are preservation/migration inputs, not transitional mechanisms to delete. `SyncCoordinator` is already a lifecycle owner and is preserved/refined by H3; only duplicate ownership and its obsolete global-notification writer role are removed. The `DeclOverlayOwner` reachability graph is preserved overlay-membership domain state under H2 `ProviderHub`: reaching roots, per-root pass stamps, and `root_reconcile_epochs` high-water (stale-pass authority). Only the independent path-lock, `close_pending`, and generation-ABA mutex are the deletion row above. H2 must keep the stale-pass invariant: an older closure pass must not re-add or re-open an edge a newer pass closed. `WorkspaceScannerConfig::done_tx` may remain only if H3 converts it to scanner-owner-local, non-authoritative owned causal progress; it cannot participate in provider/LSP readiness. A migrated hover-provenance capability may survive only on the exact G2/F1/F2 contract in the table; the current nonconforming producer/cache path may not.

## Same-key coalescer inventory

K3 close is NAMED-ROW closed. Every row below must be dispositioned — absent, or converged with its recorded final owner — and that is the whole bar. An unnamed same-key coalescer is NOT a close failure and no search is required to prove absence: the maintainer ruled that a clean cutover of the named inventory is enough and that we do not keep testing for unnamed cells (see [`MAINTAINER-RULING-COALESCER-CLOSURE-IS-NAMED-DISPOSITION`](../rulings/MAINTAINER-RULING-COALESCER-CLOSURE-IS-NAMED-DISPOSITION.md)). Exclusions, and the three ways a file hides its test gating. Rust drops `**/tests/**`, `**/*_tests.rs`, and `**/tests.rs`; TypeScript drops `node_modules`, `dist`, `*.test.ts`, and `*.spec.ts`. Beyond the globs, a hit inside an item or module gated `#[cfg(test)]` / `#[cfg(any(test, …))]` / `#[cfg(feature = "test-support")]` is excluded — but a hit's own file tells you nothing about its gating, so check the parent. Module gating lives on the `mod` declaration in the PARENT file. A `#[path = "…"]` include carries the parent's gate into a file whose name and contents both look like production: `test_harness_fixture_dependencies.rs` is pulled in exactly that way from a `#[cfg(test)] mod test_harness`. ### Ruling outcome, and the durable target

The architecture consult and the maintainer ruling that settled this are summarised here so the reasoning survives with the mechanism it retired. The ruling of record is [`MAINTAINER-RULING-COALESCER-CLOSURE-IS-NAMED-DISPOSITION`](../rulings/MAINTAINER-RULING-COALESCER-CLOSURE-IS-NAMED-DISPOSITION.md), registered in `authority-registry.toml`; it carries the full reasoning and is the authority the closure criterion below rests on.

**The fourth adversarial pass (this round) found no new cell.** It probed three shapes B1-B15 cannot express: `entry(...).or_insert(...)` / `.or_default()` WITHOUT the `_with(|| {` closure B15 requires; `get_or_insert_with` on an `Option` or an async cell; and a bare `Vec`/`VecDeque` of `oneshot::Sender` held as a struct field, which B12 cannot see because B12 needs a MAP. The first surfaced only already-rowed cells (`dag.rs:1429`, `:1446`, `:2422` reached through a fourth idiom, `or_default().push`), keyed counters of the already-probed epoch-fold class, and plain data grouping; the second surfaced only non-shared local `Option` building in the parser and the Svelte adapter; the third returned zero. A pass finding nothing is NOT evidence the population is closed — the previous three passes each found something, and the only honest conclusion is that this pass looked at three more spellings.

That the SAME already-rowed cells surface under a fourth idiom is the more useful datum: the number of lexical forms for one behaviour is not bounded, so a command set chasing them cannot terminate.

**A rail this charter proposed, and why it does not work.** The proposal was to deny the raw primitives at the crate boundary (so a hand-rolled cell could not name `DashMap`/`parking_lot::Mutex` and would fail with `E0603`) plus one sealed constructor for keyed production. The architecture consult assessed it INSUFFICIENT, and the reasons are worth keeping so it is not proposed again: Cargo dependencies are crate-wide, so denial cannot be scoped to the surfaces that need it; `std`'s `HashMap`, `OnceLock`, and the atomics cannot be denied at all; TypeScript's `Map`, `Promise`, and timers are ambient in the language; and a sealed trait constrains who may IMPLEMENT it, not who may compose the same behaviour directly out of primitives.

**The durable target, owned by G2/H2.** The consult's assessment is that the real confinement rail is an unforgeable publication/commit capability governing authoritative EFFECTS — coalescing becomes structurally impossible to do off-rail because only a capability holder can publish a result, rather than because the syntax for building a cell was forbidden. That is implementation work on G2's and H2's own surfaces, not a contracts block's to carry. It is recorded here so the option is not lost; K3 neither implements it nor depends on it, and K3's closure does not wait for it.

- **K3 closes when every NAMED baseline row is dispositioned** — absent, or converged with its recorded final owner. That is the whole condition. **No claim is made, and none is required, that no unnamed behavioural coalescer exists anywhere in the tree.** Re-running the enumeration method is NOT an acceptance condition: the maintainer ruled that a clean cutover of the named inventory is enough and that we do not keep testing for unnamed coalescers. An independent adversarial search may still add a row at any time and such rows are classified here; a clean search is not acceptance evidence and must never be recorded as one.

The threshold is the performance bound already locked for the surface the counter sits on; where that surface has NO locked bound, K3 records one BEFORE taking the measurement, so a number cannot be chosen to fit a result it has already seen. - The remaining stable facade exposes no sideways mutable access or migration carrier.
