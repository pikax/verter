## 2.2 CSS-family capability matrix (J1-A9 closure)

**Ratified by J1-A9.** The single aggregate `CSS` seed row is replaced by an exact, closed
product×dialect×operation universe: 2 products (Vue, Svelte) × 5 dialects (`Css`/`Scss`/`Sass`/`Less`/
`Stylus`) × 4 operations (parse/index/transform/format) = 40 rows, no missing or duplicate triple.
Every row carries the original §1 row schema (`Route/backend` through `Compatibility promise`,
`Status`) UNTOUCHED in meaning — `Maturity`, `Default`, and `Compatibility promise` stay their seed
`VERIFY` value on every row; no targeted diff/sign-off is required because none of those three cells
is changed away from `VERIFY` here — plus the two columns A9 adds (`Dialect`, `Disposition`) and one
further column A9's own gate text requires (`Evidence`, since gate criterion (b) demands "a non-empty
evidence citation" per row, which the original schema has no column for).

Disposition rule, uniform across both products: `parse` = `Native` (all 5 dialects — one shared
`StyleSyntaxIr` parser); `index` = `Native` (all 5 dialects — the semantic-fact projector reads
`StyleSyntaxIr` only); `transform` = `Native` for the `Css` dialect on both products (Vue via
`style_planner`, Svelte via `svelte/runtime/css` over `parse_style_ir`; the independent Svelte
`parse.rs` grammar is absent), `External` for `Scss`/`Sass`/`Less`/`Stylus` (non-CSS dialects
transform only after the sealed external preprocessor round-trip, A13/A14); `format` = `Unsupported`
for every dialect on both products — no dedicated CSS formatter exists in the workspace and this
charter adds none (J1 §2, "`format` operation"). Css transform is Native/Ratified for Vue AND Svelte;
H046 DEFER is not authority and must not reopen either row.

section's table directly out of the committed file, asserts the 40-triple universe is exact (no

matches the rule above exactly with a non-empty `Evidence` cell, asserts every `Native` row's `Status`
is `Ratified` (Css transform included), and asserts the `VERIFY`-`Status` set equals exactly the
non-`Native` subset.

# 3. Rules

- A missing/`VERIFY` row means the capability is not approved for architecture claims or default changes.
- Maturity is operation-specific; framework citizenship does not imply equal maturity.
- Changing a default or compatibility promise requires product/conformance review.
- Experimental behavior cannot be silently used as a stable oracle for another surface.
- Every enabled row links exact tests and benchmark cells.
- Unsupported and partial behavior is part of the public contract, not an implementation accident.
