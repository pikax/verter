## Ruling

### A. Concurrency / ownership

Range-level disjointness can satisfy AMD-005. The clause requires disjoint “code,” not disjoint files; the stacking contract expressly anticipates declaring shared files. [AMD-005 §4](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/amendments/AMD-005-framework-compiler-conformance-rescope.md:98), [stacked-prs.md](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/contracts/stacked-prs.md:60)

But line ranges alone are not proof. Require all of this:

- Exact common base SHA/tree and exhaustive writable-path inventory: source, fixtures, tests, manifests, generated outputs, manifests, and lockfiles.
- Symbol/AST-level ownership inside shared files; no shared declaration, `use` list, macro invocation, trait signature, constructor, or formatting-sensitive aggregate.
- Both patches apply in both orders without conflict or manual resolution and produce the same final tree and generated bytes.
- Each block passes independently from the common base; the combined tree passes in both orders.
- No block consumes an API changed by the other.
- One writer lease for every lockfile, schema, manifest, generated artifact, and dependency-firewall file. [stacked-prs.md](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/contracts/stacked-prs.md:79), [landing-equivalence rule](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/contracts/stacked-prs.md:140)

The present proof fails that bar. Your premise omits a third shared file: `carrier_compiler.rs`. B2 changes `ParseOptions` and `CarrierCompiler::parse`; B3 changes `RuntimeCompileOptions`, compiler refusals, and `compile_bundle`. [ParseOptions](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/carrier_compiler.rs:40), [`parse`](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/carrier_compiler.rs:701), [RuntimeCompileOptions](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/carrier_compiler.rs:340), [`compile_bundle`](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/carrier_compiler.rs:754)

Directive: serialize now—B2 first, then rebase/revalidate B3 on B2’s accepted tree. Do not create a semantic DAG edge; this is execution serialization between siblings. B4 remains gated on both. [AMD-005 §4](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/amendments/AMD-005-framework-compiler-conformance-rescope.md:101), [program DAG](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/program-dag.toml:105)

### B. B2 scope

1. Jointly owned official cases

A row has one aggregate disposition; successful acceptance includes all applicable products, diagnostics, mappings, and runtime observations. B2 cannot declare a whole row satisfied while its codegen half remains unresolved. [conformance-goldens.md](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/contracts/conformance-goldens.md:7), [per-case acceptance](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/contracts/conformance-goldens.md:42)

Directive:

- B2 closes the parse/recovery/syntax-diagnostic/rejection facet for every joint row and attaches facet evidence.
- BV1 or BS1 closes lowering, codegen, runtime, mapping, and product facets.
- The aggregate row leaves `blocked` only after every applicable facet closes.
- Amend B2 E1 to require “no blocked B2 parse facet,” not “no blocked aggregate row.”

This amendment is maintainer-only. The current charter’s aggregate exit conflicts with B2’s explicit exclusion of codegen and with the DAG placing BV1/BS1 after B4. [B2 exclusions and exit](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/charters/B2.md:10), [BV1/BS1 ordering](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/program-dag.toml:105), [deviation authority](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/governance.md:285)

2. `CarrierCompiler::parse`

Make it fallible:

```rust
fn parse(...) -> Result<Arc<FrameworkParseArtifact>, SyntaxReject>;
```

Recoverable malformed syntax remains `Ok` with mandatory mapped diagnostics. Unsupported syntax modes, unrecoverable construction failures, or contract rejection return the closed error before artifact publication. Downstream rejection is too late because the current seam already returns a publishable artifact unconditionally. [B2 ownership](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/charters/B2.md:5), [current infallible seam](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/carrier_compiler.rs:701)

3. `SyntaxCompatibilityId`

Do not introduce it. Consume B1’s existing `(CompatibilityDomainId, CompatibilityEpoch)` pair and encode both into the `ParseKey` descriptor. B1 deliberately landed separate nominal types. [identity types](<MACHINE_ROOT>/verter/crates/verter_identity/src/identity.rs:139), [architecture identity vocabulary](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/architecture.md:291)

4. Parse-option normalization

B3 owns normalization from public/host inputs into final typed Vue/Svelte option values, including defaults, derivation, and refusal. B2 owns canonical equivalence, encoding those already-normalized parse values into `SyntaxProfileId`, and consuming them in the frontend.

B2 must not re-default or reinterpret options; B3 must not compute a second syntax-profile identity. [B3 charter](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/charters/B3.md:5), [single option mapping](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/charters/B3.md:11), [ParseKey contract](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/architecture.md:477)

6. Diagnostic ordering

`encounter_order` is the stronger semantic order for Svelte’s strict-rejection defect rails. It records when a defect becomes provable; an unclosed tag is proved at EOF even though its reporting span points backward. [tokenizer rationale](<MACHINE_ROOT>/verter/crates/verter_compiler/src/svelte/parser/tokenizer.rs:192), [strict-error contract](<MACHINE_ROOT>/verter/crates/verter_compiler/src/svelte/parser/template_ast.rs:1309)

Directive:

- Use `encounter_order` as the primary key for strict parse/rejection arbitration.
- Add the normative span/severity/code/typed-argument key as a total deterministic tie-breaker.
- Ordinary parse diagnostics without this semantic ordinal use the standard span key.
- Never use worker completion, insertion order, or message text. [ordering contract](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/contracts/deterministic-ordering.md:20), [diagnostic fallback](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/contracts/deterministic-ordering.md:30)

7. Mandatory spans and Svelte host routing

B2 owns both.

- Make the surfaced parse-diagnostic span mandatory. Vue’s parser constructors currently manufacture `None` by default; that violates B2’s mapped-diagnostic exit. Do not substitute `0..0`; an unmappable diagnostic must fail closed. [Vue diagnostic](<MACHINE_ROOT>/verter/crates/verter_parser/src/diagnostics.rs:254), [constructors](<MACHINE_ROOT>/verter/crates/verter_parser/src/diagnostics.rs:268), [B2 exit](<MACHINE_ROOT>/verter/docs/arch/refactor/rev11/charters/B2.md:15)
- Route Svelte parse diagnostics into the canonical host parse-diagnostic channel. The Svelte artifact currently publishes an empty vector, and the host success path never imports `ParsedSvelte::diagnostics`. [empty artifact channel](<MACHINE_ROOT>/verter/crates/verter_compiler/src/svelte/carrier.rs:112), [host success path](<MACHINE_ROOT>/verter/crates/verter_session/src/parse.rs:830)

B4 later composes mappings across logical source units; it does not own making B2’s carrier-local diagnostics exist.

### C. Carrier-geometry guard

B2 must land structural enforcement. The existing machinery is insufficient.

`RegisteredProjectorSeal` only controls who invokes the projector, while `new_registered` validates that an already-built inventory matches registered source witnesses. Neither prevents downstream source scanning. [seal](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/registered_projector_seal.rs:1), [witness validation](<MACHINE_ROOT>/verter/crates/verter_language/src/parse_artifact/carrier_inventory.rs:171)

Worse, `FrameworkParseArtifact::new` is public and accepts arbitrary `FrameworkParseCommon`; both adapters currently construct it with an empty default inventory. The projector’s panic is runtime exhaustiveness, not structural geometry confinement. [public constructor](<MACHINE_ROOT>/verter/crates/verter_language/src/parse_artifact.rs:321), [Vue empty inventory](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/vue_bridge.rs:136), [Svelte empty inventory](<MACHINE_ROOT>/verter/crates/verter_compiler/src/svelte/carrier.rs:112), [runtime panic](<MACHINE_ROOT>/verter/crates/verter_compiler/src/framework_common/registered_carrier_projection.rs:168)

Directive:

- Introduce private type-state separating an unregistered parser result from a registered, geometry-bearing artifact.
- Only the sealed registered projector may convert the former into the latter.
- Make the downstream artifact constructor require an unforgeable validated-inventory witness; eliminate public construction with `CarrierBlockInventory::default()`.
- Geometry-sensitive downstream APIs accept artifact-bound block refs/slices, not raw source from which structure can be rediscovered.
- Add compile-fail negative tests proving unauthorized construction/projector access is impossible.
- Do not add a name-keyed source scanner. The binding rule expressly requires structural review/enforcement and forbids scanner-detection jobs. [CLAUDE.md](<MACHINE_ROOT>/verter/CLAUDE.md:299)

Only the joint-case exit amendment requires maintainer ratification. The remaining rulings follow existing authority without changing the ratified product boundary.
