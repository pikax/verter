### 4.1 Whole-program / cfg-gated-plumbing zero-cost proof (conformance-trace)

**What landed:** the feature-gated conformance-trace is zero-cost when off by `#[cfg]` gating plus monomorphization (the default entity-decode path takes a no-op observer closure that compiles away), backed by a structural guard (closed `AttrIr`/match-sink field/variant inventory, prod-IR trace-mention ban, decoder-mention ban, manifest feature-off-by-construction checks in `svelte_conformance_trace_zero_cost_guard.rs`) and an isolated feature-off CI gate (`cargo build`/`cargo test -p verter_compiler --lib` with no conformance crate in the graph, immune to workspace feature unification).

**The better alternative:** either (i) cfg-gate the decode-observer PLUMBING entirely — no observer parameter exists feature-off, making the zero-cost claim true by CONSTRUCTION rather than by optimizer guarantee; or (ii) an executable whole-program feature-off-vs-on output/artifact byte-identity rail.

**Why better:** removes the residual reliance on monomorphized-closure elimination and turns "zero cost" from a guarded property into a structural impossibility (or an executable whole-program proof).

**Why non-blocking:** the feature IS zero-cost as landed — `#[cfg]` gating + monomorphization, verified across four review rounds (opus C LAND); the `MatchCertainty` tri-state is an always-on behavior-preserving refactor whose production projection (`Yes | Maybe → true`) is byte-identical (the 1980 default svelte tests unchanged). The demand is a preferable design, not a correctness or fail-open defect.

**What landed:** the Spread-erases-Target degeneracy is documented and guarded (`no_unexpected_byte_identical_fixtures` in `tests/reject_unclassified.rs`): `subject_attr()` renders every `Spread` template value as `{...rest}` regardless of the declared `Target`, so five Spread×Target cell-pairs legitimately share one fixture body each (518 cases, 513 distinct fixture bodies). **Why non-blocking:** a coverage-PRECISION over-count, not a gap or a fail-open — Verter's spread behavior IS tested (once); nothing is untested or mis-scoped; the two cells of each pair are semantically identical.

## 5. Future: make `framework_codegen_uses_code_transform` AST-aware (I6-aligned guard quality)

**What landed (T1b compliance fix):** the `framework_codegen_uses_code_transform` guard scans `crates/verter_compiler/src/svelte/**` for the literal `.replace(` token. It FALSE-POSITIVED on `conformance_trace.rs`'s `active.borrow_mut().replace(ConformanceTrace::default())` — an `Option::replace` (RefCell/Option state swap), NOT a `String::replace` post-hoc munge of built codegen output. The compliance fix restructured that one call to a `take()` + reassign (`let mut slot = active.borrow_mut(); let prev = slot.take(); *slot = Some(ConformanceTrace::default()); prev`) — semantically identical (returns the prior trace, installs a fresh default). A `std::mem::replace(&mut *slot, Some(..))` form also dodges the guard token, but trips clippy `mem_replace_option_with_some` (which suggests `Option::replace` — the very token the guard forbids), so `take()` + reassign is the one form that satisfies BOTH the guard and clippy.

**The better alternative:** make the detector AST-aware (or at least receiver-type-aware) so it distinguishes `String::replace` / built-output munging from `Option::replace` / `.borrow_mut().replace(` state swaps, instead of a bare substring scan for `.replace(`. Then a future legitimate `Option::replace` needs no defensive rewrite, and the guard still catches real string-munging of compiled output.

**Why better:** removes a text-scan false-positive class; the guard becomes precise about the behavior it actually forbids (post-hoc rewriting of built codegen strings), not any `.replace(` token.

**Why non-blocking / not this train:** the guard's INTENT (no post-hoc string-munge of built codegen output) is correctly enforced today; the false-positive is dodged by an equivalent restructure, so nothing is mis-scoped or unenforced. Upgrading the detector to AST-awareness is a guard-tooling refinement, out of scope for the additive CSS-manifest train.

Refs: `crates/verter_session/tests/g_misc0/framework_carrier_compiler_guards.rs` (`framework_codegen_uses_code_transform`, `post_hoc_munging_detectors`); `crates/verter_compiler/src/svelte/runtime/conformance_trace.rs` (`capture`).
