# T2 — legacy value-wrap correctness closure: design tradeoffs + superior-but-unchosen approaches

Non-blocking capture for post-plan review (per the better-implementation directive). Records the architecture tradeoffs behind the native Svelte legacy value-wrap correctness closure and the superior-but-heavier approaches deliberately NOT taken, so a future pass can pick them up. Nothing here blocks the train.

Oracle = official `svelte@5.56.3`. The legacy (`maybe_runes=false`) `build_expression` wrap (`node_modules/svelte/.../shared/utils.js`) wraps authored reactive values `($.deep_read_state(dep), …, $.untrack(() => value))` and memoizes; runes/maybe-runes emit raw.

## Decision taken — UNIFIED wrap-injection (adopted)

Chosen over per-surface ad-hoc fixes (codex gpt-5.6-sol, session `019f5511-f4e0-7f60-a41b-7bd3efbaf9ab`, CODEX_EXIT=0). The durable boundary (over the INVENTORIED authored-value surfaces; the raw-string authored-emission residual is D-61-deferred): **every authored template expression at an inventoried surface is PREPARED exactly once during fallible planning, through a surface-keyed policy; emitters choose topology (inline/memo/derived/thunk) but NEVER decide whether legacy wrapping applies.** Authored provenance is enforced by ROUTING, not by the input type: every inventoried call site passes an analyzed expression id or the canonical `{@render}` dynamic-callee slice (which carries `&str` source/rewritten slices plus its canonical-analysis facts), and the routing guard's call-site inventory pins that topology.

- Single entry `prepare_template_value(authored: impl Into<AuthoredValueInput<'_>>, surface: AuthoredValueSurface) -> Result<PreparedTemplateValue, …>` — `AuthoredValueInput` is the two-variant input vocabulary: `Expr(AuthoredExpr)` (a whole analyzed template expression by `ExprId`) or `RenderCalleeSlice { source, scope, facts, rewritten }` (the `{@render}` dynamic-callee `&str` slice with its canonical-analysis `RenderDynamicCalleeFacts`). Mode authoritative on `self.ir.component`, not caller-supplied; surface is semantic, not a `Wrap/Raw` boolean.
- Centralized `const fn policy(surface) -> ValuePolicy { legacy: {BuildExpression|Raw}, topology }` — one exhaustive wildcard-free match; the wrap decision lives in exactly ONE place.
- Synthesized-value WRAP-carrying is impossible by type (`PlannedTemplateValue::{Authored(PreparedTemplateValue)|Synthesized(SynthesizedTemplateValue)}` — the sealed carrier has no wrap-typed state and a raw-only accessor API). The authored-masquerade half is NOT closed by the type split alone: it is closed by the sealed carrier's CLOSED TYPED CONSTRUCTOR vocabulary (`clsx(&PreparedTemplateValue)` + the class/style directive-object constructors, each consuming PREPARED/typed contributors and deriving the composite text itself — no free-form `new(String, …)`), pinned by the routing guard's constructor + consumer inventory.
- A structural routing guard inventories the current authored-value planners, rewrite call sites, and surface bindings and fails closed when that known topology changes. It does not prove arbitrary future planners cannot route authored text through an existing or new raw-string plan carrier; the terminal type/capability cutover is D-61. Two named residuals stay under the D-61 cutover and are deliberately NOT patched here (patching them chases scanner completeness the ratified DEFER-NEW ruling declines): (1) an in-owner PERMITTED method body of the sealed carrier constructing arbitrary `text` at runtime — no static structural check over the owner module can decide a method body's runtime output, so the sealed-carrier guard is a fail-closed structural tripwire, not a completeness proof; (2) a TRANSPARENT type alias (`type Surface = AuthoredValueSurface`) that renames the surface away from the guard's `AuthoredValueSurface` substring scan, dropping a parameter from surface-binding discovery. The associated-item permit-list closes the bounded static `const`/`type`/`macro` sub-vector (an associated const/type/macro in the sealed impl is now exhaustively rejected, fail-closed); the two residuals above remain the backend-wide D-61 typed-carrier cutover.

### Why unified over per-surface
The bug class proved the point: the shared wrapper `legacy_wrap_value` already existed after the first two fixes, yet direct low-level rewriting still lived in block/spread/title/attachment/class/style planners — i.e. the MECHANISM was shared but the DECISION was distributed. Per-surface fixes centralize the mechanism while leaving the decision scattered, so the next authored-value surface silently re-opens the class. Unified preparation binds the decision to a single policy table + a type boundary.

### The guarded counter-argument
A unified abstraction risks becoming a "god value" with loosely-related optional fields + conditional emitter logic. Avoided by centralizing expression PREPARATION + POLICY only, while RETAINING specialized `block` / `attribute-effect` / `title` / `lifecycle` carriers (topology stays per-surface; only the wrap decision unifies). `PreparedExpression::{Raw|LegacySequence}` is a closed enum (not `rewritten: String + legacy_sequence: Option<String>`) so a wrapped value cannot store two representations or reach an invalid state.

## Analyzer-metadata trigger facts — ADOPTED (promoted from superior-but-unchosen)

Originally recorded as a heavier follow-up, now LANDED. The prior state RE-PARSED/re-walked expression source to derive wrap-trigger facts inside `legacy_wrap_rewritten` (`client_legacy_value.rs`) and returned `false` on any parse error — a genuine FAIL-OPEN (a `BuildExpression` surface silently degraded to raw); the earlier "already fail-open-proof" claim was overstated and is retracted. Same class: `client_codegen_helpers.rs` reparsed GENERATED text for thunk topology; `client_component_plan.rs` reparsed/source-sliced the dynamic `{@render}` callee with an `unwrap_or_default()` reference fallback.

Landed shape:
- The canonical expression analysis (`expr.rs` `collect_expr_references`) populates `has_sync_member_or_assignment`, the zero-arg-callee fact, and `RenderDynamicCalleeFacts` (callee span/chain shape plus subtree references and wrap-trigger facts).
- `prepare_template_value`, `legacy_wrap_rewritten`, the `b.thunk` unthunk decision, and `render_dynamic_callee` consume those canonical facts for value-wrap and topology decisions. The former render-specific parser walk, reference recollection, and fail-open `unwrap_or_default()` fallback are deleted.
- Dynamic `{@render}` emission still slices the callee using the canonical span and passes that slice through the shared `rewrite_source` → `rewrite_expression_dialect` codegen rewriter. That universal Svelte client rewriter reparses source to perform scope-aware identifier/read/write rewriting. This residual path is fail-closed, is not a type-resolution path, and is not eliminated by T2.
- The `has_call` and binding-impurity analyses also remain scope-aware plan-time reparses because binding classification finalizes after canonical syntax analysis. Every recovery failure produces `svelte-runtime-unsupported-expression-fact-recovery`; none degrades to `false`, empty references, or raw output.
- Eliminating these reparses requires a backend-wide expression-carrier cutover and is tracked separately; T2 closes the legacy value-wrap correctness class FOR THE INVENTORIED/ENUMERATED authored-value surfaces (not the universal Svelte expression-rewrite architecture); the authored-emission capability boundary — raw-string authored routes that can bypass the enum + routing scanner — stays D-61-deferred.
- `AuthoredValueSurface -> ValuePolicy` stays in PLANNING — whether official invokes `build_expression` is visitor/surface semantics.

## Follow-up (out of T2 scope): universal Svelte expression-rewrite typed-IR cutover

The full elimination of the residual plan-time reparses (`rewrite_expression_dialect`, `expr_has_call`, `expr_has_binding_impurity`) is a backend-wide cutover, deferred beyond T2. Its shape, captured for the future pass:

- ONE owned, arena-independent expression carrier / rewrite-fact stream produced by the canonical parsing pass — no consumer ever re-enters a parser over a source slice.
- The carrier captures everything the rewriter needs: lexical scopes, source-ordered identifier occurrences, call/member/assignment/update sites, nested-function boundaries, TS erasures, spans + trivia, dialect, and each occurrence's rewrite-role.
- Plan-time resolution runs against FINALIZED binding kinds over that carrier, preserving shadowing, signal/prop/store classification, lvalue semantics, `has_call`, and binding-impurity semantics exactly.
- Callee/subexpression projections address the carrier by typed node/span identity — never by slicing and parsing source text.
- The cutover is CLEAN and universal: `rewrite_expression_dialect`, `expr_has_call`, and `expr_has_binding_impurity` cease invoking parser entry points entirely; no render-only alternative path survives.
- Guards cover the COMPLETE production expression-prep/rewrite call graph with parser entry points explicitly inventoried (a new parser call site fails the gate until consciously classified).
- Verification: behavioral, refusal, trivia, dialect, source-map, and official-Svelte conformance tests over the cutover corpus.
