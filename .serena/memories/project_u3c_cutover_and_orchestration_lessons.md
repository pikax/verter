## Orchestration lessons (hard-won; the session had ~4 claude-code restarts)
- **SESSION RESTARTS ~hourly kill in-session Agent sub-agents + background watchdogs mid-work** (new session id in agent output_file path = restart signal; SessionStart hook fires). This is THE dominant failure mode. Mitigations that worked: (1) MANDATE commit-after-every-step (a restart then costs only minutes); (2) patch-backup uncommitted WIP (`git add -A && git diff --cached HEAD > <scratch>/x.patch`); (3) AUDIT background state at the start of every turn (don't rely on watchdog alerts — they die on restart too); (4) orchestrator OWNS the long full-workspace gate (an agent's long gate gets cut off by the restart); (5) CLI-dispatch fallback (`<scratch>/safe-claude-dispatch.sh`) for restart-survival if in-session agents keep dying.
- **Agents also HANG ~50min in** (turn/token limit) even without a restart — watchdog catches it; recover via continuation from last commit.
- **Serena edit tools + relative-path Read/Edit silently target the MAIN repo, NOT the worktree.** Implementers MUST use ABSOLUTE worktree paths + `git -C <wt> status` after edits. Bake into every worktree-batch brief.
- **Watchdog busy-detection must NOT grep 'node'** (always-present Serena/MCP servers → false "progress" masking stalls). Count cargo/rustc/clippy only; use mtime/HEAD for TS-phase progress.
- **codex CLI pattern that worked:** `cat brief | timeout 3600 codex exec -s read-only -C <worktree> -c approval_policy="never" -o <verdict.txt> > <log> 2>&1`. read-only sandbox = codex can read/trace but CANNOT run cargo (no race with the orchestrator gate); `-C` cd-aware for worktrees. Verify the `-o` verdict file has content.
- **3-way review repeatedly earned its keep — each lens caught what others missed:** codex#1 (BINDING, data-flow trace) found a surviving props/emits/slots DUAL-PATH that Claude (symbol-grep) + codex#2 (test-coverage) both passed; codex#2 found test-discrimination gaps (missing negative guards, lost NoInfer alias-shell) the others missed; the orchestrator's FULL-workspace gate found integration-test failures the implementer's `--lib`-only run missed (always run the full gate yourself).
- **TRUST-BUT-VERIFY caught a confident-but-WRONG investigation:** a focused agent ("adc13040") ruled "code regressed, snapshot correct" by ASSUMING the committed snapshot was the oracle WITHOUT checking the `assert_eq!` order (actual-vs-committed) or the fix's DIFF DIRECTION. The opposite was true: the code was already correct (cutover fixed it), the snapshots were STALE (carried a pre-cutover leak), and the fix REMOVED the leaked members from the baseline. Lesson: before trusting a "snapshot-is-oracle / code-is-wrong" verdict, verify the assert convention AND whether the fix added vs removed the symptom; a passing discriminating test + codex BINDING + the diff direction are the real arbiters.
- **Pre-existing-vs-caused must be checked at the TRUE base**, not a mid-change commit: a continuation claimed a TS failure "pre-existing" by testing at a mid-cutover commit (already had the change). Decisive check = run the one failing test at the actual integration base (main repo was AT the base) → confirmed pre-existing.
