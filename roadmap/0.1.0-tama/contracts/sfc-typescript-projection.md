# SFC TypeScript projection constitution

STP0 lock. Named products: `ProjectionPolicy v1`, `CurrentFeatureObligation schema`, `InferenceParticipation policy`, `ProjectionOwnershipMap`. Machine form: `tests/sfc-projection/STP0/products/`. This document is the human contract; the schema validator is the discriminating proof. It does not certify later production code.

## 1. Purpose

Ratify how Vue SFC TypeScript projection is owned before STP1 expands fixtures. TypeScript owns type answers. Vue generated default exports stay constructor-shaped and preserve `InstanceType<typeof Comp>`. One component use has one specialization transaction. Mapping geometry, semantic origin, and edit spelling stay separate. Every shipped valid Vue feature is RequiredCurrent.

## 4. ProjectionPolicy v1

1. TypeScript is the sole type-answer authority for projection checking text.
2. Vue SFC default export is constructor-shaped; `InstanceType<typeof Comp>` and `InstanceType<typeof Comp<...>>` remain the public instance spelling.
3. One `ComponentUseId` use has exactly one specialization transaction.
4. Mapping geometry (`CodeTransform` / source maps), semantic origin, and edit spelling are separate planes.
5. `inheritAttrs` omitted and `inheritAttrs: true` are the same runtime policy. Only `inheritAttrs: false` is a distinct runtime switch.
6. Vue-correct typed fallthrough is the primary policy. The original benchmark score is retained in a separate unmodified lane; it is not a second type policy.
7. No public callable replacement for a Vue SFC constructor. No synthetic runtime property whose only job is checker metadata.
8. Channel participation is syntax/framework policy (`authored-signature`, `contextual-consumer`, `validation-only`, `observation-only`, `coupled`). Variance and inference results are not computed from native TypeInfo.
9. Logical `ComponentUseId` is not a revision-qualified observation. Inferred use-input change invalidates the specialization. Unchanged checking text cannot justify stale source mappings.
10. Incomplete, configuration-missing, or cancelled observations cannot warm complete caches. Publication uses existing provider/LSO snapshot authority.

Policy id: `projection-policy.v1`.

## 5. Constructor-shaped default export

See `sfc-projection-instancetype.md`. Generated Vue default export must remain constructable. `InstanceType<typeof Comp>` is a RequiredCurrent row. Broad `any` constructors, vacuous `never` success, and callable SFC replacements are forbidden.

## 6. TypeScript type authority

A proposal that routes a prop, emit, slot, model, or fallthrough type through native assignability (`TypeInfo` relation as the published answer) is rejected (`STP0-authority`). TypeScript checker text is the type answer. Native analysis may observe; it may not own the published type.

## 7. Specialization transaction

See `sfc-projection-implementation-protocol.md`. One use, one specialization. Coupled generic inference is a later STP3/STP18 production concern; this lock only forbids a second transaction or a native TypeInfo variance owner.

## 8. Provenance separation

| Plane | Owner | Must not own |
| --- | --- | --- |
| Mapping geometry | `CodeTransform` / existing maps | type answers, edit transaction identity |
| Semantic origin | Vue semantic facts + TS checker subject | invented source locations |
| Edit spelling | LSO authored-edit transaction | mapping-only or checker-metadata properties |

A second mapping owner is rejected (`STP0-authority`).

## 9. CurrentFeatureObligation schema

Every shipped valid Vue TypeScript feature is `RequiredCurrent`. Rows live in `tests/sfc-projection/STP0/products/current-feature-obligation.json`.

Allowed obligation: `RequiredCurrent` only for shipped valid rows. Forbidden on those rows: `optional`, `external`, deletion, or silent drop.

Preserved intended semantics, not known unsound behavior. Correcting a bug requires a source-backed oracle and a clean/dirty pair. Removing the row is not a fix.

STP1 expands these families into executable fixtures. This lock does not pre-certify that expansion.

## 10. InferenceParticipation policy

Participation is assigned per channel as one of:

- `authored-signature` — author-written type/value is the signature.
- `contextual-consumer` — consumer context supplies the type (props at use, slot props, JSX).
- `validation-only` — channel is checked, not used to infer another binder.
- `observation-only` — visible to IDE/metadata, not an inference input.
- `coupled` — one specialization transaction; not a second native inference.

Native TypeInfo must not compute type-parameter variance or inference results for these channels.

## 11. ProjectionOwnershipMap

Machine form: `tests/sfc-projection/STP0/products/projection-ownership-map.json`.

Every in-scope outcome, consumer, and displaced route has exactly one implementation owner and, for displaced production routes, exactly one later production-capable deletion/rejection owner. Bindings use DAG node IDs when the node exists in this repository's DAG. Planned STP/STS successors that are not yet DAG members must appear in section 13. A documentation-only or zero-production lock cannot own a later production deletion.

This node retires no standalone legacy route. Displaced call sites are recorded as they migrate; final Vue removal is STP58; final Svelte removal is STS15.

## 12. Identity, invalidation, publication

- Lineage: B4R0 `SourceUnitId` / `SourceRevision` / `ContentId` / `MapRevision`.
- `ComponentUseId` is logical and distinct from revision-qualified observations.
- Use-input change invalidates the associated specialization.
- Unchanged checking text is not a license for stale mappings.
- Incomplete / missing-config / cancelled observations cannot warm complete caches.
- STP0 owns no production incremental state. STP0-AC3 and STP0-AC4 are not-applicable here with the untouched owners named in the ownership map (B4R0 lineage, LSO publication, CCA1J projection route, TCM0R observation identity).

## 14. Forbidden designs

Native type-answer substitution; callable Vue SFC replacement; broad any constructor; vacuous never success; duplicate script-body checker; fixed-N overload claim; invented source location; feature-mask diagnostic suppression; incomplete rename application; per-fixture options; hidden old-route answer; complete capability claim backed only by a dormant product. Author-written `any` and framework-legal open domains stay visible.
