# Block sizing contract

A dispatchable leaf owns one independently acceptable authority, migration, or cutover. The charter's production LOC and file budgets are planning references, not floors, ceilings, acceptance checks, or automatic rescope lines. A coherent implementation may reasonably finish above or below them. Compare the actual candidate with the estimate and investigate a material mismatch: if a block names one expected production file and the implementation changes ten, that is a scope smell requiring an explanation, not a mechanical rejection. The investigation decides whether the patch is still one reviewable outcome or has exposed hidden, independently landable work; do not split or pad a coherent change merely to hit a number. The `rescope_loc` and `rescope_files` fields are stronger comparison signals under the same judgment-based rule, even where a landed historical charter calls them mandatory.

Architect rescope remains mandatory when the candidate spans 3 unrelated crates/packages, or combines public/wire, unsafe, concurrency, or lifetime work with another major concern. A dispatchable charter may not contain suggested independently acceptable subblocks. Convergence creates no authority and performs only bounded validation, named residue deletion, or an atomic route switch; its 300 LOC/3 file sizing is likewise a reference for investigating drift rather than a hard line.
