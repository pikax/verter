# Tama 0.1.0 roadmap

The program merges current Rev11, the compiler architecture, and the successor expansion into one logical DAG while preserving independent product terminals. A block can start when every transitive DAG ancestor has a trusted implementation-ledger row. External requirements and conflict domains remain agent/maintainer planning instructions; they are not machine locks or readiness validators.

The graph deliberately has no all-products join. L4 closes Rev11; BR0 follows L4 and is an ordinary predecessor for successor work; each other product owns its own terminal. Sizing, review, integration, and the trusted ledger workflow are centralized in `contracts/`, keeping packets and charters compact.

## Formatter topology

The formatter train is a sequence of independently acceptable private foundations, language contributions, boundary adapters, one live-route cutover, and a proof-only product terminal:

1. `FMT0` materializes `catalogs/formatter-compatibility-v1.toml`, `catalogs/formatter-performance-v1.toml`, and their hermetic `fixtures/formatter/**` inputs before its ledger row can complete. Those artifacts ratify per-surface compatibility cells, the exact current route inventory and sole later owners, non-self-referential emission/copy work units, absolute result/cache capacity, and all required lifecycle-mode limits. FMT0 inventories and retains LSP on-type tag auto-close outside this train, changes no production file, and accepts no deletion.
2. `FMT1P` creates the otherwise-unused `verter_formatter` crate and owns private authored/formatted UTF-8 byte domains plus `FormatProvenanceId`/`AuthoredProvenance`/`Provenanced<T>`/`FormatProvenanceTable<R>`. `FMT1` and `FMT1A` consume that shared identity in parallel; `FMT1B` owns edits; `FMT1C` only joins provenance and implements map mechanics; `FMT1D` and `FMT1E` separately own range and cursor policy.
3. Script printers branch from `FMT2` JavaScript into independent `FMT2T` TypeScript and `FMT2X` JSX contributions, then `FMT2TX` joins those seams for TSX only. Style printers land as `FMTC0` CSS → independent `FMTCS0` SCSS and `FMTCL0` Less extensions. Each changes only private printer/view surfaces.
4. `FMTH0`, `FMTV0`, and `FMTS0` provide private HTML, Vue, and Svelte carrier contributions. Vue/Svelte require `FMT2TX`, `FMTCS0`, `FMTCL0`, and `CPF1` and perform no route switch or old-route deletion.
5. `FMT3C` composes the private carrier service in at most two packages and changes no public route.
6. `FMT4P` owns versioned cursor-free Rust DTOs, the only private-authored-range ↔ SFC-absolute `Span` conversion, a non-Serde private request that couples an optional zero-width authored cursor `Span` to its exact source revision/text basis, and a non-Serde private result that couples cursor projection to its exact formatted output. `FMT4F` alone constructs the cursor-bearing request after strict UTF-16 validation. `FMT4L` owns dormant negotiated-LSP full-document edit conversion only; `FMT4F` owns strict bidirectional NAPI/WASM UTF-16 request/result conversion; `FMT4N`, `FMT4W`, and `FMT4M` independently contribute complete native-package, WASM-facade, and MCP-router adapters.
7. `FMT3` alone switches `handle_formatting` to `FormatterLspAdapter` and deletes the displaced whitespace-only/shared route body. It neither adds LSP range/cursor support nor changes the retained on-type tag-auto-close route. No printer, protocol, or other adapter owns route deletion.
8. `FMT4` is a zero-production per-surface conformance/performance/capability promotion terminal. `CLIF0` remains the later CLI formatter owner.

Private authored/formatted wrappers never serialize and never reuse generated-TSX coordinate types. Rust and MCP support full/range formatting with SFC-absolute `Span` request/edit geometry and no cursor result. LSP supports standard full-document formatting only, converting edits through the negotiated `LineIndex`; it advertises neither formatter range nor cursor cells. NAPI/WASM support full/range/cursor through FMT4F's strict UTF-16 boundary. Every M formatter node uses 800 production LOC, 8 production files, and 2 related packages as a planning reference; material drift is investigated for hidden scope rather than failed mechanically.

## Compiler bridge topology

The compiler bridge uses stable zero-production joins for downstream ordering and independently landable implementation nodes for every mutation boundary:

1. `CCA1D1` migrates registered parse execution; `CCA1D2` separately migrates complete-only publication; `CCA1D` only joins their proof.
2. `CCA1M1` migrates direct/prepared/batch runtime consumers. `CCA1M2` and `CCA1M3` independently delegate the host-backed and fixed-Vue runtime-render compatibility implementations while retaining their two outer `compile_bundle` calls. `CCA1M` proves exactly those two calls remain.
3. After the Vue/Svelte host backends, `CCA1N3` exclusively deletes the host-backed `compile_entry` call and updates its exact eight-file route-record population, including the Svelte committed cell record and observed-record gate. `CCA1N4` independently deletes `compile_entry_runtime_render`. `CCA1N` joins both route facts and remains the predecessor consumed by `CCA1O1` and `J4`.
4. `CCA1O2` installs the NAPI adapter. `CCA1O2A`–`CCA1O2G` independently migrate native benchmarks, comparison tools, bounded SSR script groups, the native probe, session vocabulary, and the production TypeScript-plugin signature consumer. `CCA1O3` installs the WASM adapter and localizes `HostCompileProfile`, `HostBlockOverrideRequest`, and `HostVirtualQuery` so generated WASM declarations have no direct or transitive native profile dependency. `CCA1O3A`/`CCA1O3B` migrate the direct WASM tools. `CCA1O4` and `CCA1O5` migrate unplugin and playground consumers without deletion; `CCA1O4D` and `CCA1O5D` are the separate native and WASM terminal deletion owners. `CCA1O` alone deletes shared `FfiCompileProfile`.
5. Terminal combined-authority removal is sequential and separately reviewable: `CCA1T1` deletes the dynamic registry; `CCA1T2V` and `CCA1T2S` independently delete Vue and Svelte compatibility implementations before zero-production join `CCA1T2`; `CCA1T3` deletes the combined trait; and `CCA1T4` deletes the mixed option/output bucket. `CCA1` is only the zero-production convergence join.
6. Staged artifacts use independently landable framework and boundary cells: `CCA2A` owns schema/map qualification; `CCA2BV` and `CCA2BS` own framework assembly before zero-production join `CCA2B`; `CCA2C` owns host handoff; `CCA2D0`/`CCA2DV`/`CCA2DS` and terminal `CCA2D` split qualified style work; `CCA2E0`/`CCA2EV`/`CCA2EH` and terminal `CCA2E` split custom-block work; and `CCA2F` owns facade integration. `CCA2D0` and `CCA2F` are non-dispatchable and carry external requirements until maintainers ratify the unresolved cross-train contract/deletion owners. `CCA2` is only the zero-production join consumed by `C2`, `CMP0`, and `CPER0`.

Every M compiler-bridge node uses 800 production LOC, 8 production files, and 2 related packages as a planning reference; material drift is investigated for hidden scope rather than failed mechanically. A stable join never absorbs implementation fixes; discoveries reopen the precise predecessor owner.

## Project, source-module, bundler-host, and project-profile topology

Four successor trains now close the product boundary deliberately left outside the compiler bridge:

1. `PM0` ratifies a live project-model successor to historical `C1`; kernel `VID0`/`CAT0` retain orthogonal identity and catalog ownership, while `PM1` owns configured-project derivation/membership/compiler environments, `PM2` owns package/module resolution, `PM3` owns atomic snapshot publication, and `PM4` owns consumer cutover/deletion. IDX0 remains candidate/index authority only.
2. `SM0` separates statically captured source-module facts from both PM package resolution and bundler execution. `SM1` owns Vite aliases/assets/query/URL/worker/env facts; `SM2` owns `import.meta.glob` membership/invalidation; `SM3` owns consumer convergence.
3. `BND0` charters `packages/unplugin` as an intentional JavaScript/TypeScript product surface. `BND1` owns sessions and virtual identities, `BND2` owns resolve/load/transform and qualified processed-content handoff, `BND3` owns graph-qualified HMR planning, `BND4` certifies Vite/Rollup/webpack/esbuild/Rspack/Rolldown/Farm for both Vue and Svelte, and `BND5` promotes/deletes. Verter supplies plugin/HMR semantics to bundlers; it does not become a bundler or dev server.
4. `PPR0` defines framework-neutral project roles. Nuxt (`NUX0`–`NUX3`) and SvelteKit (`SKT0`–`SKT3`) are co-equal first-class lanes; `PPR1` locks the shared project-profile architecture only after both terminals and cross-profile negative fixtures pass. Next is no longer the selected first project profile.

JavaScript packages may execute bundler/framework host hooks and capture typed configuration facts. Arbitrary ecosystem configuration never executes inside Rust/WASM semantic demand. All four trains target accepted convergence gates, so the additional `D2C` flow-audit projection and `D2D` typed surface-producer outcome on `trains/rev11-flow` become transitive ancestors when that train lands; this branch does not duplicate those nodes or their ownership. Reconciliation must preserve the union topology (`D2D → D2B → D2C → D3R`, with `TE5` still a `D8` predecessor), the schema-2 implementation ledger, and both type-algebra/type-evaluation modules before strict validation is rerun.
