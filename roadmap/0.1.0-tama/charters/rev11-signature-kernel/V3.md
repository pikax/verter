# V3 — Complete global contributor snapshots

Readiness comes only from trusted implementation-ledger rows. A READY node may start; tooling does not validate commit locators, Git identity, receipts, leases, external state, or runtime admission.

Normative contract: `contracts/signature-kernel.md` section 9.

## Independently acceptable outcome

Global contributor populations are maintained at artifact ingestion and published atomically as coherent immutable snapshots; every global-symbol lookup reads the population and records the symbol's contributor fingerprint (including a proved-empty set); and the two whole-program `known_canonicals()` scans on the augmentation lookup path are deleted. One independently acceptable outcome; no subblocks.

## Concrete surfaces and APIs

- Ingestion: the `IndexedReady` publish path in `crates/verter_session/src/` (`FileArtifactStore`, `fact_emission::collect_augmentations`, `ModuleAugmentationIndex`, `AugmentationPopulation { Base, Session }`) extended with per-file global contribution facts keyed by resolved global symbol identity: lib files, top-level interfaces and namespaces in script files, `declare global`, applicable module augmentations, and the file's script/module classification. `noLib` disables automatic libraries only.
- Population: new `crates/verter_session/src/global_contributors/` — `GlobalContributorPopulation` (immutable snapshot complete at revision `E` for program snapshot `S`), the publication protocol (pin `S`/`E`, read changed membership, build the delta outside reader-visible state, verify every artifact version belongs to `S`, publish atomically or abandon), per-symbol positive and negative fingerprints, declaration-merging order from the existing logical program/declaration authority (never file-read, lock, or queue-drain order).
- Consumers: `project_semantic_dispatch/build.rs::resolve_external_module_augmentation` (`:4246`) and `runtime_nominal_call_signatures` (`:10777`) read the population through `collect_augmentation_contributions`; the loops over `host.workspace().known_canonicals()` are deleted. Cached reusable generic lowering/substitution of contributor bodies.
- Mutation boundary: those surfaces, the workspace trait surface only if a population hook is required, and test homes.

## Exact predecessor contracts

- **V1:** implemented ledger row; effective `noLib`/`lib` options and the semantic context are inputs to population identity.
- **External requirements:** none.

## Source-specific scope

- Preserve `session_overlay_augmenter_isolated_from_base_index` and `session_overlay_augmentation_isolated_from_base_meta`: overlay contributions never poison the base population and never cross sessions.
- `host_upsert_performs_no_reverse_dependent_eviction` stays green: population maintenance is fact-driven, not eviction-driven.

## Acceptance IDs and discriminating proof

- **V3-AC1 — first-contributor transitions:** adding or removing the first `declare global` contributor for a symbol invalidates prior negative reads; renaming a symbol, flipping a file script↔module, changing `noLib`/`lib`, and cancelled lowering each produce the checker's answer or a typed incomplete, never a stale positive.
- **V3-AC2 — coherence under concurrency:** an edit racing a publication cannot be lost between drain and Complete; readers observe either the old or the new coherent snapshot; forward/reverse/random artifact completion yields identical declaration precedence.
- **V3-AC3 — no whole-program scan:** the lookup path performs no `known_canonicals()` call (counter/guard) and an edit to an unrelated file does not invalidate an augmented primitive's signature read (fingerprint test).
- Test homes: `crates/verter_session/src/global_contributors/*_tests.rs`, `cross_file_augmentation_merge_equivalence_tests.rs`, `tests/cases/g_block/semantic_determinism_matrix.rs`.

## Deletions and forbidden designs

- Delete both `known_canonicals()` loops in `build.rs`; no changed-file queue treated as completeness proof; no arrival-order precedence; no second merge engine (the `MergedDecl` peer-merge path remains the merge authority).
- Do not implement successors or silently enlarge this charter.

## Budgets and mandatory rescope

- Target ceiling: 1,500 production LOC, 15 files, 2 crates (`verter_session`, `verter_workspace`). Mandatory rescope above 3,000 LOC, 25 files, or 3 unrelated crates.
- Correctness budget: zero stale publication, zero lost edit, zero unrelated invalidation.

## Abort conditions

- Stop before mutation if the artifact-ingestion path cannot observe script/module classification and global contributions for lib files, or if the complete diff will not fit one review context.
- Abort on unexplained latency or RSS divergence in the ingestion path.

## Targeted verification

1. `cargo nextest run -p verter_session -p verter_workspace`
2. Run every final command in the bound `targeted-domain` profile on the squashed review candidate.
3. TDD: each acceptance row is un-ignored (failing) before its mechanism lands.

## Review and lower-severity findings

Apply `concurrency-3`: 3 fresh distinct harness tasks covering exactly `adversarial`, `conformance`, `concurrency-lifetime`. P0/P1 block; P2 needs a named owner when deferred; any post-review content change invalidates every verdict.

## Trusted implementation ledger

Before squashing or review, the implementation patch transitions this node's predeclared row in `authority/state/implemented.toml` from `status = "pending"` to `status = "implemented"` with the planned squash commit message, approximate date with timezone, and optional pull-request number.
