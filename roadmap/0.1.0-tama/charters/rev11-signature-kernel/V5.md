# V5 — SignaturesOfType discovery and demand-driven signature results

Readiness comes only from trusted implementation-ledger rows. A READY node may start; tooling does not validate commit locators, Git identity, receipts, leases, external state, or runtime admission.

Normative contract: `contracts/signature-kernel.md` sections 2, 3 and 8.

## Independently acceptable outcome

One discovery authority, `SignaturesOfType(subject, Call | Construct, SemanticContextId) -> QueryOutcome<SignatureSetRef>`, enumerates candidates over direct signatures, object and interface surfaces (inherited and merged), constrained type parameters, apparent primitives and collections through resolved globals, aliases, unions (common-match then restricted synthesis), and intersections (signature-equivalence dedup, constructor and mixin composition); one positional model with explicit modes serves comparison, applicability, tuple projection, and utility inference; and `ReadSignatureResult(descriptor, CallSubstitutionId, ResultDemand, ResultEvaluationContextId, SemanticContextId)` forces existing return/effect obligations on demand with precise evidence. No consumer is cut over here. One independently acceptable outcome; no subblocks.

## Concrete surfaces and APIs

- Queries: `SemanticQueryKey::SignaturesOfType { subject, kind: SignatureKind, context }` and `SemanticQueryKey::ReadSignatureResult(ReadSignatureResultKey { descriptor, call_substitution, projection: ResultDemand, evaluation, semantic_context })` added to `crates/verter_session/src/semantic_query.rs` (tag, `ALL`, `name()`, `FamilyKey`, `candidate_cap`, `family_and_slot`, spec rows, generated table, audit WorkSite rows, typeinfo manifests); producers in new `crates/verter_session/src/signature_kernel/discovery.rs` and `result.rs` over the V2 records.
- Positional model: `crates/verter_session/src/signature_kernel/positional.rs` — one shape accessor with modes (comparison, applicability, tuple projection, utility inference) covering declared vs effective minimum, declared optional vs synthesized optional positions, strict-null `undefined` inclusion, optional tuple elements, array rests, fixed tuple rests, variadic middle segments and required tails, receiver exclusion, void-sensitive arity, generic rest instantiation, defaults, JavaScript signature modes; parameter names preserved for diagnostics and never used as type equality. It generalizes `call_resolve.rs::call_candidate_arity`, `rest_shape`, `mapped_parameter_type`, `tuple_suffix_target`, `optional_parameter_target` (which now honours the effective options) and `semantic_query.rs::split_this_receiver`.
- Subjects: direct `Signature` returns `One` only when the stored kind matches; object surfaces read the resolved `SurfaceView` including inherited/merged declarations and overload visibility (`visible_overload_ordinals` remains the one rule, now with one producer); type parameters use constraint semantics; apparent primitives/collections resolve through the V3 population and bound generic substitution (closing `apparent_type.rs`'s primitive `Miss`); `Function`/`CallableFunction`/`any` dynamic-call permission stays a call-resolution rule, never a fabricated signature; alias/instantiation settlement is the shared worklist with dependency tracking.
- Unions: the two-phase procedure — common matches first (exact comparison under binder mapping, defaults, predicates/assertions, receiver direction, flags), then restricted synthesis — with `VerterStableV1` arm traversal, first-match rules, authored precedence, and no Cartesian product; `UnionCommon`/`UnionSynthesized` recipes with ordered mapped constituent edges. Intersections: signature-equivalence dedup with retained representative/provenance; `IntersectionConstruct` for mixin constructors.
- Results: candidate enumeration completes with closed body recipes without inspecting bodies; `ReadSignatureResult` reuses `FlowReturn` obligations (V1 `ResultEvaluationContextId`), records body-content/captured-context dependencies only when forced; composite predicates/assertions follow the shared inference rules, never blind OR/AND. `SemanticNodeData::Signature` gains `predicate: Option<TypePredicate>` (predicate/assertion payload) lowered by the producer.
- Mutation boundary: those surfaces, registries/mirrors they force, and test homes; existing consumers (`call_resolve.rs`, utilities, Awaited) are not cut over.

## Acceptance IDs and discriminating proof

- **V5-AC1 — discovery parity:** raw semantic candidate observations (count, order, kind, binders, positions, optionality, minima, rest, receiver, return, predicate, representative) match the recorded 7.0.2 corpus for every in-scope row; an empty candidate set is a complete negative distinct from every incomplete reason.
- **V5-AC2 — positional model:** the section 14 parameter rows (declared vs synthesized optionality, explicit `undefined`, strict-null toggle, optional tuple elements, empty/fixed/array/middle-variadic rests and required tails, receiver placement, void-sensitive minimum) decide identically through every accessor mode.
- **V5-AC3 — precedence under delay:** a later successful candidate is never committed while an earlier candidate remains unresolved (adversarial completion-order harness); union-arm traversal uses `VerterStableV1` while authored within-arm order is preserved.
- **V5-AC4 — lazy results:** enumeration forces zero bodies (counter); `ReadSignatureResult` with `Return`, `Effects`, and `Both` projections reuses one obligation and roots its body dependencies; a body-only edit invalidates consumed results and no parameter-shape work.
- **V5-AC5 — no escaped binders:** every instantiated output is owned by an explicit binder region (assertion in the producer's tests).
- Test homes: `crates/verter_session/src/signature_kernel/*_tests.rs`, `signature_corpus_rows_tests.rs`, `tests/cases/g_block/semantic_determinism_matrix.rs`.

## Deletions and forbidden designs

- No Cartesian product of overload choices; no per-consumer union synthesis; no `TypeExpr` raise/compare/lower round trip in matching; no `this`-less parameter read; no fabricated `Function` signature; no result computed eagerly for a shape-only consumer.
- Do not implement successors or silently enlarge this charter.
