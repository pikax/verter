# V4 — Deterministic semantic order, ReduceIntersection, and graph-native relations

Readiness comes only from trusted implementation-ledger rows. A READY node may start; tooling does not validate commit locators, Git identity, receipts, leases, external state, or runtime admission.

Normative contract: `contracts/signature-kernel.md` sections 5, 6 and 7.

## Independently acceptable outcome

Semantic union order is deterministic under `VerterStableV1` and independent of loading, querying, allocation, cache history, and schedule; union identity stays carrier-qualified before any representative elimination; ordered intersection reduction is owned by `ReduceIntersection` over explicit construction inputs with input-defined grouping preserved under parallel child evaluation; and the relation engine decides `Subtype` and `StrictSubtype` graph-natively over the structural domain the signature consumers need. One independently acceptable outcome; subblocks are review checkpoints only (representation audit; stable key and view foundation; primitive relation and reducer foundation; ordered recipe evaluation; structural/binder relation closure; SCC interaction and union reductions).

## Concrete surfaces and APIs

- Stable keys: new `crates/verter_session/src/semantic_query/stable_key.rs` — `VerterStableV1` versioned category/sub-tag table and encodings (explicit endianness, string and scalar encoding, domain separation), keys per section 5.4 (intrinsics/sentinels fixed tags; literals by canonical value and kind; authored carriers by logical source-unit identity + declaration/owner/role anchor + bound arguments; anonymous authored types by owner/syntax-role anchor; binders by owner/recursive region + position/role; synthetic types by closed normalized recipe), `(fingerprint, exact key)` as the pair order with exact comparison on collision, unordered child collections as key sets, ordered collections preserved; comparators never force bodies, resolve names, run relations, instantiate, or reduce unions. No final fallback to node id, pointer, worker id, table ordinal, timer, or counter.
- Union views: `SemanticUnionMembers(UnionRef, SemanticContextId)` memo with private key `(carrier-qualified UnionRef, project_union_order(policy_set), project_order_domain(context))`, lazy, built in request scratch, a resident valid view never re-sorted. `crates/verter_session/src/semantic_query/composite.rs` — the union node's semantic identity becomes carrier-qualified (the immutable carrier/origin set participates in identity), closing the disclosed first-wins `CompositeOriginCategory` window; `canonical_algebra.rs:1110` `sort_by_key(|id| id.0)` and `project_semantic_dispatch/mod.rs::canonicalize_node_list` order by stable key; every order-sensitive reduction (first-occurrence structural dedup, representative selection, literal subsumption survivors, `relation.rs:2350/4126` candidate ordering) consumes the stable order before the decision.
- Intersection authority: `SemanticQueryKey::ReduceIntersection { input: IntersectionInputRef, purpose: IntersectionPurpose, context: SemanticContextId }` replaces `NormalizeIntersection` (variant, tag, `ALL`, `name()`, `FamilyKey`, `candidate_cap`, `family_and_slot`, spec row, generated table, `verter_audit` WorkSite row `session.reduce_intersection`, typeinfo manifests, `loop5_instrumentation`); `IntersectionInputRef = Empty | Unary | Binary | Recipe(IntersectionInputId)`, `IntersectionRecipe = OrderedOperands | OrderedSteps([Value | EvaluateSubgroup(input, purpose)])`, syntactic normalization under proven rewrite laws before memoization, binary fast path with no recipe allocation, one ordered n-ary kernel with a request-local builder, no prefix materialization, fixed evaluation tree under parallel children. `canonical_algebra::canonical_intersection` becomes the private `intern_ordered_intersection`; `intern_normalized_union_or_intersection(…, false)` routes through `ReduceIntersection`. Reduction stages retained in order: never/any/error, nullability, literal/domain, discriminants, constraints, supertype elimination; construction-identical first-occurrence dedup only, never general `Identity`.
- Relations: `project_semantic_dispatch/relation.rs` — the `Subtype | StrictSubtype => Unknown` refusal (`:4996-5001`) is replaced by graph-native decision over primitives/literals, unions/intersections, constrained parameters, objects with inherited properties/optionality/visibility/index signatures, callable and constructable objects, arrays/readonly arrays, tuples/variadic rests, instantiated generics, and recursive combinations, through the existing `ObligationRuntime` SCC machinery; `relate_function` (`:7492-7509`) adopts the shared positional model (last-required-position arity, rest expansion, `this` receiver split) instead of a non-optional count; `Identity`, `Comparable`, `Assignable` stay distinct with no forwarding. Relation keys carry `SemanticContextId`.
- Audit: an executable audit that union member dedup identity ≠ `Relate(Identity)` ≠ display equality ≠ pure shape equality (four discriminating fixtures).
- Mutation boundary: those surfaces, registries/mirrors they force, and test homes. `NormalizeUnion` is kept but reads the stable order; its retirement is V8's.

## Acceptance IDs and discriminating proof

- **V4-AC1 — order laws:** completed union projections agree across forward/reverse/random arrival, lazy vs eager, unrelated interning first, worker counts, cold/warm/replay; pair locality holds; injected full fingerprint collisions and equal-prefix adversaries order by exact key; no two distinguishable members compare equal.
- **V4-AC2 — carrier preservation:** a union of duplicate shapes with distinct authored/synthetic origins keeps both carriers through construction; the first-wins category window is closed (mutation test flips it).
- **V4-AC3 — ReduceIntersection:** `((A & B) & C)` and `A & (B & C)` keep their evaluation trees under parallel children; a two-term list with a meaningful subgroup does not collapse to flat binary; simple binary input allocates no recipe; the 7.0.2 grouping witness holds; no prefix/product allocation explosion (counter).
- **V4-AC4 — relations:** separate `Identity`/`Subtype`/`StrictSubtype`/`Assignable`/`Comparable` outcomes on the section 14 equality rows; no in-scope structural `Unknown`; no assignability-as-subtype shortcut (mutation test); recursive structural objects converge through the SCC runtime.
- **V4-AC5 — parent invalidation:** changing the order policy invalidates a resident `ResolveOverloadSet`/`Relate` parent and its leaf together.

## Deletions and forbidden designs

- Delete `NormalizeIntersection` as a live key (retired row), the public `canonical_intersection`, the arena-id sort at `canonical_algebra.rs:1110` and in `canonicalize_node_list`, and the `relate_function` count-based arity; no production clone of the TypeScript comparator; no serialized interner or serialized queries to pass determinism tests; no generic commutativity/associativity property test on `ReduceIntersection`; no structural-intersection-dedup shortcut.
- Do not implement successors or silently enlarge this charter.
