# V1 — Effective options, semantic contexts, compact outcomes, and rooted admission

Readiness comes only from trusted implementation-ledger rows. A READY node may start; tooling does not validate commit locators, Git identity, receipts, leases, external state, or runtime admission.

Normative contract: `contracts/signature-kernel.md` sections 2, 3.4, 3.6 and 4.

## Independently acceptable outcome

Semantic queries run under one exact, interned semantic context that carries real effective compiler options and one context-owned immutable policy set; results are compact `Ready`/incomplete outcomes with shared cold evidence; every result demand whose answer depends on contextual typing, captured environment, receiver, or narrowing state carries that identity in its key; and synthesized results are admitted warm when their dependency proof is complete rather than only when an authored occurrence exists. One independently acceptable outcome; no subblocks.

## Concrete surfaces and APIs

- Effective options: `crates/verter_semantic/src/resolver_core/project_config.rs::IdeProjectCompilerOptions` gains the canonicalized semantic option set — the `strict` umbrella expanded (`strictNullChecks`, `strictFunctionTypes`, `strictBindCallApply`, `strictPropertyInitialization`, `noImplicitAny`, `noImplicitThis`, `useUnknownInCatchVariables`, `alwaysStrict`) plus `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noLib`, `lib`, `target` — resolved once per configuration by `crates/verter_workspace/src/config.rs::load_compiler_options_inner` (which already walks `extends`) and canonicalized as effective values. `crates/verter_workspace/src/engine.rs` stops hardcoding `EnvHashInputs { type_strict: false, type_no_implicit_any: false }` and `crates/verter_workspace/src/env_hash.rs::type_env_hash` folds the full effective semantic option set. `crates/verter_session/src/project_semantic_dispatch/dispatch_txn.rs::StrictFamilyConfig` is sourced from the effective options; the per-host test knob `RelationHostKnobs::strict_family_relax_bits` (`host_construction.rs`) is deleted, with causal-order and strictness injection moving to an explicitly isolated test namespace.
- Semantic context: new `crates/verter_session/src/semantic_query/semantic_context.rs` — `SemanticContext { effective_semantic_options, resolver_library_project_environment, policy_set: SemanticPolicySetId, R/T/L/J axes }`, interned by exact equality behind a digest, `SemanticContextId`; `SemanticPolicySet { compatibility_version, union_order: SemanticOrderPolicyId (VerterStableV1), intersection_policies_by_purpose, existing semantic policies }`, one production default; private projections `project_union_order(&SemanticContext)` and `project_order_domain(&SemanticContext)` with no public constructor for an independently supplied policy.
- Outcomes: `crates/verter_session/src/semantic_query/outcome.rs` — `Ready<T> { value, evidence: OutcomeEvidenceId }`, `OutcomeEvidence { proof: DependencyProofId, diagnostics: DiagnosticRecipeSetId, recovery: RecoveryProvenanceId }` with reserved IDs for empty diagnostics, no recovery and context-free evidence; `QueryOutcome<T> = Ready | Incomplete(IncompleteReason)` where `IncompleteReason` is the closed typed set (cancelled, budget, unsettled input, unsupported, unresolved obligation); `QueryResult`/`QueryError`/`ResultCompleteness` in `semantic_query.rs` and `CacheRead` gain the outcome mapping without per-read owned vectors or new `Arc` clones; location-independent diagnostic recipes replace any call-site-located diagnostic stored on a type-only memo.
- Complete result-demand identity: `crates/verter_session/src/semantic_query.rs::FlowReturnKey` gains `evaluation: ResultEvaluationContextId` (`ContextFree | Identified(...)`) covering contextual typing, captured environment, receiver, and narrowing state; `ResolveCallKey.flow` stops being pinned to `FlowNarrowingKey::empty()` at `flow_return.rs:934` and `:14094`; `ResultDemand` is the closed projection vocabulary (return, predicate/assertion effect, both) replacing `ReturnProjectionDemand::whole_return()`-only construction.
- Compact family keys: `crates/verter_session/src/semantic_query_memo/family.rs` — `Relate`, `ResolveCall` and the coming signature families key on interned handles so the 136-byte `FamilyKey` bound in `tests/cases/g_block/u2b8_relate_upgrade_guards.rs` holds with margin; `RelateMemoKey` (144 bytes) is interned rather than boxed.
- Rooted admission: `semantic_query.rs::AdmissibleCallResult::admits` (authored-occurrence-only) and `project_semantic_dispatch/build.rs::signature_group_is_rootless` are replaced by dependency-rooted admission: a candidate whose descriptor, operand origins, environment, substitutions, and consumed body obligations carry a complete stable dependency proof admits; a rootless or incomplete result stays transaction-local. `SignatureCandidateOrigin::Rootless` is retained as provenance, never as the admission oracle.
- Cache schema: incompatible persisted schemas bump their version.
- Mutation boundary: those surfaces, `query_key_spec.rs` rows and the generated `query_key_spec_table.txt`, `scripts/gen-typeinfo-ignore-manifest.mjs` mirrors, and their test homes.

## Acceptance IDs and discriminating proof

- **V1-AC1 — effective options:** two projects differing only in `strict` (or in one umbrella member) resolve different `type_env_hash` and different relation verdicts for `optional`-vs-required and `null`-assignability rows; `extends`-inherited and explicit spellings of the same effective value share one context id; cross-project isolation holds.
- **V1-AC2 — single policy owner:** a `SemanticUnionMembers`-style leaf key cannot be constructed with a policy different from its context's projection (unrepresentable, compile-time); changing the policy set changes the identity of a resident parent `Relate`/`ResolveOverloadSet` result and its leaf, and a formatting-only change rebuilds neither.
- **V1-AC3 — contextual demand separation:** two demands sharing descriptor and type arguments but differing only in contextual expected signature, receiver, or narrowing state coexist as distinct correct results; equal complete demands reuse one computation; shape-only and annotated results force no body.
- **V1-AC4 — compact outcomes:** a complete direct `Empty`/`One` read allocates no result heap memory (allocator canary), retains evidence, and never claims an empty proof.
- **V1-AC5 — rooted admission:** a synthesized signature with a complete dependency proof warms and replays equal to fresh; a rootless one stays transaction-local; a provisional inference result is never admitted; diagnostics reused at a second call site carry that site's location.

## Deletions and forbidden designs

- Delete `RelationHostKnobs::strict_family_relax_bits` and every hardcoded `type_strict: false` input; delete the authored-only admission predicates named above; no caller-supplied policy override on any public query; no changing global content generation in a persistent key; no second admission vocabulary added beside `Admission`, `ComputeAdmission` and `SignatureAdmission` (consolidate, do not extend).
- Do not implement successors or silently enlarge this charter.

## Budgets and mandatory rescope

- Target ceiling: 2,500 production LOC, 25 files, 3 crates (`verter_session`, `verter_workspace`, `verter_semantic`). Mandatory rescope above 5,000 LOC, 40 files, or 4 unrelated crates, or when public/wire schema changes combine with unsafe or lifetime work.
- Correctness budget: zero stale warm hit across a strictness or policy change; zero aliasing of two contextual demands on one key.
