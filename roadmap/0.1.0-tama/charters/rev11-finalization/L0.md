# L0 — Public product-surface capability and performance catalog

## Independently acceptable outcome

Ratify the public product surfaces this release advertises, each surface's stability class, and the controlling performance rows that govern it. This node changes plan/evidence/tooling artifacts only: it implements no product behavior, measures no candidate, and repairs nothing. MEM0 supplies the measurement and budget methodology; SG0 supplies the restored shipped-configuration execution lane that makes each surface executable.

The gap this closes is concrete. `performance-gates.toml` locks the cells the currently unlocked block needed and says so explicitly: the direct-compiler, managed-compiler, CSS, provider and competitor families are not locked there and no cell claims them. contracts/resource-and-finalization.md, L2 already permits a third controlling source — the owning product's ratified performance catalog — and that catalog does not exist. Without it, a surface the release advertises can pass closure by never having been measured.

## Binding boundaries

Follow contracts/resource-and-finalization.md, Accounting and ownership and L2, and the extension rule stated in `performance-gates.toml`. Produce `catalogs/product-surface-catalog.toml`, its schema and a validator, in the same shape as the MEM0 budget and its validator.

Each advertised surface carries: its public consumer and documented entrypoint; a stability class of `stable`, `preview` or `experimental-unranked`; the executable command and corpus that exercises it, with its build and fixture prerequisites and its local-versus-CI lane; its controlling wall, allocation and process-tree RSS rows with measurement method and limits; and, for a non-stable class, the replacement SLO and the node that removes the class.

The population must cover at least the surfaces the published 0.0.1-beta.5 run exercises: Vue direct and managed compile in raw and CSS configurations; Vue CSS semantics; the `verter-tsc` project check and its correctness wall; component-meta scalar and batch; host lint; the language-service typing and edit loop; and the Svelte equivalents of each. A surface absent from this catalog is not advertised, and a surface advertised in published documentation or a package entrypoint but absent here fails validation.

Registering these rows is an EXTENSION under `performance-gates.toml`: it requires a new implementation lock record digest and the same independent review class, and it never licenses weakening, reweighting, subsetting or reinterpreting an existing locked cell.

## Acceptance and evidence

- **L0-AC1 — sole-owner outcome:** every advertised surface has exactly one stability class and exactly one controlling row set, with one named owning node for each non-stable class. A surface with no executable command cannot hold the `stable` class; a surface with no class fails catalog validation; two catalogs or a second class authority is rejected.
- **L0-AC2 — positive contract:** every limit is ratified from recorded published baseline measurements before any candidate is measured, with the baseline's provenance, machine, toolchain and corpus recorded. A `preview` or `experimental-unranked` class states its replacement SLO and its removing node. Weakening a ratified row after observing a candidate is prohibited; correcting one requires the extension procedure above.
- **L0-AC3 — incremental equivalence:** RSS and process-tree measurement follows MEM0's method, including allocator slack, and is stated separately from exact owned-byte accounting. A statistical metric carries no implied 0.0% comparison bound, and a paired frozen-dependency methodology is specified for every cross-release comparison so that a moved dependency set cannot be attributed to Verter.
- **L0-AC4 — bounded work:** list the executable build, run and negative-control commands for every row and prove the validator rejects a surface with a missing class, a missing command, a stable class without a limit, a non-stable class without a removing node, and a row whose limit was edited after ratification.

## Verification and consumers

Run the catalog schema and fixture validation plus docs-domain. **L2** consumes the controlling rows as a third controlling source alongside `performance-gates.toml` and the MEM0 budget. **L4** consumes the stability classes as its capability-outcome population. STP54, STP57, STS17 and the product terminals consume their own rows when they qualify their surfaces later.

No new runtime capability, product behavior or measurement result is accepted here. Abort if an advertised surface has no executable command, if a locked `performance-gates.toml` cell would have to change to accommodate a row, or if a proposed class would describe a surface as stable that its owning terminal has not yet delivered.
