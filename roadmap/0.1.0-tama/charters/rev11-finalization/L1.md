# L1 — Long-churn bounded-memory soak

## Independently acceptable outcome

Execute and prove the fixed long-churn memory experiment over the integrated system. E4 and G4 supply physical/aggregate retention, H3 coherent publication, J4 style lifecycle and K3 host teardown; MEM0 supplies the measured budget and exact workload transitively.

## Binding contract and mutation boundary

contracts/resource-and-finalization.md, L1, is the acceptance contract. Expected homes are verter_bench, verter_audit measurement adapters and packages/benchmark. Bind current instrumentation and public host request routes in the implementation packet. This node owns the runner, fixtures and proof; discovered semantic, admission or lifetime defects return to their existing owners.

## Acceptance and discriminating evidence

- **L1-AC1 — sole-owner outcome:** run every frozen action in both normal and pressure modes, with at least 10,000 actions, all required lifecycle classes and complete independently checked action/result inventories.
- **L1-AC2 — positive contract:** sample at least every 100 actions; every sample, including the first 2,000 actions, must satisfy all absolute caps or the run fails. The first 2,000 establish the steady-state envelope; subsequent comparable control live sets must also obey the frozen retained-byte envelope. Closed projects/released handles reclaim their attributable storage. Report RSS separately under the ratified measurement rows.
- **L1-AC3 — incremental equivalence:** applicable incremental results equal fresh construction; failed construction and cancelled/stale/partial work release their reservations and never warm. High-cardinality keys, multiple projects, overlapping requests, failed construction with concurrent readers, and held/released results are mandatory.
- **L1-AC4 — bounded work:** the exact runner fails for a proven applied retained-key leak and an omitted workload class, and fails on missing summaries or unexpected skips. Bind its executable command and prerequisites to an owning gate profile or required CI lane before marking implementation complete.

## Verification and consumers

Run the actual fixed workload and its focused negative controls, then targeted-domain; core tests alone do not execute or prove the soak. Attach normal/pressure summaries and exact metric references for L2/L4 review. A proof-only patch cannot mark this workload not applicable.
