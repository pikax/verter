# CCA1O3E — Live-WASM carrier-fixture freshness rail

## Independently acceptable outcome and rollback boundary

The durable problem: the committed browser-carrier fixture is a snapshot of real host output that nothing compares against the host any more. The capture script only writes; it has no comparison mode, so the committed bytes are refreshed solely when someone remembers to run it, and the fixture's last generating commit is hundreds of commits behind the tree. The guards that consume it deliberately load the committed JSON instead of the live artifact, and the one assertion that calls itself a freshness check only inspects generated path names and asserts declaration text is non-empty. A compiler-output change therefore leaves the fixture stale and every consuming guard green, so those guards assert yesterday's output while claiming to describe the shipped one. The capture also passes a compile-profile key to source registration that the registration request has never declared; the request object is not closed, so the key is silently discarded, and the baseline is produced by a call that misrepresents what it asked for.

Outcome: the committed fixture is regenerated from the currently built browser artifact and a comparison mode makes that correspondence checkable, so a compiler-output change that is not accompanied by a regenerated fixture fails rather than passing quietly. Reverting removes the comparison mode and its invocation and restores the write-only script; the fixture stays as the regenerated bytes.

## Concrete surfaces and APIs

- `packages/playground/src/editor/__fixtures__/wasm-carriers.json`: regenerated from the currently built browser artifact by running the capture command. It is never hand-edited, and no committed byte is authored by hand.
- `packages/playground/scripts/capture-wasm-carrier-fixtures.mjs`: a deterministic in-memory renderer that produces the exact committed bytes, used by both writing and comparison, plus a comparison mode that renders and compares against the committed file without writing. The comparison reports what differs and exits non-zero on any difference.
- The same script's source registration drops the compile-profile key it passes today, so the regenerated baseline is produced by an honest source-only registration. The key is not added to the registration request: registration carries source only, and compile demand is stated on its own call.
- `packages/playground/package.json`: a command that runs the comparison.
- `.github/workflows/ci.yml`: a hard invocation of that command in the job that builds the browser artifact, placed after the build, so both a pure browser-binding change and a playground change compare the committed fixture against the artifact this run actually built. It is not advisory, not conditional on which paths changed within that job, and does not degrade to a skip.
- Determinism is the renderer's own: repeated renders of the same artifact over the same sources produce identical bytes, including key order and formatting.
- The fixture's sources, keys, per-source surfaces, and schema are unchanged. Recording an unavailable surface explicitly, rather than as a silent null, is preserved.
- Migrating the capture tool onto a typed compile request, and any binding change, are excluded. A consuming guard may be conformed to the regenerated fixture ONLY where that fixture invalidates a fact the guard incidentally encoded about captured output — the guard's behavioural claim must survive unchanged and stay discriminating, and a precondition it previously read from the fixture is stated directly instead. Rewriting what a guard actually proves remains excluded.

## Exact predecessor contract

- **CCA1O3:** implemented ledger row for “WASM typed host-request adapter”; the browser binding's request surface is settled, so the recaptured baseline is taken against a stable binding rather than one mid-change.
- **CCA1O1A:** implemented ledger row for “Canonical Svelte custom-element prop-type admission”; the Svelte custom-element prop-type slot has its final shape, so no captured surface encodes a superseded closed vocabulary.
- **CCA1O3C:** implemented ledger row for “Execution-proven WASM JS-boundary gate”; the browser binding's boundary refusals are proven by execution, so a capture run that reaches the binding is running a surface the canonical gate covers.

## Acceptance and evidence

- The committed fixture is byte-identical to what the comparison mode renders from the currently built artifact, and every committed byte came from a capture run rather than an edit.
- The comparison mode is proven to discriminate: it fails against the stale committed fixture as it stands today, and passes on the regenerated one — a red run before regeneration and a green control after, with the regeneration in between.
- Rendering twice from the same artifact produces identical bytes, so the comparison cannot fail for ordering or formatting reasons alone.
- The comparison writes nothing: running it leaves the working tree unchanged whether it passes or fails.
- Continuous integration runs the comparison after the browser artifact is built, and a difference fails that job rather than being reported and ignored.
- The capture's source registration passes no compile-profile key, and the regenerated surfaces are equivalent to what the same sources produce through the current host.
- The consuming guards keep loading the committed fixture. Their behavioural assertions are unchanged and still fail against a planted regression; only an expectation the regenerated capture made untrue may be restated, and each such restatement is recorded with the fact that changed.

## Deletions, budgets, and aborts

- Delete the dead compile-profile key from the capture's source registration and the stale committed fixture bytes it produced. Delete no fixture source, no captured surface, no schema field, and no consuming guard.
- Planning guidance: roughly 300 authored LOC across 4 files in 2 related packages, excluding the regenerated fixture data, which is captured output rather than authored lines. These figures are guidance, not a cap; rescope only under the program's mandatory thresholds or when a consuming guard or the capture tool's request shape enters.
- Abort on a hand-edited fixture byte, on a comparison that writes the file it is comparing, on an advisory or skippable invocation, on a renderer whose output differs between the writing and comparison paths, or on migrating the capture tool's compile calls here.

## Verification and review

Regenerate the fixture from the built artifact and commit it, run the comparison red against the stale bytes and green against the regenerated ones, run the playground guards that consume the fixture, and run `targeted-domain`. Apply `public-3`; add only CCA1O3E's ledger row.
