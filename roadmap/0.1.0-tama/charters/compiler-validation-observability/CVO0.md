# CVO0 — Probe outcome taxonomy and probe-state manifest contract

Readiness comes only from trusted implementation-ledger rows. A READY node may start; tooling does not validate commit locators, Git identity, receipts, leases, external state, or runtime admission.

## Independently acceptable outcome

One shared typed contract for validation and probe results. The current owner is **generic pass/fail collapse in comparison and workload tooling** ("empty output", "null response", "failed"). The final and sole owner is **typed probe outcome taxonomy with causal ordering plus the machine-readable probe-state manifest**. This charter accepts one contract boundary; it contains no independently dispatchable subblocks and no compiler semantic changes.

## Concrete surfaces and APIs

- Production surfaces: none; this is a test/CI/tooling-only train.
- Named API/data boundaries: the test-only workspace crate `crates/verter_validation_probe` (not a member of any production dependency graph) with modules `outcome` (`ProbeOutcomeClass`; the precedence fold `ProbeOutcomeClass::terminal(dimension: Dimension, observed: &[ProbeOutcomeClass]) -> Result<Terminal, InvalidObservation>` (dimension-aware: an observed class outside the dimension's admissible set is an `InvalidObservation`) where `Terminal` is the closed enum `Terminal::Class { class, secondary: Vec<ProbeOutcomeClass>, evidence: Vec<Evidence> }` (the single terminal class, the retained secondary classes, and typed evidence `Evidence { source: addon_diagnostic | parser | semantic_builder | comparator | driver | reference, message }` so a runner-generated parser or semantic-builder message, a comparator `DiffReason`, or a driver error is stored with its origin rather than lost) `| Terminal::NotRun { blocked_by: ProbeOutcomeClass }` (a dimension never reached because a lower one failed, see propagation below) `| Terminal::NotApplicable { reason: comparator_absent | runtime_executor_absent | map_validator_absent }` (a dimension that cannot be exercised for this framework at all, admissible only where the validated manifest's `applicability` declares it: `comparator_absent` at `Structural` under `comparison = none`, `runtime_executor_absent` at `Runtime` and `map_validator_absent` at `Map` under `applicability.runtime = inapplicable` / `applicability.map = inapplicable` — every such dimension must be an owned `skip` cell citing the framework product authority, and a driver reporting inapplicability for a dimension the manifest declares applicable is a failure of that dimension (`reference_failure` at `Structural`), never `NotApplicable`, so a missing producer, executor, or validator can never fail open; it evaluates to `Evaluation::NotApplicable` for a `canary`/`known-fail` cell, to `Skipped` for a `skip` cell, and to `GateRegression` for a `gate` cell — every gate terminal other than the exact expected class, `NotRun` and `NotApplicable` included, is `GateRegression` — and the summary counts it separately from both skips and `NotRun`) and `InvalidObservation` names the impossible observed combination), `manifest` (`ProbeStateManifest { framework, comparison: Comparison, comparator: Option<ComparatorIdentity { crate, path, function, atom }> (required exactly when `comparison = structural`, forbidden otherwise, and equal to the catalog identity), applicability: { runtime: applicable | inapplicable, map: applicable | inapplicable } (today `inapplicable` for both frameworks: no runtime executor and no map validator are bound; a later owning node flips a flag together with binding the surface in the authority catalog), external_revision: Sha40, strata: Vec<Stratum { id, pattern, min_cases }>, inventory: Vec<Case { case_id, digest: Option<Sha256> }>, entries: Vec<ProbeEntry> }` — `external_revision` is the full pinned corpus commit, `strata` the reviewed representative families with their minimum coverage, `inventory` the complete ratified case list (with a content digest per case where the corpus is generated rather than committed), all validated by `ProbeStateManifest::validate` and consumed verbatim by CVO1/CVO1S; where `Comparison` is the closed enum `structural | none`, one value per framework manifest file; `structural` is admitted by `validate-probe-authorities.mjs` only when the catalog row for that framework's product authority carries a `comparator`, and the manifest's own `comparator` header field must equal that identity verbatim (a missing, unknown, or substituted comparator is rejected, one fixture each); today only `vue` qualifies, and in a `none` manifest every `Structural` cell must be `skip`; `ProbeEntry { probe_id, framework, case, dimension: Dimension,` — `probe_id` identifies a case (`<framework>/<relative-path-in-corpus>`), and the canonical cell identity is `{ probe_id, dimension }`, unique per manifest and the key every totality and deduplication check (summary, join) uses, so one dimension's cell can never mask a sibling's omission — `ProbeEntry { ..., expected_state, expected_class, authority: Authority, atom, reason, external_revision }` with the per-cell `Dimension` enum `{ Route, Compile, Structural, Runtime, Map, Performance }`, `ProbeStateManifest::validate`; manifests are serialized as TOML at `crates/verter_validation_probe/manifest/<framework>.toml`, one file per framework, the only manifest input any validator reads), `authority` (the closed id enum `Authority`; it carries no framework or dimension logic), `evaluate` (`ProbeEntry::evaluate(&self, observation: &CaseObservation) -> Evaluation`, reading only `observation.terminals[self.dimension]`, with the closed enum `Evaluation { GatePass, GateRegression, CanaryExpected, ObservedPass, CanaryRegression, KnownFailExpected, Xpass, UnrelatedRegression, Skipped, NotRun, NotApplicable }`, the only place an expectation meets an observation), and the rejection fixtures in the crate's single integration-test binary `tests/main.rs`, cases under `tests/cases/contract.rs`. Authority citations never carry roadmap identifiers (repository rule “No roadmap archaeology in source or tests”): code and test artifacts cite a durable capability id from the closed enum `Authority` — `compiler.public-request-route`, `vue.runtime-client-product`, `svelte.runtime-client-product`, `compiler.equivalent-work-ledger`, `compiler.physical-execution`, `native.memory-audit-snapshot` — ids only. Which framework and which outcome dimensions an authority covers, and which of its acceptance atoms authorize a probe, live solely in roadmap-owned data: `roadmap/0.1.0-tama/catalogs/validation-authorities.toml` with one `[[authority]]` row per id carrying `node`, `framework` (`vue`, `svelte`, or `any`), `dimensions`, an optional `comparator: { crate, path, function, atom }` naming the exact structural comparator that authority supplies (today exactly one row carries it — `vue.runtime-client-product`: `verter_vue_conformance`, `src/compare.rs`, `compare_modules`, atom `product-identity` — and `svelte.runtime-client-product` carries none), and `atoms`, a list of `{ id, charter_atom, dimensions, outcomes }` entries where `dimensions` and `outcomes` are the cells and terminal classes that atom may authorize (e.g. `route-callable`: `Route`/`pass`; `typed-refusal`: `Route`/`request_refused`), where `id` is a durable, capability-local name (lower-case kebab, e.g. `route-callable`, `typed-refusal`, `product-identity`, `equivalent-work-ledger`) and `charter_atom` is the roadmap-side mapping to the owning charter's acceptance atom (`"<section heading>/<bullet ordinal>"` for charters without acceptance IDs, or the acceptance ID itself). A citation in any executable artifact is `{ authority, atom }` with `atom` the durable `id` only; node-shaped or acceptance-ID-shaped atom values (anything matching `[A-Z]+[0-9]+[A-Z0-9]*(-AC[0-9]+)?` or a section path) are rejected by the validator, so roadmap identifiers never enter code or test artifacts. The roadmap tool `roadmap/0.1.0-tama/tools/validate-probe-authorities.mjs --manifest crates/verter_validation_probe/manifest --join crates/verter_validation_probe/join [--observations <file|dir>]` (a directory is walked for `*/observations.json`, each file validated separately, and the directory form has its own test; run in the `Tama Roadmap` CI step, wired in `.github/workflows/ci.yml`, and in the probe workflow after every lane run) validates every citation against that catalog, the owning charter's text, and the implementation ledger. Successor nodes plug the runner, corpus adapters, controls, and join validator into this crate; none of them re-declares these types.

## Source-specific scope

- **Intent:** every comparison and workload tool reports one of a closed set of actionable outcome classes instead of a generic failure state, and every externally exercised probe/cell is described by one machine-readable manifest with an explicit expected state.
- **Problem:** generic failure states hide whether the compiler, the harness/transport, the product shape, the comparator, or the runtime/map comparison failed, and they let known future gaps either block CI or silently pass.
- **Solution and architecture decisions:**
  - minimum outcome classes: `pass`, `verter_diagnostic`, `product_not_produced`, `product_malformed`, `semantic_mismatch`, `runtime_mismatch`, `source_map_mismatch`, `reference_failure`, `harness_failure`, `host_failure`, `unsupported`, `request_refused`, `timeout`, `crash`; `request_refused` (the public route returned a typed refusal of the request's shape, framework, or binding before compiling) and `host_failure` (the host or session failed for a cause it names before compiling — registration, session state — as opposed to the harness failing to drive it) are the two extensions this contract makes to the brief's minimum set, each a distinct public-boundary outcome that is neither a harness defect nor a compiler diagnostic, and the set is otherwise extensible only for a genuinely distinct actionable class, never by alias or tool-specific variant;
  - causal ordering when multiple states are present is total and deterministic: exactly one class is the outcome, the highest-precedence class present, and every lower class observed in the same run is recorded as secondary evidence, never as the outcome. Precedence, highest first: `harness_failure` (the harness could not execute or observe the case: addon load, driver protocol, spawn, or observation failure — never a typed refusal the route returned), `crash` (the compiler process died by signal or abnormal exit), `timeout` (the compiler process was stopped by the deadline), `host_failure` (the host or session failed for a named cause before compiling), `request_refused` (the route refused the request's shape, framework, or binding before compiling), `unsupported` (the compiler explicitly declared the input outside its contract), `verter_diagnostic` (the compiler reported an error diagnostic), `reference_failure` (the reference side of a comparison could not be produced or executed), `product_not_produced` (compilation ended without a diagnostic and without a product), `product_malformed` (a product exists but fails its own validity check), `semantic_mismatch` (structural/semantic comparison differs), `runtime_mismatch` (runtime comparison differs), `source_map_mismatch` (map comparison differs; a runtime mismatch outranks a map mismatch because a wrong program makes its map moot), `pass`. A diagnostic observed together with product absence is a valid combination, not an impossible one: `verter_diagnostic` is the terminal and `product_not_produced` is retained as secondary evidence, so a compile diagnostic is never downgraded to `product_not_produced` because no product followed it. Impossible combinations are rejected rather than resolved: `pass` observed together with any failure class in the same dimension; a `crash`, `timeout`, or `harness_failure` never satisfies an expected `verter_diagnostic` or `unsupported` (an expected refusal is met only by the refusal class itself); a comparison class is never reported for a case whose product or reference is absent;
  - expected states: `gate` (failure blocks; a gate names its exact expected terminal class, and the one admission rule is that this class is listed in the `outcomes` of the cited atom for the cell's `dimension` — `pass`, a refusal class for a required negative contract, or, once an implemented framework product authority lists them, `verter_diagnostic`/`unsupported` at `Compile` after CVO4 promotion — so a gate can only ever assert what its authority actually owns (a `Route` gate may expect `pass` via `route-callable` or `request_refused` via `typed-refusal`; `unsupported` and `verter_diagnostic` are `Compile` outcomes owned by the framework product authority and cannot gate `Route`), and `GatePass` is produced only by that exact class, so a required refusal is neither hidden as `pass` nor demoted to a canary, while a `timeout`, `crash`, or `harness_failure` observed against an expected-refusal gate is `GateRegression`; admitted only when the entry cites an authority whose owning node is `implemented` and whose catalog row covers the entry's `dimension` and `framework` through the cited atom — so a gate can never be created by external output, by test tooling, or by an unimplemented contract), `canary` (non-blocking, and always owned: every canary cites the `{ authority, atom }` that will own the behavior, exactly as `known-fail` does, and an uncited canary is rejected; its `expected_class` is either a failure class — the known failure, where an unrelated class such as crash/timeout/harness failure is a new regression — or `pass`, the explicitly non-gating observed-pass state for a cell that currently passes but whose authority is not yet implemented; a `canary(expected_class = pass)` evaluates to `ObservedPass`, never `GatePass`, so a pass implies nothing about acceptance, and a later failure of that cell evaluates to `CanaryRegression`, so the regression is visible without any promotion having happened; a committed manifest never contains a classless canary — `ProbeStateManifest::validate` rejects one outright, so no wildcard entry can absorb class changes; bootstrap discovery is a separate, non-accepting step: the feature-gated `propose` run of the probe crate executes the selection and writes `target/validation-probe/proposed-manifest.toml` with the exact classes it observed, which a person reviews and commits as owned `canary`/`known-fail`/`gate` entries), `known-fail` (canary citing the authority that will own the behavior; an unexpected pass is XPASS/promotion candidate, not an automatic gate), `skip` (only when execution is meaningless/impossible/unstable; requires the owning authority and a reason; prefer canary over skip). The owning node behind each authority is recorded in the roadmap catalog, never in the manifest;
  - observation does not imply acceptance: a manifest entry records evidence about Verter behavior and never derives semantics from external fixture output;
  - the contract is framework-neutral: every manifest entry and every summary row carries `framework` (`vue` or `svelte`; both are first-class Verter targets) as a case attribute, so one taxonomy, one manifest schema, and one summary format serve every corpus the train's nodes pin;
  - class/dimension admissibility is a closed matrix, dimension by outcome, checked by `ProbeStateManifest::validate` and by the terminal fold: `Route` admits only `pass`, `harness_failure`, `crash`, `timeout`, `host_failure`, `request_refused` (whether the route answered, and how the process behaved — never what the compiler said); `Compile` admits the `Route` set plus `unsupported`, `verter_diagnostic`, `product_not_produced`, `product_malformed` (a well-formed response or typed failure carrying a compiler diagnostic or an unsupported-product refusal is `Route = pass` with its real failure at `Compile`, so route acceptance never depends on compiler semantics); `Structural` admits the `Compile` set plus `reference_failure`, `semantic_mismatch`; `Runtime` admits the `Compile` set plus `runtime_mismatch`; `Map` admits the `Compile` set plus `source_map_mismatch`; `Performance` admits only `pass`, `harness_failure`, `crash`, `timeout`. Every other pair is unrepresentable, in two distinct ways: a direct observation outside the matrix (for example `semantic_mismatch` reported at `Route`) is `Err(InvalidObservation)` from the fold — one planted fixture — while only a valid lower-dimension failure propagated into an unreachable higher dimension yields `NotRun`; as an `expected_class` an out-of-matrix pair is rejected;
  - observations are per dimension, never case-wide: the runner produces one `CaseObservation { case_id, terminals: BTreeMap<Dimension, Terminal> }` per case, folding the classes observed at each dimension with `ProbeOutcomeClass::terminal`. Propagation is one-way: a failure at a lower dimension (`harness_failure`, `crash`, `timeout`, `host_failure`, `request_refused` at `Route`; `unsupported`, `verter_diagnostic`, `product_not_produced`, `product_malformed` at `Compile`) is copied into every higher dimension of that case where the matrix admits that class; where it does not (for example `request_refused` or `product_malformed` at `Performance`), the higher dimension records `Terminal::NotRun { blocked_by: <lower class> }` — a distinct representation, not an outcome class — which `ProbeEntry::evaluate` maps to `Evaluation::NotRun` (never `GatePass`, `CanaryExpected`, or `Xpass`) and the summary counts separately from skips. Admissibility therefore applies to observed classes only, and a case that never reached a dimension can neither pass it nor be rejected by the manifest validator. A failure at a higher dimension (a `semantic_mismatch` at `Structural`, a `runtime_mismatch`, a `source_map_mismatch`) never touches a lower one, and an independently observed failure at a higher dimension wins that dimension over any class propagated into it from below — a propagated class is a default for an unreached cell, not an observation — so `Compile = verter_diagnostic` followed by a reference death yields `Structural = reference_failure` while `Compile` keeps its diagnostic. A manifest cell is evaluated against its own dimension's terminal only, so a `Route` gate cannot regress because a structural comparison differed, and a cited authority is never asked to cover a dimension it does not own.

## Acceptance IDs and discriminating proof

Preflight evidence selection: preserve all four acceptance outcomes below, then select the smallest evidence set that actually discriminates the touched contract. Existing behavioral coverage, compiler/type/capability enforcement, static validation, canonical gates, bounded inspection, and benchmarks are valid when accompanied by a terse rationale.

- **CVO0-AC1 — sole-owner outcome:** the contract must structurally reject generic terminal failure states and alias proliferation; no tool-specific outcome variant may bypass the taxonomy (`ProbeOutcomeClass` is a closed enum; there is no string-typed outcome). Planted-invalid proof is required, not optional: `ProbeStateManifest::validate` must reject at least (a) a generic `failed`/`error` alias offered as an outcome class, (b) a `known-fail` or `skip` entry with no owner, (c) an invalid state/class combination (`gate` with an expected class its cited atom does not list for that dimension — the planted case is a `Route` gate expecting `unsupported`; `known-fail` with `expected_class = pass`, which would suppress XPASS), plus an uncited `canary` of any kind, and (c2) a `canary` with no `expected_class` in a committed manifest (rejected on every run, not only the second), (d) a `canary` with an expected failure class and no `{ authority, atom }` citation, (e) an `expected_class` outside the admissible set for the cell's `dimension`, and, as a positive fixture, (f) a `CaseObservation` with `Route = pass` and `Structural = semantic_mismatch` evaluates a `Route` gate to `GatePass` and a `Structural` canary to `CanaryExpected`, `ProbeOutcomeClass::terminal` must return `Err(InvalidObservation)` for the impossible observed combinations named above (`pass` together with a failure class in the same dimension; a comparison class together with an absent product or reference), and must fold a diagnostic together with product absence to `verter_diagnostic` with `product_not_produced` retained as secondary, and `ProbeEntry::evaluate` must return `UnrelatedRegression` (canary/known-fail) or `GateRegression` (gate), never `CanaryExpected`/`KnownFailExpected`/`GatePass`, for a `crash`, `timeout`, or `harness_failure` terminal against an expected `verter_diagnostic` or `unsupported`; (g) as a planted negative, a gate expecting `unsupported` that observes `timeout` evaluates to `GateRegression`; (h) as a planted transition, a `canary(expected_class = pass)` cell evaluates `ObservedPass` on a passing observation and `CanaryRegression` on the next failing one, with no `GatePass` anywhere in the sequence. One fixture per rejection; no permutations.
- **CVO0-AC2 — positive contract:** ordering rules are total and deterministic for every combination, and every manifest entry validates (stable id, expected state, expected outcome class where applicable, a `dimension`, and an `{ authority, atom }` citation for every gate, known-fail, skip and expected-class canary entry, pinned external revision where applicable); `validate-probe-authorities.mjs --manifest crates/verter_validation_probe/manifest` passes on the manifests and refuses each of its six planted negatives.
- **CVO0-AC3 — incremental equivalence:** not applicable; the contract owns no incremental, cache, cancellation, or publication authority.
- **CVO0-AC4 — bounded work:** not applicable; the contract owns no hot path.
- Every proposed new test must name a plausible regression or contract boundary not already discriminated. Do not add implementation mirrors, duplicate permutations, or universal negative/mutation tests.

## Trusted implementation ledger

Before squashing or review, the implementation patch transitions this node's predeclared row in `authority/state/implemented.toml` from `status = "pending"` to `status = "implemented"` with the planned squash commit message, approximate date with timezone, and optional pull-request number. The transitioned row is the implementation fact. Commit metadata is a loose locator only and is never resolved or validated against Git or GitHub. Reviewers inspect the squashed candidate patch without SHA-, tree-, ancestry-, receipt-, lease-, or digest-bound orchestration manifests.

## Reconciled source-plan contract

**Intent:** one shared, typed, causally ordered outcome contract plus a probe-state manifest so external execution can be observed without implying acceptance.

**Problem:** generic failure states cannot distinguish compiler, harness, product, comparator, runtime, or source-map failures, and CI cannot execute known future gaps without either blocking or silently green-ing.

**Solution and architecture decisions:**

- closed minimum taxonomy with an explicit extension rule (genuinely distinct actionable class only);
- causal ordering rules that preserve diagnosis precedence;
- machine-readable manifest with stable probe ids, expected states (`gate`, `canary`, `known-fail`, `skip`), expected outcome classes, durable authority citations (node ownership lives in the roadmap catalog), terse reasons, and pinned external revisions;
- XPASS surfacing and unrelated-class regression detection for canary/known-fail entries;
- every skip carries an owning authority and reason; a gate needs an implemented authority covering its framework and dimension; canary preferred over skip whenever partial execution yields evidence.

**Required predecessors:** `CCA0` compiler capability contract and `CCA1O1` host adapter boundary. The harness may observe unfinished compiler work truthfully; compiler capability and performance promotion retain their own later gates.

**Normative source decomposition:**

1. **CVO0-A — Outcome taxonomy.** The class set, meanings, and the extension rule.
2. **CVO0-B — Ordering rules.** Causal precedence, diagnostic-vs-product distinction, timeout/refusal rule.
3. **CVO0-C — Manifest schema and crate.** The `verter_validation_probe` crate skeleton, entry fields, stable ids, `validate` constraints, the `Authority` enum, and the rejection fixtures.
3b. **CVO0-C2 — Authority catalog and validator.** `catalogs/validation-authorities.toml` (framework, dimensions and atoms per authority), `tools/validate-probe-authorities.mjs` with its six negatives, and the `Tama Roadmap` CI wiring.
4. **CVO0-D — Expected-state semantics.** gate/canary/known-fail/skip rules, XPASS, unrelated-class regression, owner requirement.
5. **CVO0-E — Independent review.** Challenge class sufficiency, ordering totality, and manifest completeness before any lane is built on it.

**Acceptance:** no generic failure state can hide a more specific outcome; known future failures can execute without blocking required CI; unexpected passes and unexpected new failure classes are surfaced; every deferred/skip state has an explicit future owner; no compiler semantic change is required.

**Forbidden:** deriving semantics or expected output from external fixtures, tool-specific outcome variants, automatic promotion, skip entries without owners.

**Deletion/abort:** no production deletion; abort if satisfying the contract would require repairing compiler behavior — record the failure against its owning future node instead.

## Early observation boundary

The taxonomy and non-gating workload observations run against the accepted request constitution and typed schema before the successor compiler rewrite. CMP0, CPER0, VCP7 and SCP7 retain their later semantic/performance promotion authority. Advancing observation grants no permission to treat an unimplemented semantic product as a passing gate.
