# D12 — Async, generator, and await return wrapping

Readiness comes only from trusted implementation-ledger rows. A READY node may start; tooling does not validate commit locators, Git identity, receipts, leases, external state, or runtime admission.

## Independently acceptable outcome

The sole shared flow authority wraps a function's return by its kind and unwraps `await`: an `async` function or arrow publishes `Promise<join>`, a generator publishes `Generator<yield, return, next>`, an async generator publishes `AsyncGenerator<…>`, and `await x` over a call or non-call operand publishes the awaited value through the awaited-type relation — closing the `await x` half of RESIDUAL-NON-CALL-ANY-FABRICATION (the debt record's `U6.ASYNC_GENERATOR` + `U6.CALL_RESOLVE` half). An operand the substrate cannot type keeps a typed gap and never warms. One independently acceptable outcome; no subblocks.

## Concrete surfaces and APIs

- Production surfaces: `crates/verter_session/src` (`project_semantic_dispatch/flow_return.rs`, `flow_return_products.rs`, `flow_slice_content.rs`); `crates/verter_semantic/src/analysis/flow` for the function-kind fact if the skeleton does not carry it.
- Named boundaries: the lib environment for the `Promise`, `Generator`, `AsyncGenerator` wrapper heads through the shared `Instantiate` family; the two awaited relations as first-class query families — `AwaitedNormalize` (`await x`, async-generator iteration parameters, an authored `Awaited<T>`) and `AsyncReturnPayload` (the `X` of an async function's `Promise<X>`) — whose deferred answer over an open binder is the compiler-native `IntrinsicApplication(Awaited)` node; `FlowReturnResult`; the corpus row `X18_async_return`.
- Mutation boundary: only those surfaces and their test homes.

## Acceptance IDs and discriminating proof

- **D12-AC1 — sole-owner outcome:** wrapping goes through the shared lib instantiation of the wrapper head; unwrapping goes through the two awaited query families, each the sole owner of its relation, which follow the checker's awaited-type protocol (lib `Promise` identity, declaration carriers, structural thenables); an open binder defers to the compiler-native `Awaited` intrinsic application, never an instantiation of the lib alias; no per-kind resolver and no recognition by spelling.
- **D12-AC2 — positive contract:** the four canaries and `X18` publish the checker's answer; an unresolvable lib keeps the typed gap (one negative leg).
- **D12-AC3 — incremental equivalence:** wrapped results admit warm and replay equal to fresh; gapped results never warm.
- **D12-AC4 — bounded work:** one wrapper-head instantiation per wrapped return, and one awaited-relation build per unwrap level (`awaited_normalize_count` / `async_return_payload_count`; `return await asyncSrc()` over `Promise<number>` measures 2 cold); identical warm demand adds zero builds.
