# ARH1 evidence cases

The sole owning interface is `node tests/architecture-health/ARH1/verify.mjs` (verify) plus `node --test tests/architecture-health/ARH1/arh1.test.mjs` (dirty twins), wired into `test:scripts` and into the dedicated CI `architecture-health` lane (gated on `tests/architecture-health/**` and `crates/**`, so a product/verifier-only edit or any Rust dependency/surface change runs the guard; no Git history is required). The verifier joins the shipped ARH0 predecessor products (`../ARH0/products/responsibility-map.json`, `../ARH0/products/debt-register.json`) and the live tree only; the program DAG is database-owned by the TAMA controller, so owner/heir ids are checked structurally (dotted lowercase train ids, uppercase node ids) and no DAG copy is read from this tree.

## ARH1-ratification (accept)

Clean products validate: the five ARH0 god-module candidates each carry exactly one hotspot contract, the declared import direction equals the production import tree measured from the live source (comments stripped; cfg(test) and cfg(all(test, ..)) items stripped so test configuration never counts as production direction; nested `use` groups expanded with prefix inheritance so brace-list items never classify as roots and local `macro_rules!` re-exports name file locals; use statements AND inline crate paths in code position — macro paths like `verter_audit::attribute!`, derive paths, feature-gated aliases, `crate::module::Item` paths naming their crate-internal root exactly like use statements — measured on string-blanked text with turbofish, primitive and tool-lint namespaces excluded; verter, external and crate-internal roots compared two-way), the layer rules equal the live crate Cargo manifests both ways with a pinned population, constructor anchors bind real declarations and the constructor table equals the primary type's derived Self-returning public constructors (an emptied table over live constructors is drift), every authority row binds a cohesive module of the same responsibility, the recorded snapshot counts equal the live-derived file-wide counts, every satisfied cutover debt is a real ARH1-owned ARH0 debt, retained/narrowed surface items bind real declarations with the module boundary pinned to the derived parent declaration, state rows name live identifiers with one sole owner that DECLARES the state in comment-stripped code, narrowing rows carry exact consumer inventories (fn rows by qualified reference forms, field rows by type-qualified field use), every hotspot's importer list equals the derived cross-crate population, and every declared route has exactly one cutover disposition carried by a row bound to exactly one recognized key.

Historical source titles and ISO dates are optional descriptive context. Tests exercise the verifier without commit metadata and run its CLI with Git history unavailable. Code, manifest and behavioral obligations remain enforced.

## ARH1-ratification (reject)

- `manifest-case-drift`: the manifest records a case the verifier does not implement, drops one it does, or lists a case without disposition reject and the `clean products` accept twin (dirty twins add `ARH1-phantom` and drop `ARH1-split`).
- `manifest-product-drift`: a carried product schema missing from the manifest's products list, or a recorded product no file carries.
- `manifest-command-drift`: the manifest verify/test command is not the canonical command string derived from the verifier's own location (dirty twin points verify at `scripts/affected-tests.mjs` — an existing script that is not the ARH1 verifier).
- `obligation-producer-malformed` / `obligation-without-text`: an AC4 producer obligation whose owner id is outside the structural discipline (dirty twin invents `doc2`) or that records no obligation text.
- `ac4-surface-uncovered`: a charter AC4 surface (`VIM/DX`, `host/profile`, `permissions`, `uncertainty`, `migration`) named by no producer obligation and no N/A rationale — the obligations and the rationale are rewritten keyword-free in the dirty twin (dirty twin rewrites every obligation and `ac4Rationale` to "dirty twin").

## ARH1-hotspot-coverage (reject) — AC1 join to the shipped ARH0 inventory

- `hotspot-without-contract` / `contract-without-inventory-row`: the contract population and the ARH0 god-module population are joined both directions (dirty twins delete the `flow_slice_content.rs` row and retarget `semantic_query.rs` at `semantic_query_memo/arena.rs`).
- `responsibility-dropped` / `responsibility-invented`: every ARH0 inventoried responsibility survives under exactly one authority, and no authority row claims a responsibility the inventory does not carry (dirty twins drop `batch coordination` and invent `typescript diagnostics formatting`).
- `authority-owner-unbound`: every authority row binds a cohesive module of the SAME responsibility — a single-module hotspot keeps authority in place (the hotspot file itself). An existing but unrelated file is not authority (dirty twin re-points `pool submission and admission control` at `crates/verter_span/src/lib.rs`), a cohesive module of a different responsibility is not authority (dirty twin re-points `batch coordination` at `cancellation.rs`), and deleting a cohesive row while the authority still names it fails too (dirty twin drops the `driver.rs` row).
- `duplicate-hotspot-contract`: exactly one contract per inventoried hotspot — appending an exact copy of the scheduler hotspot contract (dirty twin does exactly that) would let two contracts claim every inventoried responsibility and is rejected.
- `authority-double-claimed`, `missing-authority-owner`, `missing-hotspot`: structural discipline of the authority map.

## ARH1-import-direction (reject) — AC1 boundary binding

- `import-drift`: the declared verter/external/crate-internal sets must equal the production import tree of the live source — a declared-but-unmeasured import (dirty twin adds `verter_semantic` to the scheduler file), a measured-but-undeclared one (dirty twin undeclares `verter_language`), an undeclared live crate-internal root (dirty twins undeclare `dag` and the production inline root `pool`, whose `crate::pool::SchedulerCpuPool` constructor-parameter references have no use statement), a declared root only test configuration imports (dirty twin re-declares `scheduler`, the crate-self path that only the scheduler's cfg(test) code references) and an inline-only crate reference (dirty twin undeclares `verter_audit`, which the scheduler production text references as `verter_audit::attribute!` with no use statement) all fail, as does a measured import with no dependency in the owning crate's manifest.
- Production measurement basis: a synthetic source with `#[cfg(test)] mod` using `crate::VerterHost`, `#[cfg(all(test, not(target_arch = "wasm32")))] mod` using `crate::pool` and `#[cfg(any(test, feature = "test-support"))] mod` using `crate::stage` measures exactly `{dag, stage}` production-internal while the full measurement still sees `VerterHost` and `pool` — the live `use crate::VerterHost` inside `project_semantic_dispatch/build.rs`'s cfg(test) module is therefore measured and must be (and is) excluded by the strip, never silently undeclared. Inline-path measurement: a synthetic `verter_session::spawn()` call with no use statement measures `verter_session` (so a forbidden root cannot hide outside use statements), and a synthetic `fn f() { crate::decl_lowering::run(); }` measures the crate-internal root `decl_lowering` (so a live production internal cannot hide outside use statements — `cache_id`, `request_context` and `pool` are production roots of the scheduler measured through exactly such inline paths) while string-literal path text, `u64::from` primitives, `collect::<Vec<_>>()` turbofish and `#[allow(clippy::..)]` tool-lint namespaces never classify as roots.
- `forbidden-import`: a must-not-import root that appears in the measured source, in use or inline form (dirty twin adds `verter_language` to the scheduler file's forbidden set while it is still imported).
- `layer-violation` / `layer-rule-contradiction` / `layer-allowance-without-dependency`: layer rules equal the live Cargo manifests BOTH ways — removing a real dependency from a rule's allowed set, inventing an allowance for a crate the manifest does not depend on (`verter_fake`, or a real crate like `verter_macro_dto` that is not this crate's dependency), forbidding one the crate depends on, or allowing and forbidding the same root (dirty twins mutate `ARH1-LAYER-1`).
- `missing-layer-rule` / `duplicate-layer-crate` / `layer-rule-population-drift` / `layer-crate-unexplained`: the rule population is pinned — every hotspot's owning crate is governed exactly once (deleting `ARH1-LAYER-1` uncovers `crates/verter_scheduler`), ids are exactly `ARH1-LAYER-1..n` (deleting the middle `ARH1-LAYER-2` leaves a gap), and a rule for a crate outside every hotspot (the semantic-core substrate `ARH1-LAYER-2`, or an invented `crates/verter_lsp` rule) needs a declared `nonHotspotRationale`.
- `missing-importer`: each declared importer exists; reference evidence is enforced by the exact population join below (comment mentions never count).

## ARH1-constructor (reject)

- `missing-constructor`: a declared constructor that is not a live `pub`/`pub(crate)` fn (dirty twin invents `with_semantic_engine`).
- `constructor-anchor-missing`: a capability anchor absent from the constructor's declaration span — the span stops at the next item-level fn, so the capability talks about the real signature, not the whole file (dirty twin anchors `new` on `Arc<Mutex<Vec<Byte>>>`).
- `constructor-population-drift`: for the module's primary type (the retained type named after the module — `Scheduler` for `scheduler.rs`), every pub associated fn returning `Self` that is not a narrowed test hook carries a capability row, and every row names such a fn — deleting the `new` row leaves a derived constructor uncaptioned (dirty twin deletes it), and emptying the whole table while keeping a rationale is rejected identically — the completeness derivation runs for empty tables, and a rationale is only legal when the derived population is empty (dirty twin replaces the four Scheduler rows with `[]` plus a rationale).
- `constructor-without-rules`, `constructor-rationale-missing`: every constructor carries rules; a constructor-free hotspot records why (dirty twin deletes the flow_return rationale). `test-hook-unmarked` keeps testOnly rows named as test hooks.

## ARH1-state-lifetimes (reject) — AC3 rationale's ownership map

- `bad-lifetime`: a lifetime outside the contract vocabulary {process, session, request, dispatch-transaction, content-version, snapshot-epoch} (dirty twin sets `Scheduler.overlay` to `forever`).
- `state-without-owner` / `state-owner-missing`: every state row names one sole owner, and the owner target (file or module directory) exists.
- `state-not-in-source`: some identifier token of the state must appear in the live hotspot source (dirty twin adds an `xyzzy_entanglement_ledger`).
- `state-owner-without-declaration`: the sole-owner target must itself DECLARE the state in comment-stripped code — every dotted field identifier of a `Type.field` state (or one non-enclosing token of a prose state, the parenthesized concrete identifier being the convention) must have a fn/item/macro/let/field declaration in the owner. An unrelated existing file is not ownership (dirty twin re-points `Scheduler.nodes` at `crates/verter_span/src/lib.rs`), and neither is a consumer that constructs the type (dirty twin re-points it at `host_construction.rs`, which constructs `Scheduler` but declares no `nodes` state) nor a file that only mentions the state in comments (dirty twin re-points it at `semantic_query.rs`).

## ARH1-surface (reject)

- `surface-declaration-drift` / `missing-surface-declaration` / `surface-declaration-unpinned`: the module visibility declaration is pinned verbatim against the DERIVED parent module file (`pub mod semantic_query;` in `lib.rs`, `pub(crate) mod flow_return;` in `project_semantic_dispatch/mod.rs`, …) — dirty twin rewrites it to `pub(crate) mod semantic_query;`, and clearing the list or pinning a non-parent declaration fails because the required binding is derived, not volunteered.
- `surface-boundary-drift`: a crate-visible module (`pub(crate) mod`) carries no cross-crate retained surface — retained fns/types/assoc items inside one contradict the boundary.
- `surface-item-missing`: retained fns/types and narrowed items must be live declarations (dirty twin retains `submit_everything`).
- `snapshot-count-drift`: the recorded snapshot equals the live-derived file-wide counts exactly (pub fn and its test-hook subset, pub(crate) fn, pub types, pub/pub(crate) mods, pub fields of fully-pub structs) in every key, both directions — a stale count (dirty twin resets the scheduler `pubFn` to the pre-merge 54), a zeroed value or a key stripped from the object are all drift.
- `surface-item-uncovered`: a fully public module without a bulk row must cover its complete pub-item population — every pub fn, pub type and (fully-pub-struct) pub field is retained, narrowed or constructor-captioned; deleting a row uncovers the item (dirty twins delete the `len` retained fn row and the `new` constructor row).
- `retained-item-unconsumed`: for `semantic_query` (flagged `crossCrateRetainedVerifiedByConsumers`) every retained type must be imported by a real cross-crate consumer — derived from use-statement and inline-path syntax, never substring or comment matches.
- `bad-narrow-target` / `missing-narrow-consumer`: narrowing targets only {`pub(crate)`, `test-configuration`, `feature-gated`} (dirty twin widens `tombstones` to `pub`), and every affected-consumer path exists.
- `narrow-hook-without-reference-forms` / `narrow-consumer-without-reference` / `narrow-consumer-omitted`: each test-hook narrowing row records the qualified reference forms its consumers use (`Scheduler::test_x`, `.test_x(` receiver calls); every recorded consumer must reference one of those forms in comment-stripped code, and every file outside the owning crate referencing those forms must be recorded — an existing file that references a different hook is not a consumer (dirty twin lists `host_construction.rs` under `test_new`), and omitting the live `host_batch_coordinator.rs` caller of `test_new` fails. Field narrowing rows join the same both ways on type-qualified field use: an ambiguous field name (declared by more than one struct repo-wide, like `tombstones` which `SessionOverlayRoot` also declares) counts only through a struct literal of the owning type, while an unambiguous name (like `generation_floors`) counts a bare `.field` receiver access too — a file hitting a same-named field of an unrelated type is never a false consumer (dirty twin lists `host_construction.rs` under `tombstones`).
- `importer-population-drift`: EVERY hotspot's declared importer list must equal the complete derived cross-crate population of the module (direct `verter_session::semantic_query` paths, aliased crate roots via `use verter_session as host;`, module imports with local refs; whole-segment matching so `flow_return_audit` never consumes `flow_return`) — dropping a real importer (dirty twins drop `verter_ffi/src/convert/typeinfo.rs` from `semantic_query` and `verter_napi/src/lib.rs` from the scheduler), adding a mirror-documentation mention that imports nothing (dirty twin adds `verter_audit/src/payloads/tags.rs`) and adding a comment-only "scheduler" mention (dirty twin adds `verter_audit/src/footprint.rs` to the scheduler importers) all fail; `crates/verter_lsp/src/external_ts_sync.rs` consumes `verter_scheduler::cancellation`, not the scheduler module, and is correctly absent.
- `narrowed-item-consumer-unrecorded`: every file importing at least one narrowed (unretained) name must be recorded on the bulk row's consumer migration — dirty twin drops `flow_literal_provenance.rs`, which imports `FlowGap`, `LiteralValue` and `SemanticNodeData` from the library (integration tests compile as separate crates).
- `assoc-item-unretained` / `assoc-item-missing`: assoc items used cross-crate on retained types must be retained — qualified `Type::member` references, receiver calls on typed bindings (`ResultCompleteness::Partial(reasons)` pattern bindings, `x: &PartialReasonSet` ascriptions) and receiver calls within a line window of a qualified reference (the `if x.is_empty() { T::PROPAGATED } else { x }.iter()` chain in `component_meta.rs`) all count, so retaining a type does not retain its methods; dirty twins unlist `PartialReasonSet::PROPAGATED` (qualified use), `PartialReasonSet::is_empty` and `PartialReasonSet::iter` (receiver use by `verter_ffi`'s `component_meta.rs`), and a listed item that is not a declared pub member fails. Members are matched against pub members declared on retained types, so a same-named method on `String`/`Vec` (like `to_string().contains(..)`) never manufactures an obligation.

## ARH1-split (reject) — ARH1-AC2 discriminator

- `split-retains-shared-state`: a cohesive module claiming state with mode `shared` — moving methods into files while retaining unrestricted shared state does not satisfy a responsibility boundary (dirty twin gives `flow_products.rs` a shared claim on the flow-return compute frame).
- `state-double-owner`: two modules claiming the same state `sole` (dirty twin has `flow_return_products.rs` claim the mutable product state that `flow_products.rs` owns — the sole-claim must also match the state row's declared sole owner).
- `state-ownership-undeclared`: a claim on a state the hotspot never declared (dirty twin: `Scheduler.secret_vibes` on `dag.rs`).
- `cohesive-responsibility-invented` / `missing-cohesive-module` / `split-rationale-missing`: cohesive responsibilities come from the ARH0 inventory, modules exist, and a hotspot without cohesive modules records why.

## ARH1-cutover (reject) — AC1 route ownership

- `arh0-debt-undecided`: ARH0 debt rows naming ARH1 as decision owner must be satisfied here (dirty twin drops the `packages/core` decision row bound to `ARH0-DEBT-1`).
- `duplicate-satisfies`: one ARH0 debt decision per register — a fresh-id copy of the `packages/core` row with owner `ARH11` and the opposite decision still fails (dirty twin does exactly that).
- `cutover-debt-unknown` / `cutover-debt-foreign`: a `satisfies` value must be a real row of the shipped ARH0 debt register whose decision owner is ARH1 — the register can neither invent a debt (dirty twin satisfies `ARH0-DEBT-FAKE`) nor take another owner's route (dirty twin satisfies `ARH0-DEBT-4`, which ARH0 assigns to ARH2).
- `cutover-route-missing`: routes are keyed `(candidatePath, narrow kind)`; every narrowing kind a hotspot declares (field vs fn vs bulk) needs exactly one register row binding it to the executing heir — deleting `ARH1-CUT-2` (field narrowing) fails while its sibling `ARH1-CUT-3` (fn narrowing) stays on the same file, and dropping `ARH1-CUT-4` uncovers the `semantic_query.rs` bulk route.
- `duplicate-cutover-route`: two register rows carrying the same route key (dirty twin copies `ARH1-CUT-4` under a fresh id with a second disposition).
- `cutover-row-unbound` / `cutover-row-double-keyed`: every disposition binds EXACTLY ONE recognized key — a narrowing route or a satisfied ARH0 debt. A fresh-id copy of `ARH1-CUT-2` with owner `ARH11`, the opposite decision and neither key set cannot ride outside the uniqueness checks (dirty twin does exactly that), and a row carrying both keys is equally rejected.
- `cutover-route-invented`: a register row whose route key matches no declared narrowing kind.
- `cutover-without-decision` / `cutover-without-disposition` / `missing-candidate-path` / `deletion-rationale-missing`: structural discipline of the register.
