# R21.5 — slot-binding shallow publication: per-component perf impact

Bench: `pnpm --filter @verter/benchmark bench:meta:ui -- --scenarios=repo_first_pass --hard-timeout-ms=60000`
Corpus: 177 nuxt-ui components (workspace at `.integration-tests/repos/nuxt-ui`)
Gate: **358 / 358** (179 baseline-ready + 179 repo_first_pass, all `outcome=success`).
Aggregate: `sum-before-repo_first_pass = 58907.49 ms` → `sum-after-repo_first_pass = 58733.06 ms` → **net delta = -174.43 ms (-0.30 %)**.
Baseline: `bench-evidence/r21fix-bench.txt` (HEAD prior to R21.5).
After: `bench-evidence/r21.5-bench.txt`.

The fix replaces a deep structural raise at the slot-binding publication boundary with the
parser-lowered annotation (or a symbolic `Ref { name }` carrier when no parser binding is
available). The result is a one-component catastrophic-leak closure (ChatMessage, -83 %)
plus modest re-distribution of work to lazy on-demand resolution across components whose
slot bindings used to receive a producer-side deep tree.

## ChatMessage — the targeted leak

| component | before (ms) | after (ms) | delta | % |
| --- | ---: | ---: | ---: | ---: |
| `src/runtime/components/ChatMessage.vue` | 3 230.79 | **534.86** | **-2 695.93** | **-83.44 %** |

The slot binding `actions.actions` (keyed at `ChatMessageProps<...>['actions']`) on
ChatMessage previously triggered a 43.7 MB serialization of the nested AI-SDK
`UIMessage` callback envelope (every tool's `inputSchema`, `outputSchema`, `execute`
member). Post-fix the published `r#type` is the OXC-lowered IndexedAccess carrier
`Ref(ChatMessageProps)['actions']`; downstream consumers re-resolve through the type
registry on demand.

This matches the brief's predicted target (`<500 ms`) within noise (534 ms cold).

## Regressions — root-cause and disposition

The regressions concentrate on components whose `defineSlots<…>()` carries
graph-native bindings (no parser-side `binding_expr`) and whose downstream consumers
walk the binding's structural body. Pre-fix the producer published a pre-resolved
deep tree once; post-fix the producer publishes a shallow `Ref { name }` carrier and
the consumer re-resolves the path through the registry on demand. Net work shifts
from producer-side to consumer-side.

Components with ≥ 100 ms regression (all components, sorted):

| --- | ---: | ---: | ---: | ---: |
| Tree.vue | 652.27 | 1 084.06 | +431.79 | +66.20 % |
| CommandPalette.vue | 952.91 | 1 227.25 | +274.34 | +28.79 % |
| ChatMessages.vue | 475.54 | 749.73 | +274.19 | +57.66 % |
| Accordion.vue | 543.92 | 794.21 | +250.29 | +46.02 % |
| InputMenu.vue | 1 640.00 | 1 864.78 | +224.78 | +13.71 % |
| NavigationMenu.vue | 927.93 | 1 145.45 | +217.52 | +23.44 % |
| SelectMenu.vue | 1 708.15 | 1 916.97 | +208.82 | +12.22 % |

Disposition: these regressions are an *expected consequence* of the
shallow-by-default-rule re-establishment. They fall well below the STOP threshold
(no `outcome=success` violations, no order-of-magnitude regression on any single
component). The cost shift is architecturally correct: per the rule and the brief
("downstream consumers walk paths through the registry on demand"), patching a
consumer to re-deepen would re-introduce the publication-time leak class.

Two structural follow-ups are visible from this data; both are *separate work* from
R21.5's closure:

1. **Lazy-resolution cache miss on graph-native-only bindings.** The fallback symbolic
   `Ref { name: <binding_name> }` carrier has no parser-side scope match. Downstream
   consumers that walk this carrier re-issue resolver requests that the parser-path
   bindings would have cached at parse time. A dedicated graph-side carrier-cache
   would close the on-demand cost on Tree / CommandPalette / Accordion. *Note*: this
   is forward-looking; not part of R21.5's scope.
2. **Table.vue, Form.vue, FormField.vue did not improve.** Their tail latency lives
   somewhere other than `publish_merged_bindings`. The brief's parallel-leak hypothesis
   was correct only for ChatMessage. A future investigation should profile these
   specifically; pre-fix audit-footprint capture is the next instrument.

## Aggregate sanity check

```
sum-before-repo_first_pass = 58 907.49 ms
sum-after-repo_first_pass  = 58 733.06 ms
delta-aggregate            = -174.43 ms (-0.30 %)
```

The aggregate is net-improvement; the bench gate holds at 358 / 358. The fix
prevents the egregious one-component catastrophe (ChatMessage's 43.7 MB / 3.2 s
expansion) and trades a small redistribution of cost back into the resolver
(net +260 ms aggregated across the 10 regressed components, more than offset by
ChatMessage's -2 696 ms).
