## Path-Precise Navigation And Projection Contract

`keyof` reads `null` and `undefined` as complete empty key sets. A union
with an empty arm key set has no shared keys; a nullish branch erased by
the project's union policy contributes no arm.

Path projection is the default shape of every semantic query. Whole-surface expansion is a degenerate case of projecting the empty path; single-hop `ProjectMember` / `IndexedAccess` are sugar for `ProjectPath` with length 1.

- **Path queries are first-class semantic queries.** `SemanticQueryKey::ProjectPath { base, path, context }` is the canonical form (`context` is a `ProjectionReductionContext { mode, demand, provenance, merge_role, vue_heritage_policy }` — `provenance`, `merge_role`, and the content-free Vue heritage policy are folded into `FamilyKey` for every context-bearing projection-reduction family; the terminal projection mode rides on `context.mode`).
- **Materialize only subpaths needed for the requested path.** Sibling members and unrelated branches are not touched.
- **Mode cascades along the path.** Intermediate hops run in `Navigate`; only the terminal hop runs in the caller's requested mode (`Shallow`, `Expanded`, or `Identity`).
- **Indexed operands stay structural.** Authored lowering, deferred evaluation and locator projection use `StructuralTransit(Navigate)` for a published indexed access's object. `keyof` reads the source's key domain without expanding its values. Generic arguments remain structural carriers until the instantiated body demands them, including residual carrier normalization.
- **Argument demand and reuse.** Alias applications instantiate their live argument applications through the continuation runtime; recursive arguments in interface/class positions retain their deferred back-edges. Mapped arguments remain carriers until selected. Indexed arguments retain their authored expression during projection. A genuine alias source demand reads the selected value with Navigate through the shared evaluator; named results canonicalize to their defining scope, while other results keep the authored argument in the Instantiate recipe. A conditional consumes its indexed check and substitutes that demanded value into its winner. Conditional check projection uses Navigate with the caller's demand: branch selection reads the check type without expanding its member values. When a conditional consumes an indexed operand for comparison, its value demand preserves union alternatives that a shallow apparent surface would merge. Prior memo population never rewrites a dormant argument. Resolved declaration arguments share their defining scope only when file options, environment hashes and project identities agree; local scopes remain distinct. Normalization origins retain the reference-site carriers. Query reads retain their ordinary receipts, dependency validation and publication fences.
- **Selected results retain their demand.** The shared deferred evaluator memoizes shell, selected-value, mapped-member-value, mapped-member-interior, mapped-signature-slot, mapped-helper-head, mapped-index-value, mapped-index-interior and mapped-source demands separately with the full reduction context and receipt-backed dependency proof. Selected unions evaluate their value arms; object, array, tuple and declared-signature interiors are visited only for Expanded publication. Navigate leaves interiors addressable. Rebuilding an object rewrites the authoritative entry stream and derives its member index from that stream; changing the positive-member index alone is not a value rewrite. Selected publication preserves named object and interface applications and a named `keyof` carrier, while a key-domain demand enumerates its keys. A closed conditional alias reached in a substituted call result (including through alias wrappers) re-enters the shared Instantiate and Conditional queries; genuinely open applications retain their carriers. Its declaration-body classification runs inside the deferred evaluation frame so the memo retains that dependency proof. A partial call-return evaluation keeps its authored operand and suppresses admission. Whole-surface and selected mapped members share the mapped-member-value demand with the caller's full publication context and its own memo identity. Expanded whole-member and finite-index publication reduce declared-signature slots under the mapped-signature-slot demand. A named slot helper first reduces to its value head under the mapped-helper-head demand, preserving signature slots through unions and deferred operators. A signature-bearing head retains its named application; finite non-callable helpers and inline operators reduce. Recursive back-edges remain addressable, including mutually recursive signatures and references whose type arguments grow. Head composition inspection charges connected work and retains typed partiality. Object interiors remain addressable under mapped-member-value and mapped-helper-head demands. Transparent arrays and tuples reduce their values under mapped-member-value. Entering an array, tuple or object interior uses its own demand and memo identity, reducing finite helpers while retaining recursive back-edges; root mapped-value demands can still resolve scoped recursive helper references. Signature slots reduce inline object, array and tuple structure while retaining named callable carriers and recursive back-edges; helper-head demand leaves container interiors dormant. A finite non-callable helper head resumes signature-slot evaluation so its container interiors reduce. Under Expanded publication a mapped member helper with an object, array or tuple head uses the shared Expanded instantiator before its interior is visited, so the closed operators it holds read their members as a published Expanded answer does (`Boxed<WideSource['b']>` publishes `{ boxed: number }`) and its recursive back-edges stay declaration-owned where Navigate leaves ordinary applications; signature heads keep their narrower demand. Incomplete helper heads retain their carrier without starting that expansion. Mapped-source demand resolves a closed source and its key domain without visiting member interiors. Shell evaluation dispatches its mapped carrier directly through the query boundary, retaining carrier-normalization dependency and suppression evidence. Helper aliases and scoped recursive-reference applications follow ordinary Instantiate queries at Navigate; named interface/class carriers remain addressable. The same continuation retains cycle/work bounds and typed completeness, availability and cache-suppression evidence; incomplete evaluation never starts a second forcing route. Signature utilities retain named returned declarations and array/tuple element carriers; a subsequent projection owns their expansion. The expanded terminal of a nonempty path resolves declaration carriers in every selected union arm. Pending substitutions use binder-aware reachability, including an `InferRef` carrying the target infer declaration's binder identity.
- **Expanded object slot interiors.** Selected-value evaluation visits the authoritative object entry stream: member values, call and construct signatures, and index-signature keys and values. Rebuilding replaces those operands in the same stream before deriving lookup indexes, preserving metadata and overload order. The enclosing demand still controls whether an object interior is visited; helper-head and mapped-member carrier boundaries stay intact.
- **Finite mapped index batches.** A finite string index over a computed, unremapped map proves all selected keys belong to the domain once, then uses one path walker to materialize the selected values. A validated source view and its ordinal index supply both modifier and selected source-value evidence; exact `source[K]` occurrences use that member read before binder substitution. Source domains enumerate their indexed headers without constructing a published `keyof` union. Each value uses one typed mapped-index evaluation through the ordinary continuation and conditional authority, retaining publication context, optionality, origin edges, dependency proof and cost receipts. Once execution starts, partiality or an execution abort terminates the batch with its reason and authored indexed carrier; it cannot trigger per-key retries. This demand may instantiate alias value helpers and evaluate their selected composition; ordinary call-return selection retains those applications. Shell, selected-value and mapped-index-value memos are demand-specific. Open domains, remaps, identity maps and homomorphic non-object sources retain the ordinary walker path.
- **Prepared member receiver and declaration identity.** A selected source member binds its callable's polymorphic `this` to the original source receiver before substitution, through the shared callable receiver binder. Selected evaluation retains interface/class applications until the caller's terminal projection demands their surface; Navigate preserves their names and type arguments.
- **Intersection contribution rule.** When projecting a path through `A & B`, only arms that contribute to the next path segment are projected; non-contributing arms are ignored for that path (not rewritten to `never`). If multiple arms contribute, the projected results of the contributing arms are intersected. Zero contributors is a projection miss.
- **Union contribution rule.** Every union member must contribute to the path; if any member fails the path, the union projection is a union-wide miss.
- **Conditional path rule.**
  - **Boolean distribution.** A naked type-parameter conditional enumerates `boolean` as `true` and `false`, including a `boolean` member of a union or a resolved alias. The shared conditional distributor splits the members, rebinds each branch's distribution parameter and combines results through the canonical union reducer; the graph's ordinary `boolean` representation and `VerterStableV1` ordering stay unchanged. For a distributive check, an incomplete `extends` operand cannot use a written-arm proof to select a whole-boolean branch, including through an alias. Non-distributive boolean checks retain their readable-arm proof. Wrapped checks keep `boolean` whole. Pinned by `distributive_conditionals_split_boolean_and_boolean_union_members` and `a_written_arm_cannot_select_a_whole_distributive_boolean`, under all four compiler settings.
  - **Indexed check demand.** A conditional whose indexed check or extends operand is generic retains the authored check until substitution. Projecting an unbound mapped binder such as `S[K]` can produce a miss and erase the binder; only closed operands enter the receipt-backed indexed-value demand before branch selection.
  - **Lowering and instantiation forcing.** Reducing authored lowering consults `conditional_branch_selection` after the check and extends operands, then lowers only a decided winner. Open branches still enter `SemanticQueryKey::Conditional`; lowering and materialized queries share `build.rs`'s union distributor and winner commit path (infer substitutions, origin edges, counters, and roots). This replaces eager branch lowering, including losing-branch nested dispatches. The declaration's parameterized neutral shape remains a lower-once artifact.
  - **Pending positional substitutions.** Substitution rewrites a conditional's check and extends and retains its branch handles with a sealed ordered `(parameter node, argument node)` frame per branch. It never selects a branch. The frame is part of conditional node/query/family identity and contains no syntax, environment maps, source hashes, or projection context. Exact infer declarations shield the extends and true branch; check and false branch retain their outer scope. The deferred evaluator discharges only the selected branch, replacing unconditional four-subtree substitution. Explicit open-branch projection discharges its frames before visiting children; structural display reads the same ordered substitutions without graph mutation or relation dispatch. Frame arguments participate in structural reachability and producer roots, and selected work never inherits the losing branch's roots. When the substituted parameter is a distributive conditional's check — the declaration node itself, or an `infer` declaration whose check is an `InferRef` carrying its binder — the frame records it as the distribution parameter, so each distributed member rebinds it in both branches: a conditional nested in a branch of `E extends …` sees that member, never the whole union an outer `infer E` bound.
  - **Template construction.** Substitution builds a template literal whose every hole becomes a literal, `null`, `undefined`, `boolean`, `never` or a union of those through `TemplateLiteralReduce`, as the checker's instantiation (`getTemplateLiteralType`) folds those holes into its text and maps over a union hole; a hole still generic keeps the template, whose literal, `null` and `undefined` holes fold into its text all the same (`folded_literal_holes`, also applied when a projection rebuilds a template), so `${infer H}${D}${infer T}` with `D := "."` is the pattern `${infer H}.${infer T}`.
  - **Recursion spread into a tuple.** A tuple with a variadic element (a rest element not written as an array) is never a deferred position: the checker resolves every element to normalize it, so `[...R<Rest>, H]` instantiates `R<Rest>` as a nested instantiation, bounded by the connected instantiation budget (TS2589 resource partial, never kept), instead of minting its recursive back-edge. Under Navigate an application in a tuple rest slot over closed arguments is instantiated too, so the tuple splices and its positions and length are known; under Shallow the rest-slot application stays its carrier, a declared alias exactly as a builtin utility (a tuple value already settled still splices), and a Shallow demand that reads the shape goes through an indexed access, whose operand projects under Navigate; Skeleton keeps every application a carrier, and Expanded evaluates it. Every other carrier-mode application stays a carrier. The projection memo keys that rest-slot reading apart from the plain one (`ProjectionSlot::Spread` in `ViewMemo`), so one application written both spread and plain answers the same in either order.
  - **Suspended branch display.** Read-only display applies the ordered frame as a structural view. It may retain equivalent redundant composite members (`string | string`); canonical reduction occurs when the branch is materialized through the existing substitution authority. Fresh/incremental display parity, precedence, binder scope, and existing display limits still apply.
  - **Closed/decidable conditional** (check resolves deterministically under the current substitution environment): reduce immediately, select the winning branch, continue projecting the remaining path through the selected branch only. Emit `ConditionalSelect` origin.
  - **Open/undecidable conditional** (check depends on free type parameters or unresolved inference): keep the conditional shell and distribute the remaining path **into both branches**, producing a conditional whose branches are per-branch projections. Do NOT short-circuit to an opaque symbolic node as the default behaviour.
  - **Genuine-`Expanded` distribution scope.** A QUERY-ROOT unbound conditional under genuine `Expanded` demand distributes into both branches at the empty-path expander (guard: `root_conditional_still_distributes`). A nested-position open conditional has no reachable genuine-`Expanded` route today — the empty-path expander walks top-level composition only, and the open-mapped carrier-stop owns the mapped-value entrance; the desired carrier behaviour for a future genuine-`Expanded` nested route is pinned by the ignored tracker `nested_open_conditional_not_distributed_under_expanded` (follow-up: genuine-expanded-nested-conditional-carrier).
- **Free type variables are binder-aware summaries.** Whether a conditional's operands hold a free type parameter (`type_params_within`, the permissive/restrictive tests, `type_is_generic`'s argument check) is read from one summary per node (`conditional_decision::FreeTypeVariables`): the type parameters written below it that no generic signature within declares over that position, and whether an `infer` reference or declaration sits below. The declaration flag is consumed according to operand position: generic in a check, an inference site in an extends pattern. A node's summary is composed once from its children's and kept on the dispatcher for its lifetime (one request) — node ids are append-only and the dispatcher asks only about nodes it keeps rooted, whose payloads do not change while it holds them, so a kept summary does not go stale (a released node reads as the shared placeholder and is never asked about again). A tail run that wraps its argument once per step therefore costs one new summary per step, never a walk of the whole argument (`growing_tail_run_work_per_step_stays_flat`); the binder scoping is pinned by the `n1`–`n8` rows of `conditionals_are_deferred_and_decided_as_the_checker_decides_them`. The summaries are request state with the rest of the dispatcher's request state: a semantic task the dispatcher lends the state to starts from the summaries the request already composed, and what its drive composes (on whatever thread resumes it) returns to the lender when the task is returned or reclaimed (`semantic_task_tests::a_semantic_task_inherits_and_returns_the_free_type_variable_summaries`), so a wrapper after a task reuses the summaries below it instead of recomposing them.
- **Infer variables in nested checks remain generic.** An infer declaration substituted into a conditional check is an unbound variable, including a required tuple position. The same declaration in an `extends` pattern is an inference site. The genericness walk carries that position through alias applications and operator operands; a conditional over the variable is a complete deferred type, not an unavailable comparison. This keeps the unused `PropMethod` arm of Vue's `PropConstructor` from making the enclosing inference partial.
- **A distributed member classifies its operands from caches.** Each member of a distributive conditional is decided as its own conditional over the same `extends` operand, so nothing a member reads of that operand may walk it. `type_is_generic` answers `false` in either operand position from a node's kept free-variable summary when it holds no type parameter, no `infer` reference and no `infer` declaration (every node its walk could reach is a structural descendant, a nested conditional's check is read in check position whatever the outer position, and the walk answers generic only at one of those three); a summary that was not kept (a cycle) still walks. The `infer` inventory (`infer_inventory`, which routes `conditional_infer_route`) is kept per pattern node on the relation transaction beside the pattern cache, and a childless payload holds no declaration below it. The resolved union a named `extends` operand stands for is reduced once per operation ([relation-ownership](relation-ownership.md), composite fixed points). The lattice-extreme probe (`conditional_operand_extreme`) does not rescan a union this operation's membership index already proved literal-only. A literal member against an `extends` operand that is a union of literals alone (`is_literal_only_union`, read once per distribution from the operands' shapes, never from an index an earlier read built) is decided in place (`decides_member_in_place`), as a syntax-lowered member always is, rather than as a `Conditional` query of its own: its decision reads only the two operands (the relation is a membership lookup) and binds the selected branch by structural substitution, which evaluates nothing, so no query it reaches can re-enter it; it runs under `nested_decision_query` as a query the running decision reaches would. Before it runs it is charged and refused exactly as the member's cold query would be (`enter_in_place_query`: the nested connected demand, the entry's work unit and query level, and the cold build's request-budget operation), so a budgeted request answers and refuses the same either way (`in_place_members_answer_and_refuse_as_member_queries_under_a_request_budget`). Every other member keeps its own query. Guard: `a_declared_exclude_reads_a_derived_union_once_per_distribution` (operand walk visits, composite arm reads and membership reads stay linear in the union width, through a declared value type and through a named alias the host resolves).
- **Tail runs stop by certificate or budget, never by repetition alone.** A generic conditional whose selected branch applies its own declaration again is the next step of one tail run (`drain_instantiate`). The run is a CERTIFIED divergence — the complete TS2589 recovery (`RecoveryBasis::Certified`), kept under the run's read set — only with the dispatcher's `ExactSteps` witness (no step read a partial or a result its memo would not keep; for an `Awaited` claim on an enclosing build, every frame since that build's) and one proof: the arguments come round again (`CertifiedDivergence::exact_recurrence`), or the run grows uniformly (`CertifiedDivergence::uniform_growth`: the check is the bare parameter, `E` is closed and `infer`-free, the recursive branch wraps that parameter in a tuple without rest elements, an array or an object type and passes every other parameter through, and the permissive/restrictive tests decide that branch for every instantiation of the wrapper). Anything else — a same-path re-entry, growth the tests leave undecided (`Acc["length"]`, a spread), a step through a partial — continues under Verter's tail budget and ends as the budget's TS2589, a resource partial never kept.
- **Local library recurrence remains evaluable without a certificate.** The library `Awaited` walk continues an uncertified local recurrence under its existing tail/work allowances. Repeated synchronous carrier transitions additionally enter the existing instantiation-depth rail, so declining the proof cannot create unbounded native recursion. Active membership records each node once until its owning run exits. An unfinished cross-query producer has no executable transition to consume: without an exact witness that dependency remains a non-cacheable same-path partial. The direct library-walk seam tests incomplete caller observations, cyclic budget recovery and finite values.
- **Barrier rule.** Undecidability is the barrier, not the existence of a conditional. An `infer` binding is not itself a barrier; if the enclosing conditional's check is decidable with the current substitution environment, the navigator reduces the conditional and binds `infer` via the relation engine. Only when the check stays open does the conditional form a barrier.
- **Coarse symbolic stop is retired as the default.** The old "open-generic symbolic stop" (`Applied { identity, args }` returned when args are open at depth > 0) is retired for path projection and expansion. Symbolic-stop-style fallback survives only as a **budget-exceeded failure**, signalled explicitly via `BudgetExceededFailure`, never as the main semantic path for open generics.

Concrete expectations:

- Navigating `A['c']['full']['bar']` through an object surface touches at most three projection nodes plus the terminal; no unrelated siblings materialize.
- Projecting `OtherType<string>['a']['foo']` through `type OtherType<T> = { a: Foo, b: T } & (T extends string ? S : N)` touches `Foo['foo']` and `S['a']['foo']`; `N` is never walked. `b` is not touched because `'a'` is the requested segment.
- Navigating `OtherType['a']['foo']` with `T` open distributes `['a']['foo']` into both conditional branches, intersects their contributions, and leaves `b` untouched.

## Operands A Decision Relates

Conditional syntax lowering and graph-native view projection share
`conditional_operand_context`: both relation operands use `Navigate` mode (or
`Skeleton` for a skeleton demand), preserving declaration identity and type
arguments for the shared relation authority. The check retains the caller's
value demand so an unread indexed carrier cannot prove a reflexive relation.
The extends pattern uses structural transit, so its nested mapped operators
do not publish members while a decision reads its inputs. The selected branch
retains the caller's publication context. Eagerly
expanding an operand into its object body would bypass
same-generic variance: `Cell<'a'> extends Cell<string>` is false for
`interface Cell<in out T> { get(): T }`, despite the covariant member surface.
Annotations already flow from the retained syntax through `NarrowTypeParam` to
prepared declarations; `relation_variance` reads them before measuring any
unannotated parameters. `authored_variance_annotations_decide_same_generic_relations`
checks named publication and warm reuse for interfaces, classes and aliases in
all four strictness settings. Flow-return probes alone do not exercise the
publication lowering context.

Transparent alias applications normalize independently on both sides before
same-generic argument comparison. Target unions and intersections retain a
declaration source until each arm is related; a source that itself names a
composition keeps the ordinary source-distribution order. Structural targets
continue to compare member shapes, and discriminant fallback reads the source
structure after ordinary target-arm comparisons. Selected indexed references
and recursive declaration carriers retain their identity through composition.
Within an inference session, fixed annotated arguments are checked before
candidate collection; other arguments keep the ordinary inference path and
unannotated parameters keep their existing variance computation. A failed fixed
argument still respects structural fallback for the whole declaration: an
unreliable or unmeasurable unannotated parameter, or a covariant `void` target
argument, can permit the structural comparison even when an annotated slot
alone would reject it. Inferred and concrete rest-parameter targets exercise
the same fallback.
Named-publication tests cover these paths
and unannotated covariance, contravariance, bivariance, independent parameters
and unmeasurable-variance fallback, including warm reuse.

A conditional is decided by relating its operands as the checker relates them; a decision is only as exact as the operands' shapes. The rules below keep the operand shapes a branch selection reads checker-faithful.

- **Generic signature identity keeps deferred returns.** Contextual inference collects from parameters first, then from uninferred return positions. Two deferred conditional returns infer through corresponding checks, extends operands and branches, so an unused binder can align without replacing inference for generic signatures whose parameters differ. The shared `Identity` relation compares their `extends` operands semantically, resolving declaration carriers at every descent. Object member order, union/intersection member order, tuple labels and parameter names do not decide inequality; readonly, optionality and member types do. Optional member types include implicit `undefined` unless exact-optional policy preserves their authored types. Heritage bodies use the shared complete one-level surface; authored intersections retain their composite identity. Callable identity uses the signature kernel's exact positional, receiver, binder and result comparison; deferred conditional results compare their semantic operands and substituted branches. Sub-relations retain the relation transaction's binding barrier, SCC discharge, budget and freshness receipts. The canonical algebra keeps its conservative construction comparator; its `Distinct` is not semantic inequality for an unread deferred shape. A default constraint that is a union of closed types retains the conditional target's complete negative verdict. In the permissive test, a conditional with a wildcard check or `extends` operand is the wildcard itself, after error absorption and before generic deferral. Thus `Eq<{ a: 1 }, { a: 1 }>` is `true`, different closed arguments are `false`, and free outer arguments retain the conditional.
- **An `any` check against a tuple infers before combining branches.** A tuple infer pattern uses the shared relation's fixed bindings, including `unknown` for a site with no candidate and its declared constraint when needed. The conditional combines its inferred true branch with its false branch under the project's nullability policy: `any extends [infer A] ? A : 0` is `unknown`, while wrapping the inference yields `[unknown] | 0`. A nullish false branch disappears beside a non-nullish true branch when strict null checking is off. Bare `any extends infer A` still binds `any` and takes only the true branch; an open generic check stays deferred. Other `any`/infer pattern shapes retain their existing unavailable result: a naked inference site in a union needs different candidates from a tuple element.
- **The permissive wildcard is a known internal value.** Its `QueryErrorDisposition::PermissiveWildcard` is distinct from a failed query, so a complete conditional reduction to it remains an exact internal fact. It has its own lattice extreme and retains the existing absorbing operator rules; real errors take precedence. Partial observations and real faults stay unavailable, and an error-channel wildcard still fails rather than acquiring public TypeScript syntax. `a_permissive_wildcard_is_an_exact_internal_operand` pins those fact-boundary controls.

- **Accessor pairs are one property.** An interface or type-literal `get value(): T` / `set value(v: S)` pair lowers with its accessor kind (`verter_type_expr_oxc::interface_method_kind`, used by the type-expression lowerer, the shallow declaration lowerer and the member headers), never as two methods. A relation and an inference read the pair as ONE property of the getter's type (the setter's parameter type only when there is no getter), so `Ref<number> extends ShallowRef<infer V, unknown>` infers `number` and a reference whose setter-only argument differs (`Acc<number, number>` against `Acc<number, unknown>`) relates by the getter. A setter read as a method with no return type made every such relation undecided.
- **Weak targets reject on every object route.** The weak-type check (`isWeakType` + `hasCommonProperties`) runs on the whole target before a structural comparison, including the record-shaped object shortcut (`try_object_vs_record_relation`), never on one intersection arm: `{ a: 1 } extends { [RawSymbol]?: true }` is false. It reads a declaration source's structural surface even while the constituent relations retain that source's declaration identity for variance. Skipping it there selected Vue's `UnwrapRefSimple` raw branch for every plain object.
- **Package augmentations merge into the module they resolve to.** In a module file, a `declare module "<package>"` block augments the module FILE its specifier resolves to from the augmenting file (`fact_augments_resolved_module`; the `ResolvedRelativeCanonical` index target covers package and relative specifiers). A script's package declaration instead declares an ambient module of that name; relative matching retains its existing behavior. Vue's `RefUnwrapBailTypes`, declared empty by reactivity and augmented by runtime-core and runtime-dom through `declare module "@vue/reactivity"`, therefore holds both bail members, so `VNode` bails out of ref unwrapping. The resolver-free index invalidation treats every module-naming fact as a possible contributor to every resolved-file entry (over-invalidation is correctness-safe).
- **Indexed operands relate as their member's type.** A relation settles an indexed-access operand at `Navigate` (`unwrap_identity_carrier_for_relation`), and the deferred evaluator reads an indexed member at `Navigate` under every structural-transit `Shallow` demand (`indexed_read_mode`), so an alias over one (`type Core = Bag["core"]`) instantiates to the member's type. A `Shallow` projected-path terminal is a one-level publication surface: for a union member (`Local | { $: number }`) that is the empty object its arms share, which every object satisfies — the relation then took `{ a: 1 } extends Bag["core"]` as true.
- **An access of a type parameter is generic and relates through its constraint.** In the permissive test an access of the wildcard, or by it, is the wildcard (`getIndexedAccessType` over `wildcardType`): substitution folds `W["a"]` to `W`, so `{ a: T["a"] } extends { a: number }` is not definitely false. Outside an inference session a relation reads `T["a"]` (and `T["a"]["b"]`) as its constraint, `getConstraintOfIndexedAccess`: the same access of `T`'s constraint, `unknown` when `T` declares none, so the restrictive test (constraints dropped) fails for `{ a: number }` and the conditional stays deferred, as the checker defers it; it holds for `{ a: unknown }`, and for `{ a: {} }` without `strictNullChecks`, where the constrained relation then decides the true branch. The constraint is read only against a target that is no indexed access, deferred shell or type parameter (a union holding the access itself takes it), and a computed index of a constrained parameter stays undecided. The carrier unwrap keeps an access of a type parameter that the deferred evaluator reads as a miss as the operand it is, never the miss.
- **A written union arm proves the true branch.** When normalizing the whole `extends` operand cannot finish (an arm the lane cannot read), a check that neither absorbs nor distributes — proven positively: the type it completely names (an alias or an instantiation read through, so `Id<any>` is `any`) is a non-extreme primitive, a literal, an object, an array or a signature, or the check names an interface or a class; a union, an intersection (`1 & Id<any>` is `any`), an indexed access, a `keyof`, a conditional, a template, a tuple or a name not read completely is never proven plain — over operands with no type parameter and an `extends` inferring nothing, still takes the true branch when its complete relation to ONE written arm of the union `extends` holds (`true_through_written_arm`; `someTypeRelatedToType`): no other arm can take that branch away. The unused normalized operands contribute only their reuse evidence. The false branch is never proven so — it needs every arm. Vue's `UnwrapRefSimple<number>` decides through its `Builtin` arm although its bail arm holds `DomType<Node | Window>`. A check that absorbs or distributes is decided by its lattice row or member by member, never as a whole related to one arm: relating `Two<"a">` (`"a" | "z"`) whole published `{ v: "z" | "a" }` where the checker distributes to `{ v: "a" } | { v: "z" }`, an `any` alias took the true branch alone, and so did `Id<any>` and `1 & Id<any>` when only the extremes visible without resolving an instantiation were rejected; such a conditional stays unavailable while an arm is unreadable.
- **Composite inference collects candidates before fixation.** An active inference session visits every matching union target constituent rather than stopping at its first successful relation. Losing alternatives roll their deposits back. The sole naked variable of an intersection receives the existing `NakedTypeVariable` priority (`MatchedUnionRemainder`); direct candidates outrank it. Thus a callable return of `string` outranks a constructor return inferred through `T & {}` as `String`, independently of canonical constituent order. Bare and imported reference heads use the shared carrier resolver before structural relation, including inside mapped property checks.
- **Complete versus unavailable.** An operand the lane cannot read (a standard-library type with no registered library, such as `Date` or `DomType<Node | Window>`'s `typeof globalThis`) leaves its relation unknown, and the conditional stays unavailable — never a selected branch, never a Complete deferred conditional. A complete symbolic conditional (a check over a type parameter the checker defers on) is an exact answer and stays distinct from that unavailable reduction.

### Accessor property reads and mappings

Member and indexed reads use `KnownKeyAccessor::read_value` through the shared
path walker, including instantiated interfaces and classes. Mapped types read
that property value rather than copying the stored accessor signature. A
getter-only key preserves `readonly`; a key with a setter is mutable unless
the mapping explicitly changes the modifier. Builtin `Pick` and `Omit` publish
one property for the selected getter/setter pair. Key enumeration and mappings
that do not read the source value do not force the getter's inferred return.

Class `accessor` fields contribute property headers and lazy property bodies on
their instance or static surface. Their read type is the annotation, otherwise
the widened initializer, otherwise the implicit type a property declaration
without either has (`any`, or the typed missing-member marker where the checker
reads constructor or static-block flow); normal visibility rules apply. The
initializer is typed exactly as a mutable property definition's is, through the
one `ClassField` view (`analysis::class_field_value`): a function value is a
served class-member position, and a call-derived or `this`-reading initializer
reads its synthetic `C:field:x` / `C:static:x` value declaration. Accessor
grouping keys on the property spelling, so `get 1` / `set "1"` is one mutable
property; `Pick` and `Omit` select that pair by its `keyof` key, the key of its
first declaration (`AccessorSelectionKeys`), and the collapsed property retains
that key even when the getter comes later. Under heritage shadowing the own
member's form wins: the heritage merge (`MergedMemberAccum`) takes the
shadowing own-body contributors' method kind, so an own property over an
inherited getter maps mutable and an own getter over an inherited property
maps `readonly`.
Selective instance-member lowering includes these fields, so `keyof`, member
reads and indexed reads agree. `accessor_property_tests` covers these rules,
mapped modifiers, generic reads, and ordinary-method/call-signature controls;
the semantic lowering and accessor-decorator tests cover the producer and
typeinfo publication boundaries. Reducing an indexed reference retained inside
a composite answer belongs to the shared projection/evaluation demand rules
above; accessor reads do not add a separate recursive expansion route.

## Tail calls through forwarding aliases

Only a declaration whose own body is a conditional may follow a forwarding chain. Ordinary alias instantiation keeps its existing cycle carriers and one-hop work; eligibility is checked lazily when a result names a different declaration.

A conditional tail call can return through aliases whose bodies only apply another declaration to their own bare type parameters. The tail recognizer follows those declared forwarding applications, substituting parameters by ordinal, and uses the existing exact-step and uniform-growth proofs for the original conditional. It never evaluates another conditional or descends through a constructor while recognizing the forwarding chain. Repeated declarations and cancellation stop recognition; unsupported bodies retain ordinary evaluation and its instantiation budget. This lets a growing conditional recover through an alias without spending the full budget on freshly minted applications.
