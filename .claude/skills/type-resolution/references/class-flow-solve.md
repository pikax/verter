**Inline class-evaluation effects.** A class DECLARATION evaluates its `extends` value and then its static elements at its statement, and the checker flows what they do into the enclosing frame (measured on 7.0.2, all four strictness settings): a write retypes every later read (`class C extends (x = true, B) { static { x = 1; } }` leaves `x` as `number` — heritage first, static blocks in source order), an entered `asserts` call narrows, and a static block completes like an inlined block — its normal completions continue the statement, and when none exists the code after the class is unreachable, its reads seeing the declared type (`x = 1; class C { static { throw 0; } } return x` is `string | number`). Static property initializers and computed keys sit in the member's own control-flow container: a write there never retypes an enclosing binding.

One predicate owns which positions run inline: `verter_semantic::analysis::flow::inline_class_evaluation`. The flow skeleton (`SkeletonBuilder::visit_statement`) records exactly those positions as the frame's footprint — the `extends` value as a root expression site, each static block as a `Block` region — and the slice content (`flow_slice_content.rs`, the class-declaration statement) lowers exactly those: the `extends` value's effects through `lower_effect_statement` (a discarded value's writes and entered calls), each static block through `lower_region` as a `SliceStatement::Block` whose completion composes into the region. So the writes carry skeleton definitions, the evaluator applies them in evaluation order, and the proof's obligations are the ones the content discharges. Supported shape: no decorators; an `extends` value that is effect-free or a sequence / assignment; effect-free computed keys and static initializers; static blocks that declare nothing, read no `this` / `super` / `new.target`, and create no function or class. Anything else keeps its class subtree out of the skeleton, and the content's `LeafCallScanner` gives the statement the typed `GuardNarrowing` gap — never Complete. A class EXPRESSION's static block always takes that gap.

Each effect runs once. A local class declaration read as a value (`lower_local_class_declaration` → `lower_class_expression`) whose inline positions already ran at the statement neither re-applies its `extends` effects — `lower_evaluated_heritage` keeps only the value (a sequence's last operand, an `=` assignment's right-hand side; a value that would still run an effect is the typed unmodelled expression) — nor re-scans its class-evaluation positions. `suffix_return_of` answers a class whose inline static block holds a `throw` as `Undecided`, never as a statement that completes normally.

Evidence: `class_evaluation_flow_tests` (`project_semantic_dispatch_tests`) — the measured rows publish Complete with the checker's answers, the unsupported rows (a receiver-reading static block, a class expression, a `for (x of …)` head write the frame does not apply directly either) stay partial, the heritage write applies once when the class value is constructed later, and warm and edited reads equal a fresh computation.
