- **Unique-symbol declaration identity** — `ValueTypeAnnotationFact::is_unique_symbol` preserves an authored declaration annotation, and `ValueTypeAnnotationFact::unique_symbol_members` records the statically-named MEMBERS whose authored annotations are `unique symbol` (class statics; object-type-literal annotation members). Do not replace this with primitive `symbol`, a string spelling, or a consumer-local import alias.
- **Unique-symbol TYPE-position carrier preservation** — `unique symbol` widens to the bare `symbol` primitive, which is interned ONCE per graph, so the nominal identity must remain on the nominal terminal until the relation reads it. `ProjectSemanticDispatch::build_typeof` is the SOLE ROOT mint site: the `TypeOf` query answers a `unique symbol` DECLARATION ROOT with a `TypeOfNominal` carrier built from the prepared facts it already read, and every other `typeof` keeps its resolved value type verbatim. The DECLARING identity is recovered by `relation_nominal_identity`, so aliases, imports, re-exports, and namespace-qualified references (which resolve their own joined `Ns.NAME` root through the same query) retain one identity. A MEMBER-qualified `typeof` (`typeof C.K`, `typeof CONFIG.K`) whose declaring value records the member in `unique_symbol_members` resolves to the member's OWN `TypeOfNominal` carrier through the ONE shared member rail `member_nominal_typeof` (which chases the class heritage chain so an inherited static names its DECLARING base); a member with no nominal fact projects and widens to the shared `symbol`. There is no post-projection promotion anywhere. A consumer needing the inhabited primitive asks the widen helper (which interns `symbol` directly), never re-asks the typeof key.

  **The carrier's HEAD is the AUTHORED reference; the identity rides the PAYLOAD.** `intern_nominal_typeof` keeps the value root and dotted path the source wrote, so `import { TOKEN as T }` publishes, displays, and anchors as `typeof T` — canonicalising the head would name a symbol that is not in scope in the consuming file. Two references to one declaration therefore intern as two nodes the nominal relation answers EQUAL, which is the question the relation exists to answer.

  **Every `typeof`-resolving consumer treats a MARKED carrier as terminal, in O(1), before it resolves anything.** The deferred evaluator, the path walker, the raising reducer, the carrier normalizer, the locator-view planner, and the relation unwrap each check `typeof_nominal_identity` first. A marked carrier SELF-RESOLVES — asking its `typeof` key returns the carrier — so resolving it again is at best wasted work and at worst a projection back down to the shared `symbol`. Inside the path WALKER the carrier is reached only with a segment still pending, and member access on a `unique symbol` reads the Symbol interface, so the walker widens to `symbol` and continues — it never publishes the base with segments unconsumed.

  **A STRUCTURAL consumer WIDENS through one shared helper; it never reads the terminal through the `resolved == node` rail.** That rail means "this reference did not resolve", and a marked carrier self-resolves — so a consumer asking which runtime constructor a prop emits, which callable role a member plays, or whether a root is definitely non-object would read a program that resolves fine as a missing dependency. `ProjectSemanticDispatch::widened_nominal_typeof` supplies the widened `symbol` inhabitant at exactly those sites (broad-runtime classification, symbol-identity demand, the path walker, the non-object-root predicate, the Svelte public declaration surface). The failure it prevents is not local: an unclassifiable runtime arm clears the WHOLE ordered constructor list, so one mis-read carrier empties its siblings' `type:` entries too.

  **Structural producers mint deferred carriers; resolving demand mints nominal terminals.** `locator_shape` and `macro_arg_producer` build `SemanticNodeData::TypeOf` without resolving anything. Resolving consumers converge through the shared `TypeOf` query, whose prepared facts certify `SemanticNodeData::TypeOfNominal`. The separate terminal variant forces exhaustive consumers to classify it; it carries the declaring identity and never requires another declaration lookup just to recognize a nominal symbol. Event-name enumeration treats it as a complete non-string leaf, so it cannot make sibling string literals incomplete.

  **Nominal identity covers declaration roots and certified members.** `typeof TOKEN` over a `unique symbol` declaration retains its declaring identity through aliases, imports, re-exports, and namespace-qualified references. Prepared member facts also certify readonly unique-symbol class statics (including inherited statics), object annotations, and supported named/intersection annotations. The identity includes the declaring member path: inherited statics anchor on the base declaration, and members certified through a named type anchor on that type, so separate values with the same named annotation share the certified member identity. An own non-unique member shadows an inherited nominal member. Ordinary `symbol` annotations, mutable members, and shapes without certification continue through structural projection; an arbitrary value expression or assertion is not enough to mint nominal identity.

**Authored-reference-head positions (the closed producer inventory).** Three
