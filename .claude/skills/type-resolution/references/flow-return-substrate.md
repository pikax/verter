## Flow-Return Substrate (U6)

The whole-function flow-return capability (`U6.FLOW_RETURN_SUBSTRATE`) is a demand-sliced substrate over four artifacts plus one dispatch arm:

- **`FunctionBodySkeleton`** (`crates/verter_semantic/src/analysis/flow/mod.rs`) — an arena-free (`Send + Sync + 'static`, `NoTypeExpr`) shallow statement/control skeleton with a return-site index, a lexical binding index, assignment/kill summaries, and per-site read/write/call + object-literal property footprints. Built once per function content version from the retained parse snapshot; NO type lowering at build time. **Which sub-expressions become their own tracked SITE is not this builder's own judgement**: `SkeletonBuilder::open_site` dispatches on `analysis::flow::value_descent`, the ONE wildcard-free classifier of an expression's value-structural children, and the content half's `Lowerer::lower_expr` dispatches on the SAME verdict. That is the structural fix for a planner/content split: a conditional expression got a structural arm in the CONTENT half while the planner still had no reason to descend into a branch, so every object literal in a branch lowered with each member value on the typed `SliceExpr::Elided` carrier and the whole return failed closed (`k ? { a: 1 } : 2` — `Error(Miss)` cands=0 — while `k ? {} : 2`, with no member value to elide, stayed green: the signature of an under-selected PLAN, not a broken arm). Neither half carries an UNDISPOSITIONED wildcard over `Expression` any more. `lower_expr` does end in `other => match value_descent(other)` — the wildcard is a DELEGATION, not a disposition: the wildcard-free match lives in the classifier, so a new variant does not compile until it is dispositioned THERE, and both halves inherit that disposition in the same change. `ValueDescent::TypeCarrier` is the ONE named asymmetry (the planner descends so a projection into the literal still reaches its members) — under-selection is the bug, and over-selection is not free: the content half's leaf answer for a carrier over a literal with a CALL-sourced spread embeds the spread's unreduced `ReturnType<callee>` carrier, which the leaf's fabricated-value gate refuses, so ONE carrier failed the whole RETURN closed for a value the checker types. So the content half no longer swallows a carrier over an OBJECT LITERAL: the literal keeps its structural lowering and the carrier contributes a MEMBER POLICY instead — see "Object-literal entry lowering" below. Every other carrier still leaf-lowers whole, because its type genuinely is the carrier's rather than its operand's.

**Object-literal entry lowering never abandons the literal for ONE entry.** The fallback to the whole-literal leaf answer is not local: it folds every sibling, spreads included, into one shallow-pass answer, and a leaf answer over a CALL-sourced spread embeds the callee's unreduced `ReturnType<…>` carrier, which the fabricated-value gate refuses. One unmodellable ENTRY therefore failed the whole RETURN closed. Two entry families no longer reach it:

- **A key whose property name is not its authored text** (`{ ...base(), [k]: 1 }`, `{ ...base(), 1: 2 }`) lowers as its OWN value position — `SliceObjectKey::Computed { value, authored }`. The evaluator names the property from the key's evaluated LITERAL (numeric keys through the SHARED canonical spelling, so `{ 1: x }` is the number `1`, never the string `"1"`); a key whose value is OPEN (`[key]` with `key: string`) leaves the surface's key SET unknown, which an object surface cannot express, so the literal fails CLOSED exactly as an unevaluable spread source does — publishing the modelled siblings alone would declare a member set missing a key the authored value has. A `unique symbol` key names the member by its DECLARING identity: the value channel carries that identity (the type-position carrier is preserved — see "Unique-symbol TYPE-position carrier preservation"), so two distinct `unique symbol` declarations are two properties, never one shared computed slot. The `authored` half remains the fallback channel for a NON-unique `symbol` key, whose value carries no identity of its own.
- **A type carrier over an object literal** contributes an `ObjectMemberPolicy` (`Widen` / `Preserve` / `ConstAssert`) rather than swallowing the literal. The three states mirror the shared shallow pass's own object-literal widening contexts exactly, because a carrier that lowers structurally and one that reaches the leaf lowering must not disagree about the same literal. `as const` pins every member literal AND marks the literal's own members `readonly`; `satisfies` preserves uniformly (this substrate performs no contextual typing, so the target-driven half of tsc's rule is the deferred contextual-widening contract — `flow_return_catalog::flow_return_ob05_satisfies_preserves_value_shape` pins the preserving side).

One recorded divergence rides this, asserted rather than silent: a SPREAD-contributed member does not take an enclosing `as const`'s `readonly` (the spread program merges the source's own modifiers — the existing spread-path `readonly` gap, reached by one more shape). The former unique-symbol-key divergence is CLOSED — the member is keyed by its declaring identity (`flow_return_ob12_names_a_unique_symbol_key_by_its_declaring_identity`). Acceptance: `typeinfo_tests::value_inference::object_return_entry_forms_lower_structurally_over_a_call_spread` is the PRIMARY semantic pin against TypeScript 7.0.2 (`tsc`); `meta_tests::an_entry_form_over_a_call_spread_reaches_the_runtime_lane_intact` and `cases::g_block::framework_surface_executor::an_entry_form_over_a_call_spread_reaches_the_framework_surface_intact` are secondary evidence that the answer survives to a consumer.

**Object-literal ENTRY classification is a second shared classifier on the same module** (`analysis::flow::value_descent`): `object_entry_descent(&ObjectPropertyKind) -> ObjectEntryDescent` splits an entry into `Property { key: ObjectEntryKey, value, kind: ObjectEntryKind, property }` or `Spread { source }`, with `object_entry_key` / `static_property_key_text` as the single authority for how a key NAMES its property (`Static` for an identifier or string literal, `Computed` for a computed or NUMERIC-literal key — `{ 1: x }`'s authored text is not its property name — `Unmodeled` for a private name). Accessor kinds are decided BEFORE the `method` shorthand flag, so a getter is never called a method. The classifier's guarantee is scoped: it is the single authority for the KEY and for the entry SHAPE, consumed by the skeleton's `open_object_site` and the content half's `lower_object_literal`. It is NOT the only site that decides an entry's KIND — `type_eval_build::extract_object_literal` (the shallow-pass leaf lowering the content half falls back to) and `function_program`'s property-footprint indexing each carry their own `PropertyKind` match. No behavioural divergence is measured (the precedences agree), and unifying them is not this substrate's boundary; the scoped claim is recorded here so the "single authority" phrasing is not read wider than it holds. The classifier answers a SECOND question on the same pass: `ValueDescent::UnmodeledCall` names a form whose OWN value is a call's return with no structural arm (`f?.()`, a sequence whose value operand is one (`(k, f?.())`), and a call under a type carrier; a bare call, `new` or tagged template takes the content half's structural arms before the classifier), decided by the single predicate `analysis::flow::value_is_unmodeled_call` — the CONTENT half fails closed, the PLANNER half takes the `Leaf` disposition (a call's arguments never provide its value). A sequence whose value operand is a BARE call is deliberately NOT in that class (D7): the content half's sequence arm routes it to the structural call rails through the shared predicate `analysis::flow::value_descent::sequence_value_takes_call_rail`, so `(0, f())` surfaces `f()`'s value with the discarded operands on the discarded-operand rail, and a callee the rails cannot represent keeps the positional fail-closed marker. That verdict moved here because it is a property of the FORM: the downstream carrier gate reads the leaf ANSWER, and for all of those forms the shallow pass answers a bare `any` with no carrier in it, so nothing fired and a fabricated `any` published warm and clean under a promise that a call with no structural arm fails closed. The skeleton records the branch arms as `SkeletonExprShape::BranchJoin`, and the graph turns them into `ValueDef` edges, so the demanded path threads through both arms UNCHANGED. Acceptance: `flow_return_conditional_branches_are_planned_and_lowered_by_one_descent`.
- **`FunctionFlowGraph`** (`analysis/flow/flow_graph.rs`) — the sparse per-function typed dependence graph, built once from sealed `PreparedFunctionBodySkeleton` with private fields and immutable views. Production graph construction never resolves a display name or accepts an unprepared skeleton; an indexed `None` remains known free/opaque. Local declaration hubs retain exact declaration evidence and owner-provided runtime aliases. Each captured variable has one real `CapturedBinding(FlowCapturedBindingId)` hub, resolved through `captured_binding(id)` to its exact outer identity; no captured variable becomes a fabricated local declaration. Prepared reads and writes target those exact subjects, so shadowed twins stay distinct and captured access edges grow linearly. Closure capture inventories include write-only captures and retain their hubs through effect dependencies; actual read paths alone create value-provider edges. Read projections prepend static member paths to the remaining demand. Whole-slot/path writes emit both `site → hub` and `hub → write site` effect edges, and region-to-control-input edges preserve governing values. The graph store shares this structure and its immutable binding map across every demand on the same pinned content version.
- **`ReturnPathPeeker`** (`analysis/flow/peeker.rs`) — the graph demand planner holds only `&FunctionFlowGraph` and computes reachability for return/expression origins and a projection path. `ReadProjection` carries the structural `FlowReadKind`: direct reference results compose authored member paths with the demanded suffix using interned path tails; consumed call/computation/control/closure inputs retain their own authored paths and reset the result suffix. This prevents artificial growth around `v = v.trim()` while genuine member-alias cycles such as `v = v.a` remain budgeted. Shared `ValueDescent::{Reference,Logical,Sequence}` dispositions own result forwarding: logical value operands and only the final sequence operand inherit the result suffix; lowerable leaf computations consume independent inputs. `PathWriteSource::ObjectLiteralEntry` is the only authority for suppressing earlier definite duplicate properties; mutable writes remain candidates until runtime control flow executes them. Effect dependencies stay selected past value suppression, and typed `ControlInput` edges demand the governing expression value. The planner bounds return origins, selected nodes, and combined value visits plus path tails (`max_value_states`); every trip returns typed `FlowSliceBudgetExceeded` without a partial plan. `ReturnSlicePlan` is constructed only inside the peeker and exposes immutable selection/work getters; `value_states()` retains the charge so a stricter later request cannot reuse a plan over its budget. The cache owner alone pairs the selection with its minted slice hash in production.
- **Hash-then-lower slice artifacts** — shared `FlowSliceHashNode` / `FlowSliceLoweredBodyNode` storage lives in `crates/verter_session/src/cache_runtime/flow_slice_node.rs`; request-local execution lives in `crates/verter_session/src/project_semantic_dispatch/flow_slice_driver.rs`. The driver acquires the graph publication claim before requesting an owned `PreparedFunctionBodySkeleton` through `OwnedLowering::prepare_function_structure`; the claim retains the existing shard lock until publication or abandonment. Shared storage retains no source worker or resolver callback. The hash demand plans + folds exactly the selected subgraph into the opaque `FlowSliceHash` (no byte export, `Debug` redacted; sole constructor `compute_flow_slice_hash`), then the lowered demand lowers ONLY the retained plan into the arena-free `FlowSliceIR` (each `FlowSlot` carries its binding-identifier span — the declaration-precise slot identity the content lowering gates on; the slice hash stays span-free). The hash-then-lower split is TWO rails: the type-state pins hash-before-lowered-KEY (the lowered store is unaddressable without a minted hash), and the per-thread `compute_flow_slice_hash_thread_invocations` counter behaviorally pins that the lowered COMPUTE performs zero hash computations (the type system cannot — the hasher is a public producer); the counter, its accessor, and its increment are gated behind `verter_semantic`'s `test-support` feature (enabled by `verter_session`'s dev-dependency edge — `#[cfg(test)]` cannot serve a cross-crate consumer), so production builds compile the hasher without the TLS or the increment. Planning runs exactly ONCE per cold demand: the hash node's published `FlowSliceHashOutcome::Planned` RETAINS the plan (`Arc<PlannedFlowSlice> { hash, selection }`), and the lowered node lowers that retained plan — it never re-plans; the same idiom gates a `return_path_peeker_plan_thread_invocations` counter on the planner, and the round-trip guard binds the lowered compute to ZERO re-plans. Keys carry the per-function body-sensitive, cosmetic-insensitive `flow_body_stable_hash` (from the per-file `FunctionProgramIndex`), NOT `parse_stable_hash` — PLUS the EXACT per-function byte hash `flow_body_exact_hash`. Both nodes publish content-addressed artifacts with EMPTY fact rails — slice identity is never a warm-validity oracle — and "the key IS the validity oracle" holds only because TWO things are true together: the key carries that exact byte axis, and the artifacts carry NO absolute source position. That second half is a TYPE, not a convention: every span in `FunctionBodySkeleton` — and therefore in `FlowSliceIR` — is a `FrameSpan` (`verter_semantic::analysis::flow::frame_span`), a private-field newtype whose only constructor from a source position is `FrameSpan::rebase(anchor, span)` and whose only way back is `FrameSpan::to_absolute(anchor)`. `SkeletonBuilder::frame_span` is the ingress crossing (so `finish` is a plain MOVE with no per-family rebase pass to apply to five families and forget on two — which is exactly what happened: the read and call footprints kept ABSOLUTE offsets, and `lower_slice_plan`'s source-order effect sort mixed the two coordinate systems, ordering every call after every write at any non-zero anchor); `Lowerer::rebase` is the one crossing on the consumer side, and `FrameSpan::to_absolute` has exactly one caller (the parameter inventory comparing stored binding positions against live default-initializer offsets). A mixed comparison — `frame.start < absolute.start`, or a sort keyed off one of each — does not COMPILE. That claim was one accessor away from false: `FrameSpan::start()` / `::end()` were `pub fn -> u32` with ZERO production callers (one test), so the comparison the module exists to forbid was writable in the module that forbids it. They are deleted; `FrameSpan` now exposes no offset at all, and every consumer comparison is `FrameSpan`-to-`FrameSpan` (`contains`, the derived `Ord`). Two things stay CONVENTIONS and the module now says so instead of implying otherwise: the anchor is a bare `u32` on both crossings, so `rebase(0, absolute)` still mints a `FrameSpan` holding an absolute offset and `to_absolute(wrong_anchor)` still lands somewhere (nothing pairs a `FrameSpan` with its anchor — it outlives the file version it was recorded on, which is exactly why the anchor is re-supplied at egress); and the derived `Ord` / `Hash` let two frames' spans compare without either frame being named (harmless because every artifact here is per-function). `SkeletonRead` carries the exact root-identifier `FrameSpan`: prepared ingress joins that occurrence to the indexed binding authority, and capture admission verifies the exact selected read site. This position remains frame-relative and is excluded from slice hashing. Acceptance: `skeleton_is_invariant_under_the_function_position`, `lowered_ir_is_invariant_under_the_function_position`, `lower_orders_effects_by_authored_position_at_any_anchor` (the predecessor of the last read `span.start` back off the result and asserted it ascended — the same key the lowering had just sorted on, over a fixture at offset 0 where both systems coincide, so it held by construction and passed while the invariant was violated). Each half covers a blind spot the other cannot: `flow_body_stable_hash` is an AST fold, so it is blind to a leading blank line (which moves every absolute position and is fixed by the relative anchoring) AND, because it alpha-normalizes binding/reference identifiers, blind to a local rename that shifts every position INSIDE the body (which relative anchoring does NOT survive and only the exact byte axis catches). The exact axis is deliberately per-FUNCTION, not the file's content hash, so an edit to a sibling function preserves the untouched function's own-byte axis and may preserve its narrow slice hash. Graph artifact reuse additionally requires the exact serving `ParseKey`; its content digest pins lexical binding context, so a changed ancestor declaration cannot reuse an unchanged child body's stale captured identities. Acceptance: `flow_bundle_reuse_is_sound_for_every_content_its_key_admits`, `the_two_shift_edits_are_invisible_to_flow_body_stable_hash`.
- **`SemanticQueryKey::FlowReturn`** — the ONE dispatch arm (`project_semantic_dispatch/flow_return.rs`): key = content-free function slot + normalized type args + `FlowReturnContext` (all five env dims) + `ReturnProjectionDemand` + `FlowInputContext`. The published memo entry records `satisfied_projection` — the materialized point set the compute ACTUALLY produced (§3.4 lattice-relation satisfaction; `semantic_query_memo/flow_return_memo.rs` `cached_satisfies` decides warm hits against the REQUESTED point, never nominal demand). Warm validity roots on the sole `ProgramAnalysisFactRef::FlowBody` rail (function identity + `flow_body_stable_hash`, validated fail-closed by `StoreView::validates_program_analysis_domain`); the subplan's separate `FlowSlice` DISCRIMINANT fact does not exist on this tree (ratified C7 divergence — `FlowSlice` never enters `ReadSetSignature.facts`). Success carries `FlowReturnResult { return_type, can_fall_through, degradation }`: a degraded success (modeled-`any` substitution, typed `FlowReturnDegradation` — `NonCallableBinding`, `UnrepresentableCallee`, `FailedBindingInitializer`, the fail-closed `UnappliedWriteEffect` for a slice carrying a whole-slot write effect into a parameter or value-selected slot the evaluator does not apply, the fail-closed `ConditionalVarDefinition` for an observed function-scoped `var` whose surviving reaching definition was recorded inside a conditional arm, the fail-closed `UnreducedDeclaredUnion` for an annotated declarator whose DECLARED union could not be reduced to the constituents its initializer selects, the POSITIONAL `UnmodeledPosition` for a sub-expression whose resolver is a named downstream block, or `UnresolvedValue`) RETURNS through the success carrier but is `ReturnOnly` (never warmed). **The EVALUATION is the authority on its own degradation; the construction-time fold is a BACKSTOP, and the two deciding fields (`return_type`, `degradation`) are PRIVATE so neither can be bypassed** (`can_fall_through` is `pub` — a plain reachability bit no admission channel reads). `FlowReturnResult::new` is the sole construction point: it takes the evaluation's own observed reason and additionally consults `SemanticGraphStore::node_reaches_unresolved` (`semantic_query_memo/unresolved_reach.rs`), folding `UnresolvedValue` in when the value reaches a semantic-miss carrier (`QueryError::means_type_is_not_yet_known`). That verdict is a MEMOIZED INDUCTIVE BIT over the hash-consed immutable graph — `self_bit(n) || any(bit(child))`, decided once per node id, O(1) amortized at every later read. It carries NO budget, because a bound whose trip reports "unresolved" computes a DIFFERENT function: a 4,100-arm literal union with zero misses is fully known, and stamping it `UnresolvedValue` propagates a factually false permanent warm refusal into every enclosing result. The walk descends only structure the evaluation composes or lowers inline (`Union`/`Intersection`, `Object` members + signatures + index signatures + keyspace, `ObjectSpreadProgram`, `Array`/`Tuple`, `TemplateLiteral`, `KeyOf`/`IndexedAccess`/`Mapped`, `Conditional`, `Signature`, `InstantiationRef` args, `Alias`, and the three carriers' type ARGUMENTS through the sanctioned `carrier_type_args` accessor) and STOPS at every shallow carrier (`DeclRef`, `MergedDecl`, `BareRef`, `ImportType`, `TypeOf`) — descending one would be materialisation, and a miss inside a referenced declaration is that declaration's own admission problem. Its match over `SemanticNodeData` is wildcard-free (and covers struct FIELDS a variant match does not — `MapperKey::parameter_node` is a descent), an unresolvable node id answers "unresolved" (fail closed), `RawFallback` is not-known (agreeing with `SemanticNodeData::means_type_is_not_yet_known`, which is the reconciliation of the two classifications), and a deferred `BareRef` is explicitly NOT a miss. Without it, `function f(x: HasQ) { return x.q }` published `Opaque(Miss)` with `degradation: None` and `slot_candidate_count == 1` — a complete, warm answer with an opaque interior, so `execute_function_return_source` never folded the cache-read rails and every enclosing composition warmed around it; the same shape reached admission from FOUR independent ingress paths (the `FrameShadowed` arm, the free-leaf arm, a composed object member, and a leaf lowering's own `Array`/`Signature` interior), which is why the fold exists at all. The AUTHORITY, however, is the compute: a construction-time walk cannot see a fabricated `any` (a value cannot distinguish a fabricated `any` from an authored one), so a position whose resolver is a named downstream block RECORDS `UnmodeledPosition` where it stands and contributes the typed unresolved marker, and the fold catches only the residue no position observed. Acceptance: `a_value_reaching_a_miss_carrier_is_never_admitted_warm` + the over-degradation discriminator `a_deferred_carrier_and_a_resolved_composition_still_admit_warm`; no-value outcomes are typed `FlowReturnFailure`s through `ReturnOnly`; `FlowSliceBudget` refusals are non-admitted at every layer (planner refusal → no hash entry → unaddressable lowered store → no memo candidate). Warm admission has ONE positive authority: the flow finalizer's `CompleteFlowResult` proof token, minted only by `flow_solve::finalize_flow_solve` from the runtime-sealed completion artifact. The family memo REQUIRES that token on every `FlowReturn` build (`QueryBuildOutput.flow_completion`; the memo's flow-proof gate is a negative veto fence — it refuses an absent or mismatched token and marks the refused read partial/suppressed so no parent warms around the veto, but it can never promote a proofless result). A degraded or unproven outcome keeps its usable value and takes the rails ONCE at the source: the finalizer-outcome adapter in `build_flow_return` translates a `Partial` / no-demand verdict into the build's own `result_is_partial` / `cache_suppress` / `partial_reasons` (`degradation_reason_class` for a degraded success, `NO_VALUE_REASON_CLASS` for a no-value failure), and the universal read funnel (`fold_cache_read_rails` at the shared cold-build helper's return) propagates those rails into every enclosing composition — the request-partial sticky gating component-meta/shape/materialize warm, plus the build-local taint. There is NO consumer-side fold: at the sealed consumer entry (`execute_function_return_source`) the value routes through `FunctionReturnNode` untouched, and an inline evaluation that produces no memo read (a coinductive hold surfacing at a consumer, or an inline SCC root whose finalizer refused) marks the enclosing build through the same funnel primitives directly. SCC members are proof-typed at the publish boundary (`CompletedFlowReturnMember` / `PendingFlowReturnMember` carry the token), so a degraded member is unrepresentable in the batch. The degradation bit is still read elsewhere for questions that are not admission: the seal's `DegradedValue` refusal and `tsc_projection.rs`'s inferred-class-member row.

**Typed flow-gap retraction.** `FlowReturnDegradation::FlowGap(FlowGap)` marks a usable approximation whose model is incomplete. The five allocation-free reasons are `GuardNarrowing`, `NominalRelation`, `ClosureCapture`, `AbruptCompletion`, and `UnmodeledExpression`; `AbruptCompletion` is a reserved carrier with no syntax-only detector because current lowering facts cannot distinguish it from checker-correct completion. Every such result is `ReturnOnly`, remains cold at the root, suppresses the whole SCC batch, and propagates through the universal read funnel. Statement-level gaps retain the first source-ordered marker as a fallback and promote it only when evaluation observed no concrete degradation; expression-level gaps remain immediate because they identify the unmodelled value position. `ExpressionInferenceCompleteness` separates a semantically complete `any` (`SliceExpr::SemanticAny`, admissible when no other degradation exists) from a shallow inference fallback (`SliceExpr::Gap(UnmodeledExpression)`). The active detectors observe missing authority without changing narrowing, nominal relation, closure-effect, or expression-value semantics. `NominalRelation` is minted from the SHARED relation authority's own undecided verdict: predicate narrowing asks `RelationKind::Comparable` for the subject-versus-target overlap and consumes its `ComparabilityVerdict` — a negative verdict is the authority's disjointness PROOF (the subject reads `never` on the live positive edge), a positive one takes the checker's intersection, and only `Undecided` records the gap. The evaluator owns no relation classifier of its own. A call in a control position (an `if` / ternary test) contributes `GuardNarrowing` unless its callee is a PROVABLY CLOSED same-file declaration (`flow_slice_content.rs` → `closed_callee_declaration`): the file must be module-scoped (a carrier script block, or top-level module syntax — a script's top-level functions are globals merging with every other script's and every `declare global` block's same-name declarations), the call site must sit outside every `namespace` / `module` block (a namespace-owned call site binds a bare callee through the block scope before the top level — the block-local declaration of the name shadows the top-level one, exactly as the function index binds `N.check` over the file-global `check` for a direct call — and the gate enumerates top-level declarations only, so it refuses rather than certify or mint the wrong declaration), there must be exactly one same-file declaration, and the binding must not be exported by any spelling (an exported binding is augmentable through `declare module`). A closed callee with an authored non-predicate return is certified decided-above; a closed predicate callee mints the `TypePredicate` guard fact; every other control callee gaps — never a locally selected predicate target, never a silently certified call. A minted predicate TARGET (`x is T`, `asserts x is T`) must be closed over the module scope — the one scope the callee's declaration and the caller's frame resolve identically: the channel refuses (`GuardNarrowing`) a target naming a binding of the CALLEE's own declaration (its type-parameter clause, a formal parameter under `typeof`), which the call instantiates, AND a target naming anything the CALLER frame binds (`predicate_target_names_caller_binding`: its own or an enclosing frame's type parameter — the composed binder environment interns those ahead of every owner-scope alias — a body-local `type` / `class` / `namespace` / `enum` of the name, a parameter / local / capture under a `typeof` root), which the call site would rebind; a value-only local of a type name's spelling is transparent. A sequence's DISCARDED operands (`(assertString(x), x)`) are a narrowing position too — the checker binds the left-hand side of a comma expression into the control flow, and an `asserts` callee narrows the read that follows — so a discarded call is certified decided-above only for a `new` construct or a provably closed same-file callee whose return annotation is absent or is not an `asserts` predicate (assertion signatures are never inferred); every other discarded call gaps the statement (`record_discarded_operand_calls`, sharing the control-test scanner under `ResultIndependentPosition`). An `instanceof` right-hand side mints the `Instanceof` fact only for a bare name left free by the frame that denotes the module's ONE same-file top-level `class` whose STATIC side is provably plain (`class_static_side_provably_plain`): no static computed key anywhere in the class or its heritage chain (any computed key can spell `Symbol.hasInstance`, whose predicate type replaces the instance type as the narrowing target), and every superclass a bare name of exactly one same-file top-level class — an imported, value-bound, expression, or cyclic heritage refuses; every other spelling gaps. The FLOW-root SCC close publishes its component on the union of the root's, every drained flow member's, every drained CALL member's (callee, receiver, arguments, explicit type arguments, program point), every relation member's, and every already-completed batched member's self-roots (`union_self_roots`), mirroring the call-root close — the composition is observable in tests through `flow_root_carrier_probe` even for a component that degrades.

Both shapes take BOTH rails (the request-partial sticky AND the build-local taint), and that is the decision. Suppressing only the build-local taint for the NO-VALUE shape (a retired sealed-consumer fold arm once did) left the REQUEST unmarked, and `mark_request_result_partial` is the sole gate on `ComponentMetaResultDb`: six measured programs published `props: []`, `synthesis_should_suppress: false`, and a WARM cache hit on replay, for shapes the checker types without difficulty (a `for` / `switch` / `try` in `makeProps`; a nested arrow with a `while`; a local helper called for a member value). "The consumer decides what a contained failure means for its own surface" is true of the VALUE — which is why the value still returns — but not of the ADMISSION rail. Localisation is the POSITIONAL rule's job, one level down inside the evaluator. Pinned by `an_uninferred_body_return_never_publishes_a_complete_warm_meta_surface` (six rows + a clean warm control).

The fold rides NAMED partial classes, not the boolean-bridge `PROPAGATED` — because three consumers must treat a flow-return partial differently and a boolean cannot carry that. The classification axis is the CONSUMER, not the cause, and TWO classes span it:

- **`PartialReasonSet::FLOW_RETURN_UNINFERRED`** — a DEGRADED SUCCESS whose surface is FAITHFUL: every modelled sibling is exact, and the one position the substrate could not type carries the typed unresolved marker rather than a fabricated `any`. `UnmodeledPosition`, `UnresolvedValue`, `UnrepresentableCallee`, `FailedBindingInitializer` (`degradation_reason_class`). Every one of the four contributes the MARKER — `degraded_unrepresentable_callee` mints `CallValue::unmodeled_position`, not `CallValue::modeled_any`; a fabricated `any` here is indistinguishable from an authored one at every downstream gate, and an overloaded callee published `flag: any`, warm and clean, where the checker says `boolean`.
- **`PartialReasonSet::FLOW_RETURN_UNVERIFIED`** — a DEGRADED SUCCESS carrying a usable approximation that is not proven complete (`FlowGap(_)`, `UnappliedWriteEffect`, `ConditionalVarDefinition`, `UnreducedDeclaredUnion`, `NonCallableBinding`).
- **`PartialReasonSet::FLOW_RETURN_NO_SURFACE`** — a NO-VALUE outcome, which has no surface at all: every `FlowReturnFailure` and `DeclaredMiss` alike (`NO_VALUE_REASON_CLASS`, one rule rather than a constant-returning per-variant match). A DISTINCT bit from the unverified class, and the distinction is load-bearing rather than descriptive — see the per-lane containment note below.

### Body Completion Algebra

Two facts decide what a body contributes BESIDES its authored return arms, and both are producer-owned in `flow_slice_content.rs` — the evaluator and the join read the typed answer and never re-derive one from statement syntax.

**A loop that never completes normally ends its region's normal path**, exactly as an authored `throw` does: the lowering emits `SliceStatement::DivergentLoop` instead of `TransparentLoop`, drops the unreachable suffix, and clears the region's `can_fall_through`, so the body stops contributing the fall-through `undefined` and a lone literal return becomes the sole contributor and widens. Before this, `function f(c: boolean) { if (c) return 1; while (true) {} }` published `1 | undefined` — warm-admitted, with no degradation to mark it, where the checker answers `number`.

The classification mirrors the checker's BINDER (`createFlowCondition`) and is deliberately not generalised: the exit edge is unreachable only when the condition is the bare `true` KEYWORD, or absent for a `for`. It neither skips parentheses nor evaluates truthiness — `while (1)` and `while ((true))` both keep a reachable exit, and the parenthesized form is the row that proves the rule matches a token rather than a value. The exit is likewise reachable whenever a `break` can target the loop: an unlabeled `break` whose innermost enclosing breakable construct is the loop itself, or a labeled `break` naming a label that wraps it. A `continue`, a `break` captured by a nested loop, and a `break` captured by a nested `switch` all leave the exit unreachable. Detection is biased toward FINDING a reaching break, so an unrecognised statement form preserves the fall-through answer rather than asserting divergence.

**A body that contributes no return arm and never completes normally seeds by the function's authored FORM**, not by how it terminated — the checker's `mayReturnNever` rule, carried as the producer-owned `EmptyCompletion`. A function DECLARATION and a CLASS method model as `void`; a function EXPRESSION, an ARROW, and an OBJECT-LITERAL method model as `never`. The form is read from the node kind plus the locator's final descent step, which is the only thing separating a class method from an object-literal method (they share an OXC `FunctionExpression` node). This is what makes the divergence rule safe: without it, clearing `can_fall_through` would turn the correct `void` of `function f() { while (true) {} }` into `never`. It also corrects the throw-only declaration, which published `never` against the checker's `void`.

Acceptance: `flow_return_loop_completion_tests` (four row tables, every expectation anchored against `tsc 7.0.2 --strict` via `--declaration --emitDeclarationOnly`), plus `a_loop_fixed_point_survives_an_edit_as_the_fresh_answer` — the two spellings differ by one `break`, and each is published on a host already warmed with the other and compared against a host that has only ever seen it, so a completion fact an edit failed to invalidate surfaces as a type difference rather than a stale count nobody reads — plus the catalog rows `flow_return_bl13_throw_only_declaration_is_void` and `flow_return_bl15_models_divergent_loop_as_void`.

#### Return-Position Subtype Reunion

The join that turns a body's return arms into one value applies TypeScript's
return-position SUBTYPE REDUCTION (`getUnionType(types, UnionReduction.Subtype)`
in `getReturnTypeFromBody`): an arm that is a strict subtype of a surviving peer
is absorbed into that peer, so `{ c: string }` beside `{ c: string | number }`
leaves only the supertype. The reduction lives in the flow evaluator's VALUE
INFERENCE — `join_flow_return_contributors` →
`reduce_return_arms_to_supertypes`, applied to the arm list before the canonical
union interns it. It is deliberately NOT in the canonical algebra, where a
supertype arm never swallows a subtype arm: the same two object nodes handed to
`intern_normalized_union_or_intersection` still intern as a two-arm union.

Every judgement comes from the SHARED relation authority
(`SemanticQueryKey::Relate` through `execute_relate_pair`); the evaluator owns no
subtype oracle, and `RelationKind::Subtype` / `StrictSubtype` are refused by the
reducer, so "strict subtype" IS the pair `arm → peer` assignable and
`peer → arm` not. The directions are asked in a FIXED order and the order is the
contract: `arm → peer` decides whether the pair is a reduction candidate at all
(a `NotAssignable` answer refutes absorption; an answer the authority does not
give means the pair never entered the reduction, exactly as before the reduction
existed), and only an ADMITTED candidate asks the reverse, where an UNDECIDED
answer leaves that reduction unfinished — every arm survives, `FlowGap::NominalRelation`
rides the result, and it is `ReturnOnly`. The traversal mirrors `tsc`'s
`removeSubtypes` (last arm to first, compared against the arms still standing),
surviving arms keep source order, and each ORDERED pair is asked at most once per
join.

One structural precondition runs BEFORE the relation: two plain object surfaces
listing DIFFERENT keys are never a reduction pair. The checker's own union of
object literals normalizes each arm with `key?: undefined` for a key its siblings
have and it does not (`if (n) { return { label, n } } return { label }` prints
`{ label: string; n: number; } | { n?: undefined; label: string; }`), so neither
normalized arm is assignable to the other; the flow substrate publishes the
un-normalized arms, where `{ label, n }` IS assignable to `{ label }` and
absorbing it would delete the `n` member the checker publishes. The gate is scoped
to surfaces whose key domain is the member list — a call, construct or index
signature on either side goes to the relation.

The call value carries a matching reduction on the intersection side: a callee's
INSTANTIATED return that pairs the empty object type `{}` with a definitely
non-nullish constituent drops the `{}` arm (`andD<T>(x: T): T & {}` called at
`"x"` is `"x"`, not `"x" & {}`), in the one call sink
(`flow_return_callee.rs` → `reduce_instantiated_return`) where the checker's
`getIntersectionType` performs it. An AUTHORED `T & {}` keeps both constituents;
"definitely non-nullish" is a node-SHAPE fact (a literal, or a non-nullish
primitive), not a relation question. The canonical intersection applies the
same `getIntersectionType` rules to concrete arms: redundant supertypes drop
(`{} & "x"` is `"x"`, `string & "a"` is `"a"`; a written `string & {}` keeps
both, as the checker keeps that pair, while an instantiated one is `string`),
`null` or `undefined` beside an object type is `never` (so `(string | null) &
{}` is `string`), and an intersection distributes over its union arms (`1 & (1 | 2)` is `1`) unless the distributed union keeps an
intersection constituent and grows, where the checker prints the
undistributed origin (`(QA | QB) & Z`). A canonical union reduces an
authored intersection arm the same way. The authored shell itself stays the
display form; the relation engine reads a shell whose canonical intersection
differs as that type (`reduced_authored_intersection`: `(number & string)
extends never` holds), and a projected read ending at an intersection with a
scalar arm returns that intersection, never a one-level surface of it.

#### The Completion-Carrier Inventory

A completion fact carries no degradation of its own, so a carrier that drops or inverts one publishes a WRONG answer that also WARMS — nothing downstream can tell a lost fall-through edge from a body that genuinely never completes. The defence is the closed inventory in `crates/verter_session_query/src/flow/completion.rs`, which makes an unlisted carrier unrepresentable rather than merely undocumented.

`NormalCompletion` is an opaque `Copy` fact whose boolean is private to that module. `NormalCompletion::minted(bool, CompletionConstruction)` is its production constructor and `NormalCompletion::reaches_end(CompletionDischarge)` its production reader. Both are public, because the source lowering, the evaluator and the result rebuild are all legitimate producers in different crates. What they guarantee is ROW-QUALIFIED production: a new site that produces or consumes a completion fact cannot compile until it names a row. They do not register a unique call site per row, and they do not prove the supplied boolean correct. The two site vocabularies are distinct closed enums, so a construction row is unrepresentable at a discharge. Stored carriers (`SliceRegion`, `SliceContent`, `SliceSwitchCase`, `BodyCompletionObservations`, `FlowReturnResult`) claim a `CompletionTransport` row through `TransportsCompletion`, a public test-support registration trait implemented via `transports_completion!`. It is NOT sealed — any crate can implement it under test support — and an impl binds a type to a row without proving the type holds the fact; the closed row vocabulary and the suite's cited-equals-listed check keep the registrations honest. `BodyCompletionObservations` is the typed pair carrying the bare-`return;` and inference-only implicit-`undefined` contributions the join reads alongside the fall-through fact.

The suite (`flow_completion_inventory_tests`) closes the two directions the compiler cannot see. A probe table runs one authored program per row through the ordinary dispatch and pins the checker's answer, so a carrier whose fact is dropped fails with a wrong TYPE — dropping the `switch`-clause `break` fact publishes `number` where the checker answers `1 | undefined`. A process-wide coverage recording (process-wide, not thread-local: a fact is minted on whichever worker lowers the body and discharged on whichever thread evaluates it) then requires the CITED row set to EQUAL the LISTED one, in both directions — a listed row nobody reaches is prose that drifted in, and a cited row the list does not carry is exactly the carrier that gets missed. Re-pointing one discharge at a neighbouring row fails the coverage with that row named.

Two carriers the inventory itself surfaced: the `for_tests` hermetic result fixtures and the unproven-member injection mint real completion facts for bodies they never lowered (the `HermeticFixture` row), and `ReturnDomainMetadata::FlowReturn` carried a `can_fall_through` field no production path ever filled — deleted, because a flow member reaching that equation would have to re-decide the body's completion from a copy, which is a second completion authority by construction.

Suites inspecting a lowered region use `reaches_end_for_assertion` / `minted_for_fixture`, both built in the test configuration alone: a synthetic value handed straight to an assertion takes no decision the pipeline depends on, and giving it a row would put a stage on the inventory that production does not have.

Registry-live guards: `flow_completion_carrier_inventory_is_closed`, `flow_completion_carriers_publish_the_checkers_answer`.

#### Abrupt-Suffix Completion: Admission Closed, Value Owed

Completion is still reconstructed from statement SYNTAX in two places. Neither publishes a fabricated arm as a complete answer any more, but one of them still DERIVES it.

The region accumulator in `flow_slice_content.rs` derives `can_fall_through` along the OXC statement walk, and the suffix classifier that decides whether a pending `break` contributes an implicit `undefined` recognises `return` / block / `if` and nothing else. That gap used to answer "does not return" for every other form, which fabricated the contributor. Measured on the suffix spellings of one base program (`OUT: INNER: { try { break INNER } finally { return "a" as const } }` followed by the suffix): a `return` / block / `if` suffix published `"a" | "b"`, while a LABELED, `try`, `throw` or `switch` suffix published `"a" | undefined` — merely LABELING a block changed the answer, and all four admitted CLEAN (`degradation == None`, one warm candidate), so nothing downstream could tell the fabrication from a real fall-through edge.

**The wrong-and-warm half is closed.** `SuffixReturn` is TRI-state — `Guaranteed` / `NotGuaranteed` / `Undecided` — with a `_ => Undecided` wildcard, so a form this lowering cannot classify (a labeled statement, a `try`, a `throw`, a `switch`, any loop, any jump, and any form added later) proves nothing instead of answering the negative proof. An undecided destination mints `FlowGap::AbruptCompletion` ahead of the try, which is the substrate's standing disposition for a control fact the lowering cannot carry: the value still returns and is never admitted. The proved spellings are unchanged and stay clean — that positive half is what keeps the guard from being satisfied by a blanket degrade.

**The value is still owed.** Under the gap the derivation is unchanged, so an undecided suffix still returns `"a" | undefined`. Removing the fabricated arm — rather than refusing to publish it — is the remaining work, and extending the match to do it is forbidden: a syntax-only classifier for completion is exactly the second completion authority the substrate must not have. The reduction belongs on the DEMANDED `FunctionFlowGraph`, which today carries no completion at all — no completion edge, no reachability fact — and cannot acquire one from the current `FunctionBodySkeleton`, which indexes regions, return sites, bindings, writes and expression sites but records no `throw` statement, no `break` / `continue` jump, no break-target inventory, and no ordered statement list. Closing it therefore needs content-free abrupt-completion topology on the skeleton, ONE reduction over it on the graph, a typed producer feed for the terminators only the evaluation can decide (a proven-`never` call, an unsupported construct, an invoked-closure effect), and the deletion of every present derivation — not a local patch. The same typed-terminator gap is why an expression statement is classified `NotGuaranteed`: a call proven `never` does not complete normally, and the statement's shape does not say so.

The authored-`return` spelling stays separately pinned checker-correct (`X88_nested_label_inherits_enclosing_suffix_return`), and the no-suffix spelling keeps its checker-correct `"a" | undefined` (`flow_return_abrupt_finally_over_pending_break_contributes_undefined`) — there the destination really is the function end.

Registry-live guard: `a_labeled_try_or_throw_suffix_never_admits_a_fabricated_undefined_contributor`.

### Control-Position Narrowing Is Fail-Closed

`SliceGuard::None` means **proved non-narrowing**, never "unsupported or unrecognized". That distinction is the whole contract: a control fact the lowering cannot carry produces a SUPERSET of the checker's type, and a superset is admissible only behind the typed `FlowGap::GuardNarrowing`, which makes the result `ReturnOnly` and never warm. A superset published with no gap is a wrong-complete result.

The guard lowering is therefore tri-state. `Lowerer::classify_guard` returns `GuardDisposition::{Modeled(SliceGuard), NoNarrowing, Unexpressible}`; `Unexpressible` sets `control_test_gap`, which the callers drain into a `SliceStatement::Gap` ahead of the construct. `classify_guard` itself has NO gap side effect, so the loop-transparency probe can consult it without degrading the enclosing statement. Every composing form — `!`, `&&`, `||`, `??`, conditional, sequence, assignment, parenthesized — recurses through that one authority and COMPOSES the disposition; collapsing any of them to `None` reintroduces the defect.

Classification rules, each of which exists because the checker narrows through the spelling and the lowering does not carry it:

- Equality over all four operators is modeled only as `typeof x === "lit"` and `subject === literal`. Any other spelling degrades when either side is a narrowing destination, the `typeof` of one, or a nested guard wrapped in a boolean comparison. Loose `==` / `!=` never lowers through `EqLiteral` — `x == null` has nullish semantics that are not modeled.
- `in` is modeled only for a string-literal key over a represented subject; a computed, private-name or dynamic key over a represented subject degrades.
- `instanceof` is silent only when the left side has no represented same-frame root; an access rooted at one, or an unprovable constructor, degrades.
- Truthiness reads a reference through parentheses and the postfix non-null assertion only — the two wrappers the checker treats as transparent when matching a narrowing reference. This peeling must happen at the classifier's ENTRY as well as at its leaves, or every composing form behind a wrapper falls through to the truthiness rule and reports a proved absence of narrowing. `satisfies` and the `as` / angle-bracket TYPE ASSERTION are BOTH opaque: measured against the checker, `if ((x satisfies string | undefined))` leaves `undefined` in the result and `typeof (x satisfies string | number) === "string"` narrows nothing, exactly as their `as` twins do, while both postfix-`!` spellings narrow. Peeling either makes this half narrow where the checker does not, publishing a SUBSET of the checker's type — which DROPS a real return contributor rather than merely widening it, and is therefore a worse failure than the superset a missing narrow produces.
- A `const` alias carries the fact its initializer decided (the checker re-establishes it on the reference the initializer named), so a guard over the alias degrades. `let` / `var` aliases stay silent — the checker does not preserve aliased conditions through them.
- A CAPTURED binding is a narrowing destination like any other: the evaluator resolves a nested read against the enclosing frame's binding, and the content half already writes through captured names. A guard written inside a nested function value over a capture therefore degrades. Only a genuinely free or unresolved capture with no evaluator-visible slot stays silent. Narrowing a capture is not implemented; the rule only stops the superset being minted complete.

A `switch` clause's relation is `SliceSwitchTest::{Default, Literal, Unmodeled}`, never an optional literal — an optional conflates an absent test with an unrecognized one, and the evaluator acted on that conflation by routing an unrecognized clause onto the DEFAULT dispatch edge, whose remainder is not that clause's reaching set. That produced a WRONG VALUE rather than a superset. The modeled dispatch is exactly one shape: a represented discriminant against a literal case relation. An `Unmodeled` clause applies no dispatch narrow, never takes the default edge, and is excluded from the exhaustiveness remainder — leaving that remainder a superset, the sound direction.

Statement-position calls take the same discipline: a callee is inert only when it is a closed same-file declaration that is not an assertion and provably completes; a proven non-returning callee ends the path; every other call degrades rather than lowering to a bare throw point with its argument dropped.

Gap COUNT cannot discriminate these defects — a modeled fact and a proved-inert fact both mint zero gaps — so a regression test for this contract must assert the lowered guard SHAPE or the boundary degradation, never the gap count alone.


### Flow-Return Substrate (U6) Debt Notes

- **The demand-sliced substrate is the ONLY flow evaluator.** A `FlowReturn` cold path plans the demand slice as graph reachability (`FunctionBodySkeleton` → `FunctionFlowGraph` → `ReturnPathPeeker`), hashes it (`FlowSliceHashNode`), lowers exactly the plan into the content-free `FlowSliceIR` (`FlowSliceLoweredBodyNode`), and evaluates through the slice-gated owned content (`crates/verter_session/src/flow_slice_content.rs` — `SliceContent`, produced per demand through the `DeclBodyMemo` lease-only retained-snapshot run). Content OUTSIDE the slice never lowers: an unread binding initializer is omitted (the gate is the `FlowSlot` binding-identifier SPAN, declaration-precise — a shadowed same-named sibling declarator the plan kept out never lowers), a sibling member value rides the typed `SliceExpr::Elided` carrier (fail-closed if ever observed), and `if`-test / expression-statement positions carry no content. Selected leaf expressions lower through the ONE shared shallow-pass per-expression entry `infer_declaration_expression_type` (literal-preserving for arrow bodies / `const` initializers, widening otherwise). There is no whole-body evaluator and no separate return scanner; a leaf-lowering budget edge can only be charged by SELECTED content (guarded by `flow_return_unread_binding_content_never_lowers` / `flow_return_member_demand_never_lowers_elided_sibling_content`).

- **Per-constituent return freshness (the checker's fresh/regular literal split).** A sealed `FlowReturnResult` carries `fresh_literal_arms` — the top-level literal constituents of an inferred return that stay WIDENING: the body's own fresh sources (a bare literal return incl. a no-substitution template, a widening-`const` read, a fresh ternary/switch arm) and the fresh values a returned call carried (argument deposits + the callee's own arms, transitively across call layers). Fold is pinned-wins by literal VALUE across all contributors at one join (`as const`, type assertions, annotations, and declared return carriers pin; a pinned spelling anywhere cancels that value's freshness). Consumption is position-driven: a caller VALUE position (object member at any depth, array element, `let`/`var` declaration, evolving-target assignment) widens exactly these values; the caller's return join and an unannotated `const` keep them, the `const` recording them as its widening membership (`WideningMembership::All`/`Partial`). The call boundary transfers them on `ResolvedCallResult::Selected.fresh_literal_returns` (both the executor route and the direct same-file call rail record a `FreshCallReturn`); the component fixed point carries the SEED's arms and joins hold-target arms pinned — recursion keeps the separate all-fresh-seed whole-widening rule. Constructor-owned invariant: the list is always a subset of the return's kept top-level constituents (widened/absorbed values drop out on every rebuild). Measured against tsc 7.0.2 + tsgo; corpus rows N139–N148 pin the shapes, N136/N131 pin the return-position and declared-carrier controls. A read of a value declared OUTSIDE the frame (a module `const`, an imported or namespace-qualified one, a global) is a widening-`const` read when its declaration says so: `ValueTypeAnnotationFact::literal_freshness` (`DeclaredLiteralFreshness`) is `Widening` for an unannotated `const` whose initializer is a literal (signed numbers, bigints, substitution-free templates, through parentheses, `satisfies` and `!`, or a conditional of two such), `Follows(path)` for one that copies another value, and `Regular` for an annotation, an assertion or a mutable declaration. The evaluator asks `value_read_widens` — the same path resolution a `typeof` reference takes — only for a read that yields a literal, and treats a widening read exactly as a `WideningMembership::All` local read at every position above.

- **Optional-parameter body widening (U6.VALUE_INFERENCE debt).** Inside a body, a parameter declared `x?: T` evaluates to `T | undefined`. That is CORRECT under strict null checks (TS 5.8 / 6.0 semantics): a caller may omit the argument, so every body read sees the `undefined` arm. The non-strict branch (plain `T`, e.g. `number`) is NOT modeled by the flow-return substrate and remains U6.VALUE_INFERENCE debt — do not "fix" the strict branch to the non-strict answer.
- **Write-effect retype application (U6.NARROW_SUBSTITUTION / U6.VALUE_INFERENCE debt).** The evaluator does not yet APPLY the slice's `FlowSliceIR.effects` write obligations (retypes / widenings before evaluating the value providers that read the affected slots — the `flow_ir` contract). Until that lands, a lowered slice carrying a whole-slot write effect targeting a parameter or a value-selected slot fails CLOSED as the `UnappliedWriteEffect` DEGRADED SUCCESS (`ReturnOnly`, never warm) — evaluating past the write could publish a wrong type as complete (assignment narrowing; object members evaluate left-to-right). Projection-path writes (`x.a = v`) never retype the binding and stay clean; writes to slots that are neither parameters nor value-selected cannot be observed by the demanded value. The rail intentionally over-degrades source-order-safe direct reads (`return { b: x, a: (x = "s") }` degrades a correct `string | number` — recorded as the `debt:R2-UNAPPLIED-WRITE-EFFECT-SOURCE-ORDER` row on `U6.FLOW_RETURN_SUBSTRATE` in `scripts/manifests/typeinfo-programme-reconciliation.json`); a span-comparison suppression ("every read span precedes the write span") is UNSOUND — a deferred closure read (`{ b: () => x, a: (x = "s") }`) observes the write despite preceding it in source — so sound suppression requires actual write-effect application. Do not "fix" a degraded reassignment fixture by dropping the rail — implement the retype application on the same graph instead.
- **Selected reaching definitions and continuation state.** The control interpreter executes `SliceRegion` statements over one graph-scoped `FlowProductExecution`; `FunctionFlowGraph` supplies dependence and selection, not a control-flow traversal. The retained execution selection bounds every subject, and the exact attached demand plan alone authorizes proof evidence. Reaching value, reaching type (including literal freshness), definite assignment and narrowing share canonical runtime binding identities. Authored declared types occupy separate immutable source-declaration cells; runtime alias groups provide explicit declared-authority lookup without collapsing lexical shadows. Parameters and hoisted `var` aliases share runtime state, while lexical scope restoration rewinds only the scoped bindings. Every continuation merge passes its original ordered predecessor snapshots to the shared product kernel in one batch. Capture each arm's actual end narrowing before resetting the interpreter for a sibling; the kernel preserves common post-write facts, and a surviving edge never re-applies an earlier guard invalidated by its own write. A terminated arm contributes no continuing state; genuine successive control points, such as a switch clause's dispatch/fall-through merge followed by its body, remain sequential. The kernel owns domain joins, canonical union/provenance work, and atomic failure. Successful executed writes transfer RV/RT/DA and kill stale narrowing transactionally; bounded write receipts follow continuation snapshots so unchanged writes and finally replay are observed precisely. Each control entry records an execution-scoped observation of the shared write sequence; multiway merges use the common entry preceding all contributing paths. Two persistent indexes retain only the latest receipt per selected runtime subject, so snapshots share storage and clause observation seeks only newer writes. Scope close removes local receipts while preserving outer writes; replay never revives a closed declaration. Conditional-definition and clause type-change flags remain definite-assignment facts, and observing an unsupported path fails closed. Executed-write receipts and conservative clause-refusal inputs have distinct types: finally replay consumes every successful write, while the existing clause policy compares only written subjects' entering and final unified reaching types. That comparison neither reconstructs products nor decides whether a write executed. Storage budgets distinguish materialized runtime products per continuation from immutable declared products per execution; selected subjects bound capacity. Acyclic merges consume no fixed-point iterations, and only actual iterative work calls `note_iteration`. A return-free loop remains transparent only when selected content is transfer-inert: no escaping declaration, enclosing-label jump, or selected guard/call/write may change a downstream read. Read/write dependencies retain exact binding identities and static paths; computed paths remain conservative. Indexed captured write/control facts govern directly invoked nested closures, while callback arguments are not proof of invocation. Unsupported iteration-dependent effects retain the typed loop refusal.
- **A bare direct invocation cannot publish an unmodeled closure transfer.** An expression statement whose callee is an inline function/arrow is checked against the downstream selected slot. If that closure writes the capture or reads it in a guard/control position, the slice takes the typed `InvokedClosureEffect` no-value rail with zero candidates. This is intentionally conservative: the substrate does not yet apply the single-invocation closure's narrowing overlay, so discarding the effect and warming the pre-invocation union would be unsound.
- **Declarator annotations SUPPLY a stable assignment and mutable-capture authority.** A declarator's authored TS annotation lowers onto `SliceStatement::Binding.declared` through the same shallow pass a `SliceExpr::Type` leaf carries. Lexical declarations seed that authority at their source-ordered binding statement; selected `var` annotations seed it at frame entry because both assignment checking and a forward read observe the hoisted declared type before the initializer (`X66_hoisted_annotated_var_authority_serves_forward_read`). Runtime values remain source-ordered: an initializer executes at its statement, and an initializer-less `var` performs NO runtime write, so `x = "b"; var x: "a" | "b"; return x` keeps the assignment-reduced `"b"`. With no preceding reaching value, an initializer-less annotated declaration still supplies its declared type (`var y: number | undefined;` is `number | undefined`, not the unbound implicit `any`). A destructured parameter element seeds both its reaching value and declared authority before its first read OR write, so a preceding write is reduced against the annotated member union. A non-union annotated initializer publishes the declared type (`const y: string = "s"` is `string`; `const y: "s" = "s"` still pins `"s"`); a declared union is assignment-reduced to comparable DECLARED constituents for both its initializer and later whole-binding writes (`let x: "a" | "b" = "a"; x = "b"` reaches `"b"`). A nested function value carries the exact declared authority for each captured mutable `let`/`var` and parameter element, keyed by binding identity rather than reconstructed from a current value. A reaching `let` value remains the closure's read authority until that closure writes it; `var` and forward-`let` captures retain authored authority. The declared node belongs to the exact authored declaration in the execution authority bank and survives continuation and scope restores. Runtime alias lookup consults the declaration group explicitly; a later write never reconstructs authorship from the current value. Nested descriptors carry content-free source locators, and only selected value captures hydrate missing authored authority through the retained source owner. Assignment-context object literals retain a pre-property-widening member view solely for constituent selection. When mutually assignable object arms differ by exact present keys or discriminants, that evidence can select the best-matching declared arm; spread programs deliberately bypass exact-key selection because their final key set is not closed. Generic strict-subtype dominance is not a checker rule here: required-property presence alone does not discard an overlapping optional-property constituent. Ordinary object evaluation still uses mutable-property widening. `X65_object_assignment_declared_union_selects_matching_arm`, `X69_overlapping_object_union_assignment_selects_narrow_arm`, `X75_fresh_object_assignment_selects_optional_member_arm`, `X76_fresh_computed_object_assignment_selects_optional_member_arm`, `X77_spread_object_assignment_preserves_declared_union`, and `X84_required_property_assignment_preserves_optional_union_arm` pin those boundaries.
- **Abrupt-edge state is point-in-time and scope-closed.** Break, return, and throw edges each capture the complete reaching-definition state where the edge occurs. Every crossed lexical scope replays its shadow close onto those snapshots before a construct joins them; `if` arms likewise snapshot only after closing the arm scope. A `finally` entry joins normal completions, throw points, and pending break/return pre-states. Return inference aggregates every authored try/catch/finally return even when an abrupt `finally` overrides runtime completion, while the pending control edges exposed to an enclosing construct still obey that override: an abrupt finally replaces pre-finally returns and breaks but preserves returns and breaks authored by the finally itself. A pending named break overridden by an abrupt finally remains an implicit-`undefined` return-inference contributor when its target statement has no following current-function return; that holds for both a directly labelled try (`X68_finally_return_over_labelled_break_keeps_undefined`) and a try wrapped by labelled blocks (`X80_wrapped_labelled_try_finally_keeps_undefined`). A following return suppresses that contributor, preserving `X52_finally_entry_joins_pending_break`. Switch dispatch death is independent of a live clause fall-through chain: exhausting the no-match edge cannot delete fall-through into `default`.
- **Logical guard facts are edge-asymmetric when an operand is unmodelled.** The guard tree preserves `SliceGuard::None` operands instead of simplifying them away. On `modelled && opaque()`, the true edge may apply the modelled fact but the false edge cannot negate it; on `modelled || opaque()`, the true edge establishes nothing while the false edge may negate every modelled disjunct. Predicate leaves retain their negation bit, so De Morgan transformation is reversible: the surviving edge of `!(isStr(x) && opaque)` recovers the original positive predicate rather than erasing it. A disjunction evaluates every alternative from the same starting overlay and joins each alternative's FINAL value per subject; intermediate conjunction facts never become separate union contributors (`N21_guard_union_uses_final_alternative_overlay`, `N22_double_negated_guard_union_uses_final_alternative_overlay`). An alternative whose sequential conjunction has no surviving declared arm is represented as impossible and contributes no overlay to the disjunction (`N23_impossible_conjunction_drops_dead_disjunction_alternative`). This is one `And`/`Or` authority consumed in positive and negative modes, not two pattern-specific rewrites.
- **Guaranteed-return qualifier for labelled-break inference.** In the preceding abrupt-edge rule, a “following current-function return” means a suffix statement that guarantees the return on every normal path (a direct return, a sequential block containing one, or both arms of an `if`). The qualifier is inherited through recursively lowered blocks and labels: an abrupt `finally` retains a pending named break as a return-inference-only suffix edge when the crossed target carries it. A suffix contributor already strictly covered by an ordinary return is redundant; an incomparable suffix remains in the inferred union. Merely containing a conditional return does not suppress the implicit-`undefined` contributor.
- **The root-identifier gate.** The shared shallow-pass leaf lowering (`infer_declaration_expression_type`) has NO frame — it resolves every name it meets in FILE OWNER SCOPE. So every leaf answer the slice content mints routes through ONE gate (`flow_slice_content.rs` — `Lowerer::leaf_type`, the sole producer of a leaf answer). Two evidence sources, one verdict: (a) the ANSWER's names, read off the produced typed IR through the shared exhaustive walk `verter_type_expr::referenced_names` (`typeof x…` value-path roots + named type references — never a re-derivation of the leaf's own traversal), and (b) for an answer the leaf could not model at all (a bare `any`), the expression's REFERENCE-CHAIN root (`a`, `a.b`, `a["b"]`, `a.#b`, `a?.b`, `a.b()`, `new a()`, `` a`…` ``, through parentheses and TS wrappers). A frame-owned name in (b) fails closed immediately (`SliceExpr::UnmodeledBinding` — no answer exists and no owner scope could supply one; POSITIONALLY, as the typed unresolved marker). A frame-owned name in (a) rides the `SliceExpr::FrameShadowed { inner, shadowed }` carrier, and the EVALUATOR decides against the live owner scope (`flow_return.rs` — the one shared `owner_scope_answers_frame_name` probe, taken through the same lowering the answer itself would take: `typeof name` for a value reference, a bare `name` reference for a type or namespace one; the head of `N.B` is the same scope lookup as a bare `N`, so the meanings differ on the FRAME side, not here): a name the owner scope ANSWERS fails closed positionally (the marker + `UnmodeledPosition`), a name it answers nothing for evaluates the wrapped leaf unchanged, because nothing can be mis-bound and the leaf's own typed miss is the honest result. The `any`-half deliberately does NOT scan the whole subtree: a name in a position the leaf never consumes (a conditional TEST in `c ? 1 : 2`, an assignment target in `{ a: (x = "s") }`, a call argument) says nothing about the answer.
- **The frame gate covers every `TypeExpr` ENTRANCE, not just leaves — structurally.** Slice content mints types at eight `TypeExpr`-bearing fields, and each one is a place the frame-less shallow pass can hand back an owner-scope answer for a frame-owned name. Six of them (`SliceParam.ty` from an annotation, from a rest annotation, and from a default-initializer inference; `SliceTypeParam.constraint` / `.default`; `SliceStatement::Binding.declared`) hold the `GatedType` newtype (`verter_session_query::flow::slice`), whose `ty` / `shadowed` fields are PRIVATE and which is built only by an operation that computes its verdict — `DefiningFrameGate::gate` at a body position, `CaptureScope::gate`, the `SignatureScope` operations (`gate`, `predicate`, `parameter`, which add the parameter-list and default-initializer shadows themselves), `FrameAnswer::into_gated` — or by the explicitly-named `GatedType::root_signature`; `or_undefined` is its one transformation. So "mint a slice-content type without deciding what the frame does to it" does not compile. The remaining two (`SliceExpr::Type` / `SliceCall::Symbolic`) take the body answer `FrameAnswer` (built by `DefiningFrameGate::answer` / `free_read` at the exact lexical position) and ride the `SliceExpr::FrameShadowed` carrier; a `GatedLeaf` (private fields) is built only by `DefiningFrameGate::leaf`, which derives the frame root from the answer type and the frame's indexed root occurrence, or by `GatedLeaf::nameless` / `primitive` for an answer naming nothing; `widen_literal` is its one transformation. `SlicePredicate` is built only by `SignatureScope::predicate`, which gates the authored predicate's own target. The frame records (`DefiningFrameGate`, `CaptureParameterLocator`, `CapturedFrame`, `CaptureScope`, `NestedFlowContext`, `SliceCaptureAuthorityLocator`) are immutable once sealed: `DefiningFrameGate::seal` checks a source-assembled `DefiningFrameDiscovery` against the indexed function (binding map built for that function and over that skeleton, exact body hash from the entry) and derives the parameter locators and `SignatureParameters`; `DefiningFrameGate::nested_context` builds the capture chain and nested context from a child position; `NestedFlowContext::mutable_authorities` is the sole locator producer. These are structural seals and checked relationships, not parser provenance. The two free producers `lower_params` / `lower_slice_type_params` take a NON-defaultable `SignatureScope::{Root, Nested}`, so a new call site must choose the scope. `SliceStatement::Binding.declared` must be gated on the ANNOTATION itself: with a non-union declared type the evaluator binds the declared node and never evaluates the initializer, so the initializer's own gate cannot stand in.
- **Root signature vs nested signature (`resolveName`, `lastLocation !== location.body`).** A function's body-local type declarations are in scope ONLY inside its own body — never in its own parameter list, type-parameter clause, or parameter defaults (TypeScript discards a Type-meaning hit in a function-like `location`'s `locals` when `lastLocation !== location.body`; the value side mirrors it in `useOuterVariableScopeInParameter`). So the ROOT function's signature stays UNGATED (`SignatureScope::Root` ⇒ `GatedType::root_signature`) while a NESTED function value's signature — which sits inside the enclosing body — is gated against the ENCLOSING frame at the nested value's own span (`SignatureScope::Nested`). Gating the root positions would fail closed on `function f(p: Info) { class Info {} … }`, where the OUTER `Info` is correct. A parameter DEFAULT initializer additionally carries its reference-chain root as a `FrameShadowedName::Value`: a widened or primitive answer (`p = C` ⇒ `string`) names nothing at all while still having read THROUGH a frame binding.
- **A nested signature's OWN type parameters are BINDERS, in TYPE meaning only.** They are the names the evaluator's nested `flow_binder_env` interns, so an answer naming one resolves to the binder and a captured same-named `class` / `enum` does not shadow it (`Lowerer::name_is_frame_bound` subtracts them). In NAMESPACE meaning the binder still wins lexically but denotes no namespace, so a qualified `T.B` is unresolvable and stays frame-bound (fail-closed). The SHARED walk `verter_type_expr::referenced_names` masks the same class structurally: a `Function` / `ConstructorType` / method / call-signature node opens a binder frame over its own subtree on the same explicit heap work-stack the rest of the walk uses (depth-safe, exhaustive), so a generic function type in an ANSWER never reports its own `<T>` as a scope reference.
- **Type-space lookups are MEANING-filtered, and the meaning is per OCCURRENCE.** A bare `N` reference demands a `Type` meaning; the HEAD of a qualified `N.B` demands a `Namespace` meaning (`SymbolFlags.Namespace = ValueModule | NamespaceModule | Enum` — a class is NOT in it). `FunctionBodySkeleton::declares_meaning_in_scope(name, region, NameMeaning)` walks the region chain filtering by `SkeletonBindingKind::declares(meaning)` at EVERY hop (a scope whose symbol lacks the meaning is skipped and the walk continues outward), and `bindings_of_name_in_scope` is symmetric — it filters by `SkeletonBindingKind::declares_value()` at every hop, so the TYPE-ONLY kinds are transparent to a value lookup. Oracle-anchored cells (`tsc --strict`, one fixture per cell): `class` (± statics) and `type` / `interface` shadow the bare reference but NOT the qualified head; `namespace` is the reverse; `enum` / `const enum` shadow both; every value-only kind (`const` / `let` / `var` / `function` / parameter / catch-param) shadows neither; `class N` + `namespace N` shadows both while `function N` + `namespace N` shadows only the head. `import N = …` is meaning-TRANSPARENT (it occupies exactly its target's spaces), which the skeleton cannot decide, so it answers BOTH conservatively — a recorded over-fire that can only fail closed. The `qualified` bit rides `verter_type_expr::ReferencedTypeName` PER OCCURRENCE, because one answer can reference the same head both ways. `CaptureScope` therefore carries `type_names` and `namespace_names` as two SEPARATE inventories, and `FrameShadowedName` splits `Type` / `Namespace` alongside `Value`.

A function DECLARATION keeps `from_function` — its name binds in the ENCLOSING scope. Consequently `SliceCall::DirectSelf` is minted only where the frame owns a flow slot: `FlowEvaluator::self_slot` is `Option<&FlowReturnKey>` and is `None` inside every nested function value, so an inner self-call can no longer take a hold on the ENCLOSING function's slot.
- **A block-level function declaration is BLOCK-scoped.** `FunctionBodySkeleton::hoisting_bindings_of_name` hoists `SkeletonBindingKind::Var` unconditionally but a `NestedFunction` only when its recorded region is the frame's ROOT region: in strict-mode ESM (every carrier surface this substrate serves) a block-level function declaration is block-scoped, and only Annex-B sloppy-mode semantics create the function-scoped alias. Hoisting it unconditionally made `if (c) { function f() {…} } return f()` resolve to the block's function and FAIL CLOSED where the correct answer is the module-scope `f`'s return. (Latent, no live consumer: `StatementListInventory.nested_function_names` in `function_program.rs` carries no region axis.)

The direct-call rail therefore checks the target's prepared value decl for an authored annotation (`ValueAnnotationClass::Direct` / `TypeOfAlias` with a `SemanticTypeSource::Authored` source) and, when present, resolves the callee as a VALUE TYPE through the same shared path a parenthesised or ambient callee takes (`call_return_of_callee_node`), never through the initializer's own flow position: `const f: () => 42 = () => 42; f()` is `42`, not the initializer arrow's inferred `number`. (a) The flow rail's clause is read from the per-file `FunctionProgramIndex` entry's `type_parameters`, keyed by the target's exact program identity, NOT from the prepared value declaration — the value registry does not carry a namespace-scoped function at all, and reading the clause there leaves exactly those callees leaking. (b) The name-driven binder collection can claim THREE resolution states of one clause parameter — the bound `TypeParam`, the deferred `BareRef`, and the RESOLVED `DeclRef` — and WHICH of them it claims is chosen per route by `ClauseSpelling`, because the answer depends on PROVENANCE and the name alone cannot supply it.
