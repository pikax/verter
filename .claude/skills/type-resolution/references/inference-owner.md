### Reverse-homomorphic mapped recovery

The reverse-source preflight scans the full subtree of every source position that `assemble_reverse_candidate` copies into the aggregate: positive object-member values, index-signature keys and values, array elements, and tuple element values. Root object call signatures, construct signatures, and keyspace are excluded because assembly drops them; open-spread operands are excluded from this scan and refused independently by the root-open guard. The exhaustive subtree walk includes free-standing `TypeParam.constraint` and `TypeParam.default` edges as well as signature-declared type-parameter bounds.

This full-subtree boundary is sound but conservative, and refusal is **aggregate-wide**. One semantically unresolved node in any scanned nested non-slice position refuses the whole reverse recovery; no unaffected property is recovered separately. For `S = { a: { value: string; (x: unknown): x is string } }` against `{ [P in keyof infer T]: { value: T[P] } }`, the nested predicate's `RawFallback` cannot affect `T[P]`, but the preflight refuses the entire aggregate and the conditional stays deferred. This is a false refusal (`Unknown`), never publication of a wrong recovered type.

The precision ideal is a projection slice: only source positions structurally corresponding to the template's registered `T[P]` sites and the structure wrapping those sites. The slice is template-dependent—`T[P]`, `{ value: T[P] }`, `Box<T[P]>`, and `T[P][]` select different source structure. The current relation walk records projection targets but not the source-to-template correspondence needed to derive that slice, so the sound boundary remains the assembled-input full-subtree preflight. Skipping signatures categorically is unsound: under the identity template `T[P]`, a source member value that is itself a signature belongs to the projection slice and must be scanned.

`Opaque(QueryError)` has an explicit recovery polarity. `RecursiveRef` and `DeclPlaceholder` are publishable carriers and do not refuse recovery: the former is a settled recursion leaf and the latter an addressable declaration shell. `Miss`, `UnsupportedIntrinsic`, `BudgetExceeded`, `Cancelled`, `UnstableState`, `AliasCycle`, `Other`, `ValueDomainMismatch`, `RaiseAliasCycle`, `TypeParamCycle`, `RaiseMiss`, `OpenSurface`, `UnrepresentableSurface`, and `UnrepresentableSurfaceMember` are failure, unresolved-control, or unrepresentable states and refuse recovery.

Two session invariants prevent alternative and ordering drift:

- `inference_candidate_precedence` is the **only** inference-candidate ordering authority. `InferenceCandidatePriority` deliberately implements no `Ord`; enum declaration order cannot become an accidental precedence rule.
- An inference-session checkpoint covers projection-target registrations as well as ordinary and projection candidates. Rollback truncates registrations created by the losing alternative and restores candidate lengths on surviving registrations, so a losing alternative cannot poison deposits made by a later alternative.

Current reverse-recovery fixture coverage has these explicit gaps:

- `RecursiveRef` recovery is characterized; `DeclPlaceholder` recovery is not.
- The aggregate-wide nested non-slice over-refusal above has no characterization fixture.
- Root call-signature exclusion is characterized; root construct-signature and root-keyspace exclusions are not.
- Unresolved-input refusal at root index-signature key/value positions and top-level array/tuple positions has no discriminating fixtures.
- No reverse-specific fixture pins refusal for `UnsupportedIntrinsic`, `AliasCycle`, `RaiseAliasCycle`, `UnrepresentableSurface`, or `UnrepresentableSurfaceMember`.

The exhaustive Rust matches protect taxonomy completeness when a new node or `QueryError` variant appears: compilation forces the new variant to receive a classification. They do not protect the polarity of an existing variant; an existing publishable/refused arm can be flipped while the matches remain exhaustive. Discriminating fixtures are the only guard for existing-variant polarity.

**Conditional-infer identity and cyclic fixation.** Every authored `infer` declaration receives a canonical `InferBinderId` derived from the stable lexical `NodeScopeId`, the declaration or macro body's content-free `AuthoredBodyLocator`, and the declaration's exact typed child path. The identity is neither graph-allocation order, traversal order, nor a lossy digest, so eager, locator-shape, and structural lowering, spread-fragment lowering, re-lowering, unrelated demand order, and concurrent demand all converge on the same token. Anonymous/transient roots use a separate exact typed-root identity and remain ReturnOnly unless an authored locator is available. The wrapper is non-forgeable in production; only a test-gated synthetic constructor exists. Display names are not binder identity: one exhaustive typed syntactic traversal predeclares a conditional's `extends` binders for declaration sites and its true branch only, while ordinary sibling refs keep using the ordinary lexical environment; carrier arguments, template interpolations, signature constraints/defaults, and every other `TypeExpr` child position participate. Every `InferRef`, `InferBinding.param`, substitution, open-walk association, and reverse projection carries or compares the exact token/node identity. Nested same-name declarations therefore cannot intern together or deposit into one another's session. Inference sessions use the one-way `Collecting → StagedDeterministic → CommittedDeterministic` lifecycle, with `Collecting | StagedDeterministic → Abandoned`; only the innermost `Collecting` session is deposit-active. Fixation stores an immutable staged binding snapshot. Relation roots stage and immediately commit at their existing safe pop, while call candidates always push their own collector even when an outer collector exists and delay commit until mixed-SCC stability. A cyclic binding judgement stages and commits its session before SCC re-discharge, then re-enters the sole `execute(SemanticQueryKey::Relate)` authority for every SCC member, including negative non-binding consumers; publication requires the re-discharged polarity and exact `(param, bound)` binding snapshot to equal the provisional snapshot, otherwise the whole deferred batch is `ReturnOnly`. The transient redischarge frame is ReturnOnly and cannot recursively initiate another SCC discharge unless it is itself cyclic. A cold top-level binding relation uses a store-owned independent flight: it never joins another transaction's transient inference session, but retains the ordinary cooperative cancellation, invalidation, admission, retention, and reverse-index fences. Nested non-binding relations register ordinary family flights so concurrent top-level consumers may join their decided publication.


### The inference owner

`crates/verter_type_engine/src/project_semantic_dispatch/inference/` is the one owner of inference state and its mutations:

- `session.rs` — the session state: `InferenceSession` (per-parameter candidate journals, reverse-projection journals, fresh-literal deposits, staged bindings), `InferenceSessionSetup` / `InferenceInfoSetup`, `SessionCheckpoint`, `InferenceCandidate`, `FixationInput`, and the `Collecting → StagedDeterministic → CommittedDeterministic | Abandoned` lifecycle. The transaction (`dispatch_txn.rs`) holds the session stack and the binding-barrier stack; it does not define session state. Finished sessions stay on the stack for the transaction's lifetime, so the active-session search reads `collecting_ids` (the sessions that may still collect, pruned from the top as they finish) rather than scanning every session the transaction opened.
- `collect.rs` — candidate collection: `relation_deposit` (with the call-argument literal policy), the projection and reverse-aggregate deposits, the projection-target probe, and the alternative checkpoint/rollback (`relation_session_checkpoint` / `relation_session_rollback`). No other module calls a session's deposit methods. `relate_collecting` is the relation a caller uses to collect into a session it opened itself (`instantiateSignatureInContextOf`).
- `fixation.rs` / `constraints.rs` — the winning-candidate selection (`winning_candidates`, priority via `inference_candidate_precedence`), `getInferredType` fixation, and `infer X extends C` constraints.

**Pure assignability deposits nothing.** `execute_relate_pair` / `execute_relate_pair_kind` run behind a binding barrier: every session open before the question is invisible to it, so a type parameter an enclosing session infers is rigid there (the checker's `isTypeAssignableTo`). A relation whose own key carries an inference context still opens its own session above the barrier, so a conditional's `infer` evaluated while a call is collecting binds in the conditional's session — never by depositing into, or failing against, the call's. Candidate collection happens only through a call's applicability relation (`call_relation` with binding enabled), a relation root over an `infer` pattern, and `relate_collecting`. The former per-site `begin_binding_disabled` wrappers around pair questions (`relate_outside_inference`, the fixation and constraint guards, `BindingControl`) are gone.

**A call argument's own literal is kept where it lands.** A deposit of the argument's whole type keeps its literal even when the target position is not a naked type parameter (a conditional or alias target the relation reaches through): `both<T>(x: T, y: Unbox<{ v: T }>)` called with `(1, 2)` infers `1 | 2`. Only a literal nested in an array or object literal argument widens at the deposit.

**Completed no-candidate is not unfinished inference.** Value inference of a call argument has no work cap: it runs from explicit stacks, so a finite literal of any width or depth is inferred whole (`f<T>(xs: [T, …]): T` called with 1,025 or 5,000 `1`s selects `T := number`, cold and warm — `a_source_call_infers_from_every_argument_position`). An argument whose value inference fails typed lowers as the typed unsupported-call refusal (`IndexedValueExpression::UnsupportedCall`), never a fabricated `any`: the call is refused instead of completing with no candidate (`unknown`).

**Base signatures derive their clause substitution once.** `base_signature` computes the clause's base constraints once per signature and applies them to every parameter and the return; the sibling rounds stop at their fixed point. Binder-collection work grows quadratically in the clause length (`base_signature_inference_work_grows_quadratically_in_the_clause`).

**Contextual calls retain one collector per candidate.** `call_resolve_contextual.rs` owns the flow route's transient continuation. Callback delivery advances the retained candidate with one acquired argument; it skips signature discovery, arity scans and full argument acquisition until completion or rejection. Final applicability and publication still enter the call executor. Calls that do not open a collector retain the executor's ordinary contextual recheck route. Object, tuple and array templates preserve each nested callback's unfixed return while substituting its parameter context. Definite eager and receiver mismatches reject a candidate before assigning callback contexts. Eager arguments (including annotated callbacks) collect once. Deferred callbacks are typed left to right under the candidate's current inferences; a parameter-position binder fixes before its callback runs, and an unfixed return binder collects that callback's return. The mapper reads the template's reachable binders, their declared bounds/defaults and reverse constraint siblings, through session-owned indexed fixation inputs. Reverse edges are indexed once per candidate because a sibling constrained to a binder can influence its covariant-versus-contravariant choice. It does not walk already-fixed binder images or solve the whole clause again at every stage. The final applicability check remains `check_call_candidate` and uses the completed callback types. Final constraint and winner lookups share an indexed binder-to-bound map. Inference work, relation/deposit counts and final binding inspections therefore grow with stages times candidates tried rather than replaying each earlier callback at every stage.

The continuation records its owning call point. Every call-resolution run hides an installed continuation belonging to a different point for its full argument acquisition and candidate evaluation, then restores it on every exit, including replay and refusal. The continuation owns the collecting session outside the transaction while the callback body evaluates. It reinserts that same session only for the candidate's inference work, so nested callback calls cannot deposit into its collector. No suspended or partial candidate enters a family memo. A rejected candidate discards its collector and inference deposits. The continuation retains its parameter-context bindings and callback diagnostic for final applicability and sole-candidate error recovery. Those binders are rigid during later collection; recovery preserves the contextual diagnostic and instantiates the return with the same fixed types. As in TypeScript, the first candidate that reaches a callback assigns its parameter context once; subsequent candidates reuse that checked callback type, but infer in their own fresh collector. The assignability pass after subtype obeys the same separation. Definite annotation/arity failures carry a `Diagnosed` refusal whose diagnostic recipe the flow result binds to its call site ([checker-diagnostics.md](checker-diagnostics.md)): a callback return mismatch carries both the returns and the argument, an excess argument count is TS2554. Ordinary successful calls and direct call requests still use the same call-resolution authority.

Top-level declarators initialized by direct calls with function arguments are indexed as `FunctionNode::Initializer` expression-body positions. The optional `ProgramInitializerSource` on their `SemanticCall` records reads their values through the same FlowReturn evaluator and contextual-call continuation used by function bodies, including `typeof` demand, while retaining the indexed call and callback-return records. When the entire call initializer is an unresolved positional marker, declaration-value consumption keeps the ordinary unsupported-call refusal rather than publishing that marker as an inferred value; resolved initializer values and nested failure carriers retain their existing treatment. Const declarators retain fresh literal values; mutable declarators and fields keep the existing widening policy. Discovery indexes callbacks beneath that initializer once, and retained-parse locator resolution recognizes both its expression body and nested functions.

Contextual preparation uses the same receiver base-signature normalization and relation-only SCC classification as final applicability. Both receiver and generic-rest inference charge their accepted deposits and preserve operational budget refusals. A bare generic rest parameter receives its implied tuple arity before receiver inference; its eager trailing arguments relate once as a tuple, rather than through positional parameter mapping. Context-sensitive arguments inside the generic tail retain the ordinary executor's contextual recheck route because no positional callback template exists yet.
Callback contextual signatures expand fixed, required tuple rest elements into their individual parameter contexts. Optional or variadic tuple rests remain refused by that flow typing reader; array rest contexts retain their element-type behavior.

The call route prepares its first-pass contextual parameter shape once, lazily when an annotated callback or context-sensitive object requests it. Shared signature discovery remains the authority. A complete list with no sole signature (including an overload set) is a cached negative for that route; incomplete discovery remains uncached and can retry. The route borrows the signature's parameter array rather than copying it. Constraint-bearing binder replacements are built once; only requested parameter types are substituted, and equal types share that result. Each callback then reads its position directly, or the array-rest element past the fixed parameters, instead of rediscovering the callee and scanning its parameter prefix. This state dies with the route and never enters a shared cache. The argument-work probe counts preparation visits and positional reads as well as acquisition and arity work, so a repeated prefix scan cannot hide behind otherwise linear relation counts.
